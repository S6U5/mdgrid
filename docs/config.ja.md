# 設定

[English](config.md)(英語が正本)

mdgrid は TOML のファイルを1つ読む:

- `$XDG_CONFIG_HOME/mdgrid/config.toml`。`XDG_CONFIG_HOME` が無ければ `~/.config/mdgrid/config.toml`(macOS でも同じ)。Windows では `XDG_CONFIG_HOME` が無ければ `%APPDATA%\mdgrid\config.toml`。
- `mdgrid --config <パス>` なら、そのファイルを読む。

同じフォルダには mdgrid が書くファイルも置く: `ui.toml`(画面で選んだもの。ビューの設定の「見た目」の区画のテーマなど)、`views.toml`(mdgrid のビューと表ごとの設定)、`workspaces.toml`(ワークスペースとお気に入り。[お気に入りのワークスペースを行き来する](manual/ja/tasks.md#お気に入りのワークスペースを行き来する))、`places.toml`(登録した表。[使う表を登録して切り替える](manual/ja/tasks.md#使う表を登録して切り替える))、`sessions.toml`(名前を付けたセッション。[表示をセッションとして保存する](manual/ja/tasks.md#表示をセッションとして保存する))。mdgrid は `config.toml` を書き換えない。

どの項目も書かなくてよい。ファイルが無ければ既定で動く。知らない項目・型の違う値・その場所に書けない項目は、メッセージ行に警告を出して無視し、起動は止めない。警告はどれも「ファイル: 項目の道筋: 理由」の形。壊れた TOML は理由を1行出して止まる。

既定から始めるなら、説明のコメント付きで書き出す:

```sh
mdgrid --print-config > ~/.config/mdgrid/config.toml
```

書き出したものは警告なしに読め、ファイルが無いときと同じに動く。既定の無い項目は、コメントにした例として出る。

## 2種類の項目

- **アプリ全体の項目**(範囲「全体だけ」): 最上位の `language`・`editor`・`poll_ms` と、区画 `[terminal]`・`[workspace]`・`[git]`・`[keys]`・`[search]`・`[templates]`。`config.toml` にだけ書く(`ui.toml` には `[terminal] nerd_font` を書ける)。
- **表のプロファイル**(範囲「全体・ワークスペース・表・ビュー」): `use`・`[look]`・`[display]`・`[dates]`・`[edit]`・`[new_note]`。下のどの場所にも同じ形で書け、狭い範囲が広い範囲を上書きする。
- **台帳ごとの条件と知らせ**(範囲「全体・ワークスペースの印」): `[conditions]`・`[[notices]]`・`[[notify]]`。`config.toml` と、印 `.mdgrid/workspace.toml` の最上位に書ける。印に書いたものはその台帳の表でだけ効き、全体のものと並べて使う([名前を付けた条件](#conditions--名前を付けた条件))。

## ワークスペース・表・ビューごとの上書き

| 範囲 | 手で書く | mdgrid が書く |
|---|---|---|
| 全体 | `config.toml` | `ui.toml` |
| ワークスペース | 印 `.mdgrid/workspace.toml`(最上位)か、`workspaces.toml` の `[[workspace]]`(`[workspace.look]` など) | `workspaces.toml`(印には書かない) |
| 表 | ワークスペースの表の項目(印の `[[table]]` と `[table.look]`、`[[workspace.table]]` と `[workspace.table.look]`) | `views.toml` の `[[table]]` |
| ビュー | — | ビューの設定(mdgrid のビューは定義にも保存) |

各項目の値は、それを書いた一番狭い範囲から取る(ビュー → 表 → ワークスペース → 全体 → 既定)。同じ範囲では、mdgrid が書いたものが手で書いたものより先(`ui.toml` は `config.toml` より、`views.toml` はワークスペースの表の項目より)。ワークスペースの印に書いた `[look]`(最上位と `[table.look]`)だけは、台帳を作った人の勧める既定として全体より広い範囲(既定のすぐ上)に置く。だから `config.toml` や画面で自分が選んだテーマ・組・色は、どの範囲のものも印より先に効く(印のほかの区画は、今までどおりワークスペースの範囲)。見た目が混ざらないように、2つだけ例外がある: `preset` を書いた範囲は、それより広い範囲の部品の形(`[look.style]`)を使わず、`theme` を書いた範囲は、それより広い範囲の役割の色(`[look.colors]`。値の色は除く)を使わない。`use = "<テンプレート>"` は、その範囲の値の下にテンプレートを敷く。

`mdgrid [<表>] --print-config --resolved` で、その表で効く設定を、項目ごとにどこから来たかのコメント付きで出せる。

```toml
# notes/.mdgrid/workspace.toml — notes のワークスペースの表は nord、tasks だけ dracula
name = "notes"

[look]
theme = "nord"

[[table]]
path = "tasks"

[table.look]
theme = "dracula"
```

印には、根のフォルダを開いたときの表も書ける: 最上位の `open = "<表の名前>"`(`[[table]]` の `name` か、自動の表ならフォルダの名前)。根のフォルダを開くと(そこで `mdgrid`・`mdgrid .`・ほかからそのパス)、フォルダの全部のノートではなくその表を(`--view` が無ければその `view` で)開く。`--print`・`--check`・`--print-config --resolved` も同じ。`--raw` でフォルダそのものを開く。下のフォルダ・2つ以上のフォルダ・`.md` のファイルでは使わない。どの表も指さない `open` は警告して、フォルダをそのまま開く。

`open` でない表は、`--table <表の名前>` で名前を言って開く(`mdgrid ~/notes/research --table ニュース`)。印は開くフォルダ(無ければ今のフォルダ)から上へたどって探すので、台帳の中のどのフォルダからでも同じ名前で選べる。画面でも、`--print`・`--count`・`--check`・`--new-note`・`--pick`・`--apply`・`--notices`・`--notify`・`--runs`・`--print-config --resolved`・`--page` でも、その表を開いた表として動き、`--view` はその表のビューから探す(無ければその表の `view`、それも無ければ最初のビュー)。`--new-note` は、その表の `[new_note]`(作る場所・名前の頭・前もって入れる値・本文の雛形・必須の列)で作る。無い名前と印の無い所では、印の表の名前を並べた理由1行で止まる。`-w <ワークスペース>` と一緒なら、`workspaces.toml` のそのワークスペースの表から選ぶ。`--raw`・`-s`・`--continue` とは一緒に使えない。

表のノートを置くフォルダ(その表の `[new_note] folder` か、表の `.base` の絞り込みの `file.inFolder` が指すフォルダ)を直に開いたとき(`mdgrid ~/notes/research/News`)も、素のフォルダではなくその表を開き、その表の新しいノートの決まり・ビュー・値の候補を使う。素のフォルダを見たいときは `--raw` を添える。

```toml
# tasks/.mdgrid/workspace.toml — tasks で `mdgrid` と打つと、README.md や AGENTS.md ではなく tasks.base を開く
open = "tasks"

[[table]]
name = "tasks"
path = "tasks.base"
```

印の `[[table]]` には、ガントの画面(`C`。[キー](keys.ja.md) の `gantt`)の設定も書ける: `gantt = { start = "<列>", end = "<列>" }`(`end` の代わりに `days = "<日数の列>"` でもよい)。設定が無くても、日付の列の名前(始まりは start・begin・from・開始、終わりは end・due・finish・until・to・期限・終了)から推定し、画面の題にそう示す。`gantt` が表でない、`start` が無い、`end` も `days` も無いときは警告して設定を外し、列が表に無いときはノートを読み終えてから知らせる。画面の型の設定はどれも同じ形(`<型> = { <列の名前> }`)で、画面の型のメニューには設定か推定のある型だけが並ぶ。

印の `[[table]]` には、カンバンの画面(`B`。[キー](keys.ja.md) の `kanban`)の設定も書ける: `kanban = { column = "<列>" }`。行はその列の値ごとのレーンに札として並び、レーンの順は列の決まり(`[rules.<列>] values`)の順、続いて決まりに無い値を行に現れた順、最後に値の無い行の **(なし)**。設定が無くても、列の名前(status・state・stage・状態・ステータス・段階。大文字小文字を問わない)から推定し、画面の題に推定と出す。リストの列は推定では選ばず、設定で指すと警告になる(1行が複数のレーンに入るため)。`kanban` が表でない・`column` が無いときは警告して設定を外し、表に無い列はノートを読み終えたときに知らせる。

札の名前の下には、`card = ["<列>", …]` に書いた列の値を、書いた順に1列1行で出せる。値の見せ方は表のセルと同じ(決まりの字と名前・設定の日付の形・リンクの行き先の名前・計算の列の値)で、ビューに出していない列も書ける。値の無い列の行は出さない。`card` を書くと札と札の間が1行空き、名前の続きと値の行は名前より2字下がる。名前はレーンの幅に入らなければ2行まで折り返し、それでも入らなければ末尾を `…` で切る(`card` を書かなくても折り返す)。`card` が列の名前の文字列の並びでないときは警告して外し(カンバンは名前だけの札で出る)、表に無い列はノートを読み終えたときに知らせる。

```toml
[[table]]
name = "本と記事"
kanban = { column = "status", card = ["author", "formula.progress", "formula.stars"] }
```

印の `[[table]]` には、親子の設定も書ける: `children = { key = "<列>" }`。その表はどのビューも、`key` の列に書いた親のノートへのリンク(リストなら先頭)で、子の行を親の下に字下げして並べる(ビューの設定の「親子」の区画でオンにしたときと同じ並び)。ビューの設定でオフにしたビューは、開き直してもオフのまま。`key` のほかの項目は省ける:

- `status`: 状態の列。省くと印の `kanban` の `column`、それも無ければ `status`。
- `done`: 完了の値。省くと `"done"`。
- `closed`: 終わったとみなす値の並び。省くと `["done"]`。完了の値は書かなくても終わったとみなす。
- `on_done`: 親の状態を完了の値に直したときの、まだ終わっていない子孫の扱い。`"complete"`(省いたとき)は子孫も完了の値にし、列の `then` の値も入れて、親と同じ1手でためる(取り消し1回で戻る)。`"refuse"` は終わっていない子孫が残っていれば親を直さず、その数を出す。`"keep"` は親だけを直し、残っている数を下の帯に出す。
- `closed_by`: 親の完了で一緒に完了にした子孫に、親へのリンク(`[[設計]]` の形)を書く列。親の完了と同じ1手でためるので、取り消し1回で戻る。自分で済ませていた子には書かない。省くと書かない(既定の列の名前は無い。ノートに列が黙って増えないように)。
- `on_reopen`: 完了の親を終わっていない値に戻したときの、`closed_by` がその親を指す子孫の扱い。`"keep"`(省いたとき)は子孫を変えない。`"reopen"` は子孫を親と同じ値に戻して `closed_by` を空にし、親と同じ1手でためる。`"ask"` はその場で「子も戻す」「親だけ」を選ぶ窓を出す(Esc なら親も直さない)。`"reopen"`・`"ask"` で `closed_by` を書いていないときは、戻す子が分からないので警告して `"keep"` として扱う。
- `gantt`: ガントで子孫の棒が、自分の日付を持つ親の期間からはみ出したときの扱い。`"mark"`(省いたとき)は子と親の行の名前の右端に `!` を付け、選んだ行の下の帯にはみ出した日数を出す。`"extend"` は子の棒を動かす・伸ばすと、親の始まりか終わりを子の範囲まで広げ、子と同じ1手でためる(親を動かしても子は動かさない)。`"none"` は何もしない。

子孫は、ビューの絞り込みやグループ分けによらず、表の全部の行のリンクでたどる。`key` の列のセルを直すときと新しいノートの窓のその欄には、まだどのノートにも親が無くても、同じ表のノートを候補に出す。その行自身と子孫は出さない(選ぶと親子が輪になるため)。親の完了で子孫を扱うのは画面で直したとき(セル・一括・カンバンの札・vim の `.`)だけで、`--apply` では扱わない。ビューの設定で親子をオンにしただけの表でも扱わない。`key` の列が表に無いとき(どのノートにも値が無く、`.base` の `properties` で名前も付けず、どのビューの `order` にも並べていないとき)は、ノートを読み終えてから警告(`.mdgrid/workspace.toml: table[1].children.key: …` の形)して親子にしない。`children` が表でない・`key` が無いときは警告して設定を外し、ほかの項目の値が違えば警告してその項目を既定にする。

```toml
# tasks/.mdgrid/workspace.toml — 子が残っているあいだは親を完了にせず、子を延ばしたら親も延ばす
[[table]]
name = "tasks"
path = "tasks"
children = { key = "parent", on_done = "refuse", gantt = "extend" }
```

ニュースは新しい順、支出は日付の新しい順のように、表ごとに決まった並びがあるときは、印の `[[table]]` に既定の並べ替えを書く: `sort = [{ property = "<列>", direction = "DESC" }, …]`。形は `.base` のビューの `sort` と同じで、`direction` は `ASC` か `DESC`(大文字小文字は問わない。省くと昇順)。書いた順が優先の順で、前の決まりで並びが同じ行を次の決まりで並べる。

効くのは、その表のビューのうち自分の `sort` を持たないもの(`.base` のファイルのビュー・印の `[[table.base.views]]`・並べ替えを持たない mdgrid のビュー)と、ビューの無い表。`--print` の出力、カンバンのレーンの中の札、ガントの行も同じ順になる。`sort` を持つビューはそのビューの `sort` のまま。見出しの `s` や並べ替えの窓(`S`)で並べ替えると、その決まりが先に効き、並びが同じ行はビューの `sort`(無ければ表の既定)の順に残る(既定が期限の順の表で状態の見出しを押すと、同じ状態の中は期限の順)。並べ替えの窓とビューの設定の並べ替えの区画では、既定から来た決まりに「既定・印」(表の既定)か「既定・ビュー」(ビューの `sort`)を添え、画面で変えたあとは窓の「既定に戻す」で戻せる。

書けるのは印の `[[table]]` だけで(画面の型の設定と同じ)、`workspaces.toml` と `views.toml` には書かない。全体の設定にも無い(表ごとに列が違うため)。`sort` が配列でないときは警告して使わず、`property` が無い・`direction` が `ASC` と `DESC` のどちらでもない決まりは警告してその決まりだけを外す。表に無い列はノートを読み終えたときに知らせる(`.mdgrid/workspace.toml: table[1].sort[1].property: …` の形)。

```toml
# research/.mdgrid/workspace.toml — ニュースは日付の新しい順、同じ日はファイルの名前の順
[[table]]
name = "ニュース"
sort = [{ property = "date", direction = "DESC" }, { property = "file.name", direction = "ASC" }]
```

印の `[[table]]` には、グラフの画面(`P`。[キー](keys.ja.md) の `chart`)の設定も書ける: `chart = { kind = "bar", x = "status" }`。鍵はどれも省ける。`kind` は種類(`bar` 棒・`stacked` 積み上げ棒・`line` 折れ線・`scatter` 散布図・`heatmap` ヒートマップ。省くと棒)、`x` は分ける列、`y` は値の数の列(省くと件数。散布図では縦の列で、数か日付の列)、`agg` は集め方(`count`・`sum`・`avg`・`min`・`max`。`y` があって省くと合計)、`by` は内訳の列(積み上げ棒・ヒートマップでは要り、省くと推し量る。折れ線・散布図では任意)、`unit` は日付の区切り(`day`・`week`・`month`。省くと収まる最も細かい単位)、`cumulative = true` は折れ線の累積、`name` は題に出す名前。グラフを複数書くときは配列(`chart = [ { … }, { … } ]`)にし、画面の `[` `]` で移る:

```toml
[[table]]
name = "tasks"
path = "tasks"
chart = [
  { name = "状態ごと", x = "status" },
  { name = "月ごとの期限", kind = "line", x = "due", unit = "month" },
  { name = "担当と状態", kind = "heatmap", x = "assignee", by = "status" },
]
```

省いた列は推し量る(分ける列は 状態の列 → 決まりのある列 → チェックボックス → リスト → 日付 → 最初の列の順)。知らない鍵や値、文字でない列の名前のグラフは警告して外し、表に無い列を指すグラフはノートを読み終えたときに知らせて外す。画面で切り替えた種類や列は印に書き戻さない。

印の `[[table]]` には、木の画面(`T`。[キー](keys.ja.md) の `tree`)の設定も書ける: `tree = { path = "<列>", separator = "<区切り>", order = "<列>" }`。`path` の列の値を `separator`(省略は ` > `)で切ったものを、その行の置き場の階層とみなし、`order` の列(省略してよい)でフォルダの中を並べる。階層の列が文字のリストなら最初の要素を使う。`path` の列が表に無い、区切りが空、`tree` が表でないときは、警告(`.mdgrid/workspace.toml: table[1].tree.separator: …` の形)して木を出さない。

```toml
# bookmarks/.mdgrid/workspace.toml — folder が「bar > 開発 > Web」のようなノートを、フォルダの木で見る
[[table]]
name = "Bookmarks"
path = "Bookmarks"
tree = { path = "folder", order = "order" }
```

印の `[[table]]` に `runs` を書くと、その表はルーチン(毎週のレビュー・毎月の請求のような繰り返しの仕事)の表になり、行ごとの決まりから、その回のノートを別のフォルダに1つずつ作る: `runs = { folder = "<フォルダ>", rule = "<列>", name = "<名前の雛形>", set = { <列> = <値> }, copy = ["<列>"], body = "<雛形のファイル>" }`。要るのは `folder`(回のノートを作るフォルダ。印の根からの相対)と `rule`(決まりの列)だけ。`name` は回のノートの名前の雛形(省略は `{routine} {date:YYYY-MM-DD}`。`{routine}` はルーチンのノートの名前、`{date}` は回の日で、ほかの変数は [`new_note`](#new_note) と同じ)、`set` は回のノートに入れる値、`copy` はルーチンの値を写す列、`body` は本文の雛形(印の根からの相対。省略は回の名前の見出し1行)。回のノートのフロントマターは、ルーチンへのリンク `routine`(`"[[名前]]"`)・回の日 `date`・`set`・`copy` の順。決まりの列の書き方は `daily`・`weekly mon thu`・`monthly 1 15`・`monthly last`・`every 3d`(列 `start` の日から)と、日本語の `毎日`・`毎週 月 木`・`毎月 1日 15日`・`毎月 末日`・`3日ごと`。作るのは今日までの一番新しい回だけで、作った回は見た目の状態の置き場の `routine.json` に覚え、同じ名前のノートは上書きしない。開いている画面は作る前に名前を見せて確かめ、`mdgrid <台帳> --runs` は確かめずに作る([手引き](manual/ja/tasks.md#ルーチンの回を作る))。表でない `runs`、`folder` か `rule` の無い `runs` は、警告(`.mdgrid/workspace.toml: table[1].runs.folder: …` の形)して、その表では回を作らない。

```toml
# notes/.mdgrid/workspace.toml — ルーチンの表に書いた決まりから、Runs/ に回のノートを作る
[[table]]
name = "ルーチン"
path = "ルーチン"
runs = { folder = "Runs", rule = "recurrence", set = { status = "todo" }, copy = ["actor"] }
```

ワークスペースには、縦に並べた表の形に名前を付けた**ページ**も書ける(印は `[[page]]`、`workspaces.toml` はそのワークスペースの `[[workspace.page]]`)。`name` と、上から並べる表の並び `tables` を書き、表ごとに範囲の表の名前 `table`・開くビュー `view`(省略は表のいつものビュー)・高さの比 `height`(1 以上の整数。省略は 1)を書く。画面のパレットの **並べ方に名前を付けて残す** も同じ形で書き足し(同じ名前なら置き換え)、印にはファイルの末尾に足すだけで、ほかの行とコメントは変えない。ページは表の一覧の引き出しの表の上に並び、`mdgrid -w <ワークスペース> --page <名前>`(印のワークスペースなら `mdgrid <フォルダ> --page <名前>`)でも開ける。読めない行(名前の無いページ・範囲に無い表の名前など)は `.mdgrid/workspace.toml: page[1].tables[2].table: …` の形で警告して飛ばす。

```toml
# notes/.mdgrid/workspace.toml — 朝はタスクの今日と進行中のプロジェクトを上下に見比べる
[[page]]
name = "朝"
tables = [
  { table = "tasks", view = "今日", height = 2 },
  { table = "projects", view = "進行中", height = 1 },
]
```

印の最上位には、[名前を付けた条件](#conditions--名前を付けた条件)・[通知の欄](#notices--通知の欄)・[知らせ](#notify--知らせ)も書ける(`[conditions.<名前>]`・`[[notices]]`・`[[notify]]`。形は全体の設定と同じ)。その台帳の表を開いたときだけ効き、全体のものと並べて使う。印の通知の欄の連絡の項目(`note`)は、台帳の中のファイルだけを指せる(`~`・絶対のパス・`..` で外へ出るパスは警告して使わない)。

```toml
# people/.mdgrid/workspace.toml — 人の台帳だけの条件。この台帳では 1 が「連絡する日が来た人」
name = "人と会議"

[conditions.contact]
label = "連絡する日が来た人"
expr = 'formula.contact <= today()'
key = 1
```

印は手で書かなくてもよい。**スターター**は、よくある台帳の印とノートの雛形(と少しの見本のノート)をひとまとめにしたもので、`mdgrid <フォルダ> --init-workspace --starter <名前>` が新しいフォルダに書く: フォルダが無ければ作り、`--with-samples` で見本のノートも入れ、上書きはしない(書く先のファイルが1つでもあれば何も書かない)。`mdgrid --starters` で一覧が1行ずつ出る: 組み込みの `tasks`・`tasks-ai`・`bookmarks`・`reading`・`people` と、自分のもの。画面ではパレットの **スターターから台帳を作る** が同じこと(選んで、作る場所を打ち、見本を入れるかを答える)。自分のスターターは設定のフォルダの `starters/<名前>/` に、組み込みと同じ形で置く:

```
starters/kanban/
  starter.toml                  # [name] と [description]。鍵は言語の符号(en・ja)
  ledger/                       # そのまま写す(台帳の根からの相対)
    .mdgrid/workspace.toml
    .mdgrid/templates/card.md   # [new_note] が指す本文の雛形({date} はノートを作るときに埋まる)
  samples/                      # --with-samples のときだけ写す。{date}・{date+N}・{now} … は写すときに埋まる
    Board/最初の札.md
  ledger.ja/  samples.ja/       # 任意: 言語が ja のとき、ledger/ と samples/ の代わりに使う
```

組み込みと同じ名前のスターターは、組み込みの代わりになる。いちばん早い作り方は、気に入った台帳の `.mdgrid/` を `starters/<名前>/ledger/` に写すこと([examples/places/mdgrid/starters/journal](../examples/places/mdgrid/starters/journal) が見本)。スターターのフォルダそのものはシンボリックリンクでもよい(dotfiles の道具が置く形)が、中のリンクはたどらないので、ファイルごとではなくフォルダごとリンクする。

## 項目

下が項目の全部。この一覧(道筋・「型」「既定」「範囲」の行・例)と、mdgrid が読む項目と、`--print-config` の出力が合っているかを試験で確かめている。

## 最上位(アプリ全体)

### `language`

- 型: `文字列("auto" か、"en"・"ja" などの言語の符号)`
- 既定: `"auto"`
- 範囲: 全体だけ

mdgrid の画面と起動の文言(`--help`・起動できない理由・警告)の言語。言語は英語(`en`)・日本語(`ja`)・ドイツ語(`de`)・スペイン語(`es`)・フランス語(`fr`)・韓国語(`ko`)・ブラジルのポルトガル語(`pt-BR`)・中国語の簡体字(`zh-CN`)・繁体字(`zh-TW`)。`"auto"` は `LC_ALL`・`LC_MESSAGES`・`LANG` の順で最初の空でない値から、言語と地域が合う言語(`zh_TW.UTF-8` なら `zh-TW`)、無ければ言語が合う言語(`de_AT.UTF-8` なら `de`。中国語は台湾・香港・マカオでなければ `zh-CN`、ポルトガル語はどれも `pt-BR`)を選び、どれも合わなければ英語にする(どれも無いときも)。言語の符号を書くと環境によらずその言語。知らない符号は警告して `"auto"` と同じにする。ノートの値・列の名前・`.base` の中身・ファイルの名前は訳さない。引数の誤りは設定を読む前に出すので、環境に従う。

```toml
language = "en"
```

### `editor`

- 型: `文字列`
- 既定: なし
- 範囲: 全体だけ

選んだノートを開くエディタ(`e`、または選んだ行のファイル名のクリック)。`"code -w"` のような引数つきでよい。値はシェルを通さずに単語に分け(引用符とバックスラッシュは POSIX と同じ)、ノートのパスを1つの引数として足す。書かないか、空か、空白だけなら、`$VISUAL`、`$EDITOR`、`vi`(Windows では `notepad`)の順で空でない最初のものを使う。エディタが終わると、そのノートを読み直すので、エディタはノートを閉じるまで戻らない形にする。すぐ戻るエディタ(すでに開いているタブのメモ帳など)は、`"code -w"` のように待つ形を `editor` に書く。Windows でパスを書くときは `/` で区切るか(`editor = "C:/tools/nvim.exe"`)、引用符で囲む。引用符の外の `\` は次の字を打ち消すので、`C:\tools\nvim.exe` のままでは起動しない。

```toml
editor = "nvim"
```

### `poll_ms`

- 型: `整数(1 以上)`
- 既定: `1000`
- 範囲: 全体だけ

mdgrid の外で変わったノートを読み直す間隔(ミリ秒)。

```toml
poll_ms = 2000
```

### `use`

- 型: `文字列(テンプレートの名前)`
- 既定: なし
- 範囲: 全体・ワークスペース・表・ビュー

テンプレート `[templates.<名前>]` を、同じ場所に書いた値の下に敷く。config.toml なら全体の、ワークスペース・表・ビューならその範囲の土台になる。無い名前は警告して無視する。

```toml
use = "night"
```

## `[terminal]` — 端末

### `terminal.color`

- 型: `真偽値`
- 既定: `true`
- 範囲: 全体だけ

色を使う。`false` で色なし(環境変数 `NO_COLOR`・`--no-color` と同じ)。

```toml
[terminal]
color = false
```

### `terminal.ambiguous_wide`

- 型: `真偽値`
- 既定: `false`
- 範囲: 全体だけ

East Asian Ambiguous の文字(`○`・`※` など)を幅2として扱う。端末が幅2で描くなら `true` にすると列がそろう。このとき窓の枠はいつも ASCII。

```toml
[terminal]
ambiguous_wide = true
```

### `terminal.nerd_font`

- 型: `真偽か "auto"`
- 既定: `"auto"`
- 範囲: 全体だけ

丸い札の端(Nerd Font の字 U+E0B6・U+E0B4)を描いてよいか。`true` は端末の字形が Nerd Font(どの Nerd Font でもよい)。`"auto"` は、その字を字体に頼らず自分で描く端末、Ghostty と WezTerm(`TERM_PROGRAM` で見分ける)のときだけ描き、ほかの端末では字が化けないようにする。描けないときは `"pill"` を `"soft"` で描き、淡い札・塗った札の端は四角のまま。端末はどの字体を使っているかをアプリに教えないので、ほかの端末で Nerd Font を使っているなら `true` と書く。ビューの設定の「見た目」の区画は、この項目を ui.toml に書く。

```toml
[terminal]
nerd_font = true
```

### `terminal.nerd_icons`

- 型: `真偽値`
- 既定: `false`
- 範囲: 全体だけ

設定のボタン(歯車)・画面の型のボタンと窓(表・関係マップ)・列の見出しと関係マップの箱の型の印(数・日付・日時・チェック・リスト・札の列と、箱のリンクの列)・カレンダーの題に、アイコン用のフォント(Nerd Font)の記号を使う。端末の字形が Nerd Font のときだけ `true` にする(ほかの字形では空の箱になる)。既定は字の記号(`⚙`・`▦`・`◇`・`#`・`◷`・`⋮`・`◉`・`↪` と、部品の形のチェックの印。既定は `✓`)。絵文字は使わない。記号の幅は画面のほかの所と同じく数える。

```toml
[terminal]
nerd_icons = true
```

### `terminal.herdr`

- 型: `真偽値`
- 既定: `true`
- 範囲: 全体だけ

[Herdr](https://herdr.dev) の窓で、今見ている表とビューで開き直す命令を Herdr に伝える。別の表やビューへ移るたびに伝え直す。Herdr のサーバーが止まって立て直したとき(パソコンを再起動したあとなど)、Herdr は同じ窓でその命令を走らせるので、mdgrid が同じ表とビューで戻ってくる。自分で mdgrid を終えたときは窓を返すので、開き直さない。Herdr のサイドバーには、窓の題として今の表とビューの名前(`タスク · 進行中` のように。ワークスペースの表なら表に付けた名前)が出て、終えると消える。`false` で Herdr を呼ばない(題も出さない)。Herdr の外では何もしない。命令を受け取れない道具には `mdgrid --continue` がある([説明書](manual/ja/features.md))。

```toml
[terminal]
herdr = false
```

## `[workspace]` — ワークスペース

### `workspace.detect`

- 型: `文字列の並び`
- 既定: `[".obsidian"]`
- 範囲: 全体だけ

書いたワークスペース(`-w`・`.mdgrid/workspace.toml` の印・`workspaces.toml`)に入らない表を開いたとき、上にたどって、この目印のフォルダを持つ最寄りのフォルダ(ルートフォルダ)をワークスペースとみなす: `".obsidian"`(`.obsidian/` のあるフォルダ)か `".git"`(git のリポ)。直下の、ノートのあるフォルダが関係マップの表になる。`[]` で検知しない。旧い値 `"vault"`・`"git"` も同じ意味で読み、移ったと警告する。検知したワークスペースには、上書きのワークスペースの範囲は無い。

```toml
[workspace]
detect = [".obsidian", ".git"]
```

## `[git]` — 保存のあとの git

ノートを git のリポに置いているとき、mdgrid が書いたノートを保存のあとに git へ渡せる。既定は何もしない。渡すのは mdgrid が書いた(か作った)ノートだけで、ほかの変更中のファイルやステージ済みのファイルはコミットに入れない。この区画は `config.toml` にだけ書く(台帳の印には書けない: 写してきた台帳が勝手に push しないように)。

### `git.auto`

- 型: `"off"・"add"・"commit"・"push"`
- 既定: `"off"`
- 範囲: 全体だけ

git をどこまで進めるか。`"off"` は何もしない。`"add"` は書いたノートをステージする。`"commit"` はさらにコミットする(書いたノートだけ)。`"push"` はさらに push する。git のリポでないフォルダでは何もしない。git が失敗したら(push 先が無いなど)1行で知らせ、保存そのものは済んだままにする。

```toml
[git]
auto = "commit"
```

### `git.when`

- 型: `"save"・"quit"`
- 既定: `"save"`
- 範囲: 全体だけ

いつ走らせるか。`"save"` は保存のたび(保存1回が1つのコミット)。`"quit"` は終了のときに1回(その起動の分をまとめて1つのコミット)。画面から作った新しいノートも対象で、終了のときに残っているノートはどちらの設定でもそこで流す。

```toml
[git]
when = "quit"
```

### `git.message`

- 型: `"auto"・"ask"`
- 既定: `"auto"`
- 範囲: 全体だけ

コミットの文。`"auto"` は1行目に「mdgrid: N 件のノートを更新」、空行のあとにリポの根からのパスを1行ずつ書く。`"ask"` は保存のたびに1行の欄を出し、打った文を1行目にする(空のまま Enter なら自動の文。Esc はコミットせず、終了のときのコミットに回す)。

```toml
[git]
message = "ask"
```

## `[look]` — テーマ・部品・色

### `look.theme`

- 型: `文字列("auto"・"default"・"nord"・"solarized-light"・"dracula"・"gruvbox"・"pink-monster"・"dozy-pink"・"sumi"・"slate"・"saas"・"saas-dark"・"paper")か表({ light, dark })`
- 既定: `"default"`
- 範囲: 全体・ワークスペース・表・ビュー

画面の色のテーマ。`"default"`・`"nord"`・`"solarized-light"`・`"dracula"`・`"gruvbox"`・`"pink-monster"`・`"dozy-pink"` と、落ち着いた組の `"sumi"`・`"slate"`・`"saas"`・`"saas-dark"`・`"paper"` のどれか。表 `{ light = "…", dark = "…" }` は端末の地の明るさ(`COLORFGBG` か端末への問い合わせ。分からなければ暗い地)で選び、省いた側は既定を使う。`"auto"` は `{ light = "saas", dark = "sumi" }` と同じ。`"default"` は端末の文字と地の色のまま。ほかのテーマは、地・文字・1行目・列の見出し・選んでいるセル・下の帯・一行おきの色・`>` の印をテーマの色で塗り、意味を持つ色(ためた値・検索の一致・差分の足した行と消した行)もテーマの地で読める色で塗る。色を使わない表示(`--no-color`・`NO_COLOR`・`TERM=dumb`・`terminal.color = false`)ではテーマは効かない。トゥルーカラーに対応しない端末では 256 色のうち近い色で塗る。知らない名前は警告して既定の見た目にする。狭い範囲に書いたテーマは、広い範囲の役割の色(`[look.colors]`)を使わない。

```toml
[look]
theme = { light = "paper", dark = "sumi" }
```

### `look.preset`

- 型: `文字列("sumi"・"slate"・"saas"・"paper"・"grid"・"classic"・"dozy-pink")`
- 既定: `"sumi"`
- 範囲: 全体・ワークスペース・表・ビュー

部品の形の組: `"sumi"`(既定。状態の前に色の点、タグは `·` で区切る、`✓`、選んだ行は印 `>` をアクセントの色に、見出しの下に線)・`"slate"`・`"saas"`・`"paper"`・`"grid"`・`"classic"`(0.2.0 の見た目)・`"dozy-pink"`(テーマ dozy-pink に合う柔らかい丸い札)。`[look.style]` で部品を1つずつ上書きする。狭い範囲に書いた組は、広い範囲の部品の形を使わない。

```toml
[look]
preset = "saas"
```

### `look.mode`

- 型: `文字列("modern" か "classic")`
- 既定: `"modern"`
- 範囲: 全体・ワークスペース・表・ビュー

色を使うときの見た目: `"modern"`(lazygit のように、選びは反転でなく背景の色、窓の枠とキーはアクセントの色、説明は薄い色)か `"classic"`(今までの反転)。どちらでも画面の文字は同じで、色を使わない表示ではどちらも classic。

```toml
[look]
mode = "classic"
```

### `look.cells`

- 型: `文字列("rich" か "plain")`
- 既定: `"rich"`
- 範囲: 全体・ワークスペース・表・ビュー

色を使うときの表のセルの見せ方。`"rich"` は `[look.style]` の形の部品で見せる: 真偽(`check`)、リストの要素(`tags`)、いくつかの値をくり返す短い文字の列(`status` など)の値(`status`)、リンクはアクセントの色(`links`)、列の見出しの型の印(`icons`)。同じ値はいつも同じ色で、文字はいつも見せる。`"plain"` は文字のまま。色を使わない表示ではいつも文字のまま。ノートに書く値・編集・検索・出力(`--print`)の値は変わらない。

```toml
[look]
cells = "plain"
```

### `look.style`

- 型: `表(status・tags・check・select・rules・tabs・frames・band・links・icons)`
- 既定: なし
- 範囲: 全体・ワークスペース・表・ビュー

組の部品の形を1つずつ上書きする:

- `status`(状態や担当のような、くり返す短い値): `"dot"`・`"shape"`(○ ◐ ●)・`"text"`・`"pill"`・`"tint"`・`"solid"`(値の色をそのまま塗った札)・`"soft"`・`"chip"`・`"plain"`
- `tags`(リスト): `"dots"`・`"hash"`・`"brackets"`・`"pill"`・`"tint"`・`"solid"`・`"soft"`・`"chip"`・`"plain"`
- `check`(真偽): `"box"`・`"tick"`・`"bracket"`・`"text"`
- `select`(選んでいる行とセル): `"bar"`・`"cross"`・`"tint"`・`"outline"`・`"fill"`・`"reverse"`
- `rules`(表の線): `"none"`・`"header"`・`"columns"`・`"grid"`
- `tabs`: `"underline"`・`"pill"`・`"segment"`・`"brackets"`・`"dim"`
- `frames`(窓の枠): `"rounded"`・`"square"`・`"heavy"`・`"ascii"`・`"none"`
- `band`(下の帯のキー): `"keys"`・`"boxed"`・`"quiet"`
- `links`: `"accent"` か `"plain"`
- `icons`: `true` か `false`(列の見出しの型の印)

`"plain"`(`check` は `"text"`、`icons` は `false`)はその部品を文字のままにする。`"pill"` は丸い端を Nerd Font の字で描くので、丸い端を描けるとき(`terminal.nerd_font`)だけ使い、そうでなければ `"soft"` で描く。`docs/catalog/index.html` のカタログで全部の形を見比べ、この表を作れる。

```toml
[look.style]
status = "chip"
select = "cross"
```

### `look.columns`

## `[new_note]` — 新しいノート

### `new_note`

- 型: `表(mode・folder・name・name_head・ask・required・hidden・body と [new_note.set])`
- 既定: なし
- 範囲: 全体・ワークスペース・表・ビュー

表から新しいノートを作るとき(ビューの帯の右の端の「+ 新規」・`a`)の決まり。どれも省ける。

- `folder`: 作る既定のフォルダ(開いたフォルダからの相対。空なら開いたフォルダ)。`..` や絶対パスで外に出る値には作らない。`.base` のビューの絞り込みに `file.inFolder("X")` があるときは、作った行がビューに残るように、そのフォルダ(ルートフォルダからの `X`)に作る。`folder` はそのフォルダの中(`X/inbox` など)のときだけ使う。
- `name`: 名前の欄に前もって入れる雛形。`{date}` は今日の日付(`YYYY-MM-DD`)。`{date:YYYYMMDD}_` なら名前が `20261118_` で始まる。
- `name_head`: `name` の雛形を埋めた文字の見せ方。`"show"`(既定)は名前の欄に入れて出す。`"hide"` は欄に出さず(名前の欄を離れたあとも)、打った名前の前に付けて作る(`sub/名前` と打てば最後の名前の部分に付く。`display.note_name` に当たる頭を自分で打った名前には重ねない)。`mdgrid --new-note <名前>` で作るときも、渡した名前に同じ決まりで付ける。表で頭を隠す `display.note_name` と組むと、日付を見ずに題だけを打てる。`"hide"` のときの変数 `{name}` は、頭を付ける前の打った名前(本文の雛形の `# {name}` は `# 買い物` になる)。
- `ask`: 新しいノートの窓に欄として並べる列の並び。無ければ表で見えている列を並べる。欄は列の型に合った入力で直し、空の欄は書かない。どの欄からでも `Ctrl+S` で作る。
- `required`: 空では作らない列。空のあいだは作らず、その欄に理由を出す。
- `hidden`: 窓に欄を出さずに値だけ入れる列(`[new_note.set]` と組んで、作成日などを入れる)。
- `mode`: `"form"`(既定。全部の欄を並べた窓)か `"editor"`(名前だけを聞き、前もって入れる値と本文の雛形で作って、すぐエディタで開く)。窓からも `Ctrl+E` で、作ってすぐエディタで開ける。
- `body`: 本文の雛形のファイル(開いたフォルダからの相対)。その中身を新しいノートの本文にする。フォルダを書くと、窓の名前の次に「雛形」の欄が出て、そのフォルダの `.md` から選べる(選ばなければ名前の順で最初のもの、「なし」を選べば本文なし。`--new-note` は選ばずに作ったときと同じ最初のもの。`.md` が1つも無いフォルダなら本文なし)。
- `[new_note.set]`: 新しいノートに前もって入れる値(列 = 値)。文字列・数・真偽・日付・その並び(リストとして縦の形で書く)。

雛形(`name`・`[new_note.set]` の文字の値・`body` のファイル)には次の変数を書ける。知らない変数はそのまま残る。

| 変数 | 値 |
|---|---|
| `{date}` | 今日(`YYYY-MM-DD`) |
| `{date+7}`・`{date-1}` | 今日から何日後・前 |
| `{date:YYYY/MM/DD}` | 今日を日付の形で(`dates.format` と同じ書き方) |
| `{time}` | 今の時刻(`HH:MM`) |
| `{now}` | 今の日時(`YYYY-MM-DDTHH:MM`) |
| `{weekday}` | 曜日 |
| `{name}` | ノートの名前(`name_head = "hide"` なら、隠した頭を付ける前の打った名前) |
| `{folder}` | 作る場所のフォルダ |
| `{uuid}` | このノートの新しい UUID(版4。`3f2b8c1e-9a4d-4e7b-8c21-5d6f7a8b9c0d` の形) |
| `{uid}` | このノートの新しい短い印(英小文字1字に数字か英小文字が7字続く8字。`k3f9x2ab` の形) |

`{uuid}` と `{uid}` は、1つのノートの中では同じ値です。`name = "{uid}_"` と `[new_note.set]` の `id = "{uid}"` を合わせて書けば、ファイルの名前とフロントマターに同じ印が入ります。その列を `hidden` に足せば、窓に欄を出さずに入ります。

`name` で埋まるのは、日付の変数(`{date}`・`{date:形}`・`{date+N}`・`{date-N}`・`{weekday}`)と印の変数(`{uuid}`・`{uid}`)だけです。ほかは書いた文字のまま残ります。名前を決める前なので `{name}` に入れる値が無く、時刻にはファイルの名前に書けない `:` が入るためです。

ビューの絞り込みのうち値が1つに決まるもの(`status == "todo"`・タグを含む など)は、`[new_note.set]` より先に入れる。`[new_note]` は1つの項目で、狭い範囲(ワークスペース・表、`views.toml` の `[table.view.new_note]` の mdgrid のビュー)に書けば丸ごと代わる。

```toml
[new_note]
folder = "inbox"
name = "{date} "
ask = ["priority", "due"]
required = ["due"]
hidden = ["created"]
body = "templates/note.md"

[new_note.set]
tags = ["inbox"]
due = "{date+7}"
created = "{now}"
```

## `[types]` — 列の型

### `types`

- 型: `表(列 = "text"・"number"・"checkbox"・"date"・"datetime"・"list"・"auto")`
- 既定: `{}`
- 範囲: 全体・ワークスペース・表・ビュー

列ごとの型。ここで決めた型は、ルートフォルダの型の設定(`.obsidian/types.json`。mdgrid は読むだけ)と、値からの推定より優先する。`"auto"` は推定に戻すので、狭い範囲で広い範囲の型を外せる。型は、セルの入力・型の合わない値の `!` の印・並べ替え・列の見出しの型の印に効く。ノートは書き換えない。列の見出しの型の印をクリックするか、パレットか操作の一覧の `column_type` で、選んだ列の型(か「自動」)を選ぶと、`views.toml` の表に書く。`file.*`・`formula.*` の列は自分の型のまま。知らない型の名前は警告して、その列は推定にする。

```toml
[types]
due = "date"
estimate = "number"
```

## `[rules]` — 列の決まり

### `rules`

- 型: `表の表(列 = { required = 真偽値, values = [文字列, …], then = { 値 = { 列 = 文字列 か { value = 文字列, if_empty = 真偽値 } } }, icons = { 値 = 文字列 }, labels = { 値 = 文字列 } })`
- 既定: `{}`
- 範囲: 全体・ワークスペース・表・ビュー

列ごとの決まり。列の型と合わせて確かめる。`required = true` は、キーが無い・`null`・空の文字列・空のリストを問題にする。`values` は選べる値の並びで、値(リストは各要素)がこのどれかでなければ問題にする(大文字小文字を区別する)。狭い範囲が項目ごとに勝つ(表の範囲で `values` だけを狭め、`required` は全体のものを使える)。決まりに合わない値と列の型に合わない値をまとめて「問題」と呼ぶ。問題には `!` の印が付き、下の帯に数が出て、`!` と `@` で次と前の問題に跳び、`problems_only` で問題のある行だけにでき、`mdgrid --check` で並べて出せる(CI 向け)。決まりの確かめはノートを書き換えず、値を書くことも止めない。`values` のある列は、セルの入力の候補にその値を並べる。`values` のある列でグループ分けすると、まとまりはその順(降順なら逆)に並び、`values` に無い値はそのあとに文字の順で、値の無い行は最後に来る(カンバンのレーンと同じ順)。`--print` の行もこの順に出る。計算の列(`file.*`・`formula.*`)には書けない。知らない項目と型の違う値は警告して使わない。

`then` は、その列をある値に直したとき、同じ行のほかの列にも値を入れます。`[rules.<列>.then]` の下に `値 = { 列 = "入れる文字" }` と書きます。入れる文字には[雛形の変数](#new_note)(`{date}`・`{now}`・`{uuid}` など)を書け、入れる先の列の型で読みます。空の文字なら、その列を空にします。一緒に入れる値は、直した値と同じ変更としてたまります。保存の前の差分に出て、取り消し1回で両方が戻り、セルを別の値に直せば外れます。セルの直し・一括の編集・チェックボックス・カンバンで札を動かしたときに効きます。その列が空のときだけ入れたいときは、文字の代わりに `{ value = "{date}", if_empty = true }` の表で書きます。入れる先の列が空(キーが無い・`null`・空の文字列・空のリスト。前にためた値があればその値で見る)のときだけ入れるので、始めた日のように最初の1回だけ入れたい値は、状態を行き来しても上書きされません。セルを別の値に直したときに外すのは、`then` が入れた値のままのときだけで、手で入れた日付は残ります。`value` が無い・`if_empty` が真偽でない・知らない項目のある表は、警告してその列には入れません。狭い範囲に `then` を書けば、丸ごと代わります。下の例は、`status` を `done` にしたら `done_at` に今日を入れ、`doing` にしたら `started` が空のときだけ今日を入れます。

`icons` と `labels` は、画面での値の見え方を決めます。`icons = { todo = "○" }` と `labels = { todo = "未着手" }` なら、`todo` はまとまりの見出し・カンバンのレーンの題・表のセル(札でも文字でも)・詳細・木の画面の右の欄で `○ 未着手` になります。字だけ書いた値は `○ todo`、どちらも書かない値は値のまま。札の色は値で決まるので、名前を付けても色は変わりません。字は Nerd Font の字でもよく、書いたとおりに出します。字の幅は画面のほかの字と同じに数えるので、`○` のような字が字体で2桁に描かれて次の字に重なるなら、[`terminal.ambiguous_wide`](#terminalambiguous_wide) を入れてください。値を選ぶ窓(セルを直すときと新しいノートの窓の候補・リストの値の付け外し・絞り込みの窓とビューの設定の値の一覧・値の件数の窓)には、名前のある値を `未着手 todo` のように名前と値で並べ、どの値を選ぶのかが分かるようにします。`\` の簡易の絞り込みと `/` の検索は、値でも名前でも当たります。ノートに書く値と `--print`・`--count`・CSV の書き出しは元の値のままです。同じ表の `values` に無い値の項目は、その道筋(`rules.status.icons.blocked`)を言う警告を出して使いません。`values` を広い範囲に書いたときは、そこに無い値の項目を黙って出しません。狭い範囲に `icons` か `labels` を書けば、丸ごと代わります。

```toml
[rules.status]
required = true
values = ["todo", "doing", "done"]
icons = { todo = "○", doing = "◐", done = "●" }
labels = { todo = "To do", doing = "In progress" }

[rules.status.then]
done = { done_at = "{date}" }
doing = { started = { value = "{date}", if_empty = true } }
```

## `[format]` — 数の見せ方

### `format`

- 型: `表の表(列 = { thousands = 真偽値, decimals = 0〜10 の整数, prefix = 文字列, suffix = 文字列 })`
- 既定: `{}`
- 範囲: 全体・ワークスペース・表・ビュー

列ごとの数の見せ方です。`thousands = true` で整数の部分を3桁ごとに区切ります。`decimals` は小数の桁で、足りない桁は `0` で埋め、超える桁は四捨五入します(`decimals = 1` なら `1234.56` は `1,234.6`、`3` は `3.0`)。書かなければ値の桁のままです。`prefix` と `suffix` は数の前と後ろに付ける字で、負の数は `-` を頭の字の前に置きます(`-¥1,200`)。桁の区切りと小数点は画面の言語の習慣に合わせます: 英語・日本語・中国語・韓国語は `1,234.5`、ドイツ語・スペイン語・ポルトガル語は `1.234,5`、フランス語は `1 234,5`(狭い空き)。`formula.*` の列にも書けます(名前を引用符で囲む: `[format."formula.rate"]`)。文字の値と、[`labels`](#rules) で名前を付けた値は、そのままの見え方です。

見せ方は、表のセル・詳細・ためた値・集計の行・まとまりの見出しの小計と、その列を値にしたグラフの値(合計・平均・最小・最大)に効きます。件数を数える集計(`Checked`・`Unchecked`・`Empty`・`Filled`・`Unique`)と件数のグラフは、ふつうの数のままです。見せ方だけなので、ノート・並べ替え・絞り込み・式・編集の欄・`--print`・`--count`・コピーは元の数のままです。狭い範囲が項目ごとに勝ちます。知らない項目・型の違う値・0〜10 の外の `decimals` と、制御の文字か文字の向きを変える書式の文字を含む `prefix`・`suffix`(印は人から受け取った台帳にも入っていて、端末の画面を乱せるため)は、警告して使わず、ほかの項目は効きます。

```toml
[format.amount]
thousands = true
prefix = "¥"

[format."formula.rate"]
decimals = 1
suffix = "%"
```

## `[keys]` — キー

### `keys`

- 型: `表の表([keys.<モード>] の下に キー = 動作)`
- 既定: なし
- 範囲: 全体だけ

モードごとにキーを割り当て直す。書かなければ組み込みのキーの割り当て。`[keys.<モード>]` の下に `キー = "動作の名前"` と書く。動作の名前 `"none"` でそのキーを外す。キーは `"j"`・`"ctrl+s"`・`"shift+tab"` のように書き、`"g g"` のような続けて押すキーは空白で区切る。

モード: `table`・`edit`・`review`・`quit`・`help`・`palette`・`search`・`filter`・`detail`・`settings`・`settings_input`・`chips`・`list_select`・`menu`・`freq`・`sorts`・`relations`・`drawer`・`filter_window`・`filter_input`・`screen_menu`・`column_type`・`tree`・`gantt`・`kanban`・`chart`・`notice`・`switch`、vim モードの `input_normal`。動作の名前はコマンドのパレット(`:`)に出る。モードごとの既定のキーと動作の名前の全部は [keys.ja.md](keys.ja.md) にある。知らないモード・キー・動作は警告して飛ばす。

```toml
[keys.table]
"ctrl+f" = "search"
"x" = "none"
```

### `keys.vim`

- 型: `真偽値`
- 既定: `false`
- 範囲: 全体だけ

vim モードにする。入力の欄(セル・探す・検索・パレット・設定の値・新しいノートの名前)は挿入のモードで始まり、いつもどおり打てる。Esc でノーマルのモードに移り、`h` `l` `0` `$` `w` `b` `e` で動き、`i` `a` `I` `A` で挿入に戻り、`x` `X` `dw` `db` `d$` `D` `dd` で消し、`cw` `c$` `C` `cc` で替え、`u` で取り消す。ノーマルのモードの Esc で入力を取りやめ、Enter はどちらのモードでも決める。下の帯に `-- 挿入 --` か `-- ノーマル --` が出て、カーソルは棒か四角になる。

表には3つのキーが足される。`dd` は印を付けた行(印が無ければ選んでいる行)のノートを、名前を確かめてからごみ箱へ動かす。`p` は `y`(セル)か `Y`(行)で写した値を入れ、`.` は直前にセルに入れた値を、選んでいる行の同じ列にもう一度入れる。数字は回数にせず、ほかのキーのために空けておく。パレットの `q!`(保存せずに終わる)は vim モードによらず使える。

`false`(既定)ではキーは今までどおり。足すキーは [keys.ja.md](keys.ja.md#input_normal) にあり、`[keys.table]` と `[keys.input_normal]` で割り当て直したり外したりできる。

```toml
[keys]
vim = true
```

## `[search]` — 表を横断して探す

### `search.across`

- 型: `真偽値`
- 既定: `false`
- 範囲: 全体だけ

コマンドのパレット(`:`)に「ワークスペースを横断して探す」を足す。どの表に書いたか覚えていない行を、表を1つずつ開かずに見つけるときに使う。語を打って Enter を押すと、今のワークスペースの表の全部(ワークスペースを開いていなければ登録した表)を裏で読み、当たった行を表ごとに、ノートの名前と、当たった列と値を添えて並べる。当て方は検索の欄(`\`)と同じで、ノートの名前か値が語を含めば当たり、語に大文字が無ければ大文字小文字を区別しない。

結果は読み終えた表から出し、読み終えるまで「3 / 5 を読みました」と見せる。Esc で止めると、元の表の画面のまま戻る。読めない表は飛ばし、結果の終わりに名前を出す。行を選んで Enter を押すと、その表を開き、検索の欄に同じ語を入れてその行を選ぶ。ためた変更があれば、引き出しで表を移るときと同じく先に確かめる。

`false`(既定)ではパレットにこのコマンドを出さず、使わない人の画面は変わらない。

```toml
[search]
across = true
```

## `[templates]` — テンプレート

### `templates`

- 型: `表の表([templates.<名前>] の下にプロファイルの項目)`
- 既定: なし
- 範囲: 全体だけ

名前を付けたプロファイルの断片(`[look]`・`[display]`・`[dates]`・`[edit]`・`[new_note]`)。どの範囲でも `use = "<名前>"` で、その範囲の値の下に敷く。テンプレートの中に `use` は書けない。ビューの設定の「見た目」の区画で保存したテンプレートは ui.toml に入り、同じ名前なら ui.toml のものが config.toml より先。

```toml
[templates.night.look]
theme = "dracula"
preset = "dozy-pink"
```

## `[conditions]` — 名前を付けた条件

### `conditions`

- 型: `表の表([conditions.<名前>] の下に expr・label・key・hide)`
- 既定: なし
- 範囲: 全体・ワークスペースの印

「期限が1週間以内」のように、よく使う条件に名前を付けて1回だけ書く。`expr` は `.base` の絞り込みと同じ書き方の式。名前は英字で始め、英数字・`_`・`-` だけにする。書いた条件は、名前で次のように使える。

- どの式でも `cond("<名前>")`(行が当たれば真): `--print --filter`・`--count --filter`・画面の式の絞り込み・`.base`・ほかの条件の式。
- `key = 1` 〜 `9`: その数字のキーで当たる行だけにし、もう一度押すと全部に戻す(2つ以上入れると、全部に当たる行だけ)。数字のキーと通知の欄から付けた条件は、選択と検索の欄の絞り込みが無ければ、表の画面の `Esc` で全部解ける(`hide = true` の条件はそのまま)。
- ビューの設定(`o`)のフィルターの区画: そのビューで、当たる行だけを残すか、当たる行を隠す。
- `hide = true`: どの表と画面でも、`--print`・`--pick`・`--count` でも、当たる行を隠す。設定の帯に条件と隠した行の数が出て、その条件の数字のキーで出し直せる。`--show-hidden` を添えると出力にも出す。

例の `far` は、始まりが30日より先の予定を隠す。ただし期限が1週間以内なら出す。`label` は設定の帯とヘルプに出す名前(`label = "期限が近い"`)。式の中の `cond()` では、表に無い列は値の無い列として読むので、1つの条件を列の違う表にも使える。決まりに外れた名前・読めない式・輪になって呼び合う条件・同じファイルでほかの条件が先に使っている数字は、警告して使わない。

条件は、台帳の印 `.mdgrid/workspace.toml` の最上位にも同じ形で書ける。人の台帳なら「連絡する日が来た人」、お金の台帳なら「支払い日が近い」のように、その台帳だけの条件を台帳と一緒に配れる。印に書いた条件は、その印の台帳の表を開いたときだけ使え、全体の条件と並べて使う。同じ名前なら印のものが勝ち、全体の条件の式の中の `cond()` も印のものを指す。スターターの印に書けば、そのスターターから作った台帳でもそのまま効く。どちらの条件が効いているかは `mdgrid <表> --print-config --resolved` の出どころのコメントで分かる。

数字のキーは、`key` を書いた条件に、印の条件を先に、全体の条件を後に、1 から詰めて振る。`key` の数は振る順で、同じ印や同じ設定の中では小さい数が先になる。式が使う列(ノートのキーと `formula.*`)が今の表の行に1つでも無い条件は、その表では数字のキーにもヘルプにも、ビューの設定のフィルターの区画にも出ない。タスクの条件(期限・担当)を全体に書いておいても、人の台帳では 1 から台帳の条件が並び、押して 0 行になる数字は出ない。`hide = true` の条件は、列の有無によらず当てる。

```toml
[conditions.soon]
expr = 'due <= today() + "7d"'
key = 1

[conditions.far]
expr = 'start > today() + "30d" && !(due <= today() + "7d")'
hide = true
key = 9
```

## `[[notices]]` — 通知の欄

### `notices`

- 型: `表の並び([[notices]] の下に cond・text・scope・show_zero か note・lines)`
- 既定: なし
- 範囲: 全体・ワークスペースの印

期限切れのタスクの数のように、目に入れておきたいことをヘッダーの上の小さな欄に出す。ここに項目を書いたときだけ出て、書かない人の画面は変わらない。`[[notices]]` の1つが1項目で、書いた順に並ぶ。台帳の印の最上位にも書け、印の項目はその台帳の表でだけ、全体の項目より先に並ぶ(連絡の項目の相対の `note` は印のフォルダから)。

- 件数の項目は、[名前を付けた条件](#conditions--名前を付けた条件)(`cond`)に当たる行を数える。`text` は `{count}` を数に置き換える文(無ければ条件の見せる名前と数)。`scope` は数える範囲で、`"table"`(開いている表。既定)・`"workspace"`(今のワークスペースの表の全部)・表の名前の並びから選ぶ。数えるのは、表の絞り込みと `hide = true` の条件を当てたあとの行で、ビュー・検索・数字のキーには左右されない。0 件の項目は出さない(`show_zero = true` なら出す)。条件の式が使う列の無い表は数えず、`"table"` の項目は、開いている表に列が無ければ `show_zero` によらず出さない。
- 連絡の項目は、ノート(`note`。先頭の `~` はホーム、相対なら設定のファイルのフォルダから)の本文の空でない行を頭から `lines` 行(既定 1)出す。

件数の項目は1行目に ` · ` でつなぎ、連絡の行は1行ずつで、欄は3行まで。欄へはキーで移り、項目を選んで `Enter` を押すと、件数の項目はその条件で表を絞り(ほかの表を数える項目なら、当たる行のある表を並べる)、連絡の項目はノートをエディタで開く。`mdgrid --notices` は同じ項目を1行ずつ出す(tmux の帯・シェルのプロンプト・Herdr のサイドバーに)。

```toml
[[notices]]
cond = "overdue"
text = "{count} overdue"
scope = "workspace"

[[notices]]
note = "~/notes/inbox.md"
lines = 2

[conditions.overdue]
expr = 'due < today() && status != "done"'
```

## `[[notify]]` — 知らせ

### `notify`

- 型: `表の並び([[notify]] の下に cond・scope・title・text・to・group_over・group_text・command)`
- 既定: なし
- 範囲: 全体・ワークスペースの印

[名前を付けた条件](#conditions--名前を付けた条件)に行が新しく当たったときに知らせる。思い出したい時刻が来たときや、タスクが期限切れになったときに使う。ここに項目を書くまでは何も起きない。`[[notify]]` の1つが1つの条件を見張り、1つの条件を見張れるのは1項目だけ。台帳の印の最上位にも書け、印の項目はその台帳の表を開いた画面と、その台帳を開く `mdgrid <台帳> --notify` でだけ確かめる。全体と印に同じ条件の項目があれば、その台帳では印の項目を使う。条件の式が使う列の無い表の行は知らせない。印の項目には、コマンドの出し先(`to` の `command` と `command`)を書けない。印は人から受け取ったフォルダにも入っているので、開いただけでほかの人のコマンドを動かさないためで、書いてあれば警告してその出し先を外す。コマンドに出す知らせは `config.toml` に書く。

- `cond` は見張る条件。
- `scope` は見張る表で、`"workspace"`(今のワークスペースの表の全部。既定)・`"table"`(開いている表)・表の名前の並びから選ぶ。
- `title` と `text` は知らせの題と文。`{列の名前}` はその行の値になり、`{file.name}` や `{formula.x}` も使える。行に無い列は空になる。書かなければ、題は条件の見せる名前、文はノートの名前。
- `to` は出す先の並びで、`"desktop"`(OS の通知。既定)・`"terminal"`(端末の通知)・`"command"`(自分のプログラム)から選ぶ。
- `command` は `"command"` で動かすプログラムと引数の並び。引数の `{title}`・`{text}`・`{path}` を埋める。シェルを通さないので、ノートの値が命令として動くことはない。
- 1回の確かめで新しく当たった行が `group_over`(既定 3)を超えたら、1件の知らせにまとめる。`group_text` はその文で、`{count}` が行の数になる(既定は「新しく 4 件」)。

知らせるのは、行が当たり始めたときの1回だけ。当たり続けている間は黙り、外れてからまた当たれば、もう一度知らせる。項目を足したときに既に当たっている行は、知らせずに覚えるだけなので、一度にたくさん届くことはない。この記録は mdgrid の状態のフォルダに置き、ノートには書かない。

確かめるのは、表を開いたとき・保存したあと・開いている間の1分ごと。閉じているあいだは、`mdgrid --notify` が画面を出さずに1回確かめる。OS の定期実行から呼ぶ([登録のしかた](manual/ja/tasks.md#新しく当たった行を知らせる))。画面と同じ記録を使うので、同じ行を二度知らせない。届けられなかったときは、理由を画面の下に1回だけ出し、その行は次の確かめでまた知らせる。

OS の通知は、macOS・Windows・WSL では OS に元からある仕組みで出す。WSL の中からは Windows の通知に出る。Linux では `notify-send` が要る。`"terminal"` では、使っている端末(iTerm2・kitty・Ghostty・WezTerm・foot・Windows Terminal)が読む合図を1つだけ送り、ほかの端末にはベルを鳴らす。tmux の中では `set -g allow-passthrough on` を入れておく。

```toml
[[notify]]
cond = "remind"
text = "{title} ({remind})"
to = ["desktop", "terminal"]

[conditions.remind]
expr = 'remind <= now() && status != "done"'
```
