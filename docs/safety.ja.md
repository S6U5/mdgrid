# 書き戻しの安全

[English](safety.md)

mdgrid はノートをその場で書き換えるので、1つの約束を芯にしている: 直した値だけを変え(必要なら、キーの行かフロントマターを足す)、ファイルのほかのバイトは1バイトも変えない。この文書は、mdgrid が何を書くか、どのノートと値を書かないか、直している間にノートが外で変わったらどうなるか、ファイルを実際にどう書くかを説明する。書いてあるのは今の振る舞い。

下の読むだけのノートの例は、試験(`tests/test_safety_docs.rs`)で確かめている。例を1つずつフロントマターの読み取りに通し、書いた理由で読むだけにならなければ落ちる。読み取りに、この文書に無い理由が足されても落ちる。

## mdgrid が変えるもの

直した値はすぐには書かない。ためる変更として持ち(表に印が付き、下の帯に数が出る)、保存の操作(既定は `Ctrl+S` と `:w`)で初めて書く。書く前に、ファイルごとの差分を見せて確認をとる。ためる変更は取り消し・やり直しができ、ためたまま終わろうとすると、保存する・捨てる・戻る を確かめる。

書くときに変えるのは、次のものだけ:

- **直したキーの値。** フロントマターの中でそのキーの値のバイトの範囲を探し、その範囲だけを置き換える。ほかのキー・キーの順・コメント・空行・改行コード(LF か CRLF)・本文は1バイトも変えない。書いた前後の差分は、直した値のところだけになる。
- **無いキーを足す1行。** フロントマターはあるがキーが無いノートには、フロントマターの末尾に `key: 値` の1行を足す。リストの値は Obsidian と同じ縦の形(`key:` の次の行から `  - 要素`)で足す。
- **フロントマターの無いノートに足すフロントマター。** フロントマターの無いノート(1行目が `---` でない)には、先頭に `---`・`key: 値`・`---` を足し、本文のバイトは変えない。空のフロントマター(`---` が2行だけ)のノートには、2つの区切りの間にキーの行を足す。この2つは設定で止められる(下の [`no_frontmatter`](#no_frontmatter) を見る)。
- **キーの名前の変更・削除のときの、キーの名前か、キーの行。**(列の操作の「キーの名前を変える」「キーを消す」)名前の変更は、キーの行のキーの名前のバイトだけを置き換え、値・引用符・コメントはそのまま。削除は、キーの行とその値の行(リストの要素・複数行の文字)を消し、後ろの空行とコメントは次のキーのものとして残す。

足す行の改行コードはファイルに合わせる(改行が1つも無いファイルは LF)。

mdgrid が書くのは、ノートのフロントマターの第1階層のキーだけ。ノートの本文は書き換えず(`e` でエディタで開く)、`.base` も書き換えず、ほかの既にあるファイルも置き換えない。作るファイルは、新しいノート(上の無いフォルダも作る)、ビューを書き出すときに名前を決めた新しい `.base`、保存の間に使う一時ファイル([ファイルの書き方](#ファイルの書き方)を見る)、設定の置き場(`$XDG_CONFIG_HOME/mdgrid/`、無ければ `~/.config/mdgrid/`)の `views.toml`、状態の置き場(`$XDG_STATE_HOME/mdgrid/`、無ければ `~/.local/state/mdgrid/`)の見た目の状態のファイルだけ。`config.toml` は読むだけで書かない。

値の書き方:

- 新しい値は、元の値と同じクオートの種類(素・`'単一引用符'`・`"二重引用符"`)で書く。元のクオートで安全に表せない値は二重引用符で書く。改行を含む値は受け付けない。
- YAML がほかの型として読みうる文字列(`no`・`yes`・`on`・数字に見える文字列・`: ` や ` #` を含む値・先頭が記号の値など)はクオートし、YAML 1.1 と 1.2 のどちらで読んでも同じ文字列になるようにする。
- 日付・日時の列の日付は、Obsidian と同じく囲まずに書く(`due: 2026-11-03`)。元の値が引用符で囲んであれば、その引用符を保つ。ただし引用符つきの空の文字列(`due: ""`)は、囲まない日付に置き換える。テキストの列に日付に見える文字を書くときは囲む(囲まずに書くと型が変わるため)。
- 値を直してから、ファイルから最後に読んだ値に戻すと、そのセルはためる変更から外れ、書かれない。「同じ」値でも書き直すとクオートや書式が変わりうるので、触らない。
- リストは元の形(1行の `[a, b]` か、1行に1要素の縦の形)と字下げを保ち、変えていない要素は元の書き方のまま書く。要素を全部外すと `key:` と書き、キーは消さない。

## 読むだけのノート

壊すおそれがあるか、どちらの値かを推測しないと書けないノートがある。mdgrid はこれらのノートを表に出すが、行全体を読むだけにし、セルを直そうとすると理由を出す。`add_frontmatter` で変わる2つの形を除き、どの設定でも変えられない。

理由ごとに、小さな例のノートを添える。例では、印の無い行は LF で終わり、次の印はバイトを表す:

- `<BOM>` は UTF-8 の BOM(EF BB BF)。
- 行の終わりの `<CRLF>` は、その行が LF でなく CR LF で終わること。
- `<XX>`(大文字の16進の数字2つ)は、その1バイト(例: `<E9>`)。

### `no_frontmatter`

1行目が `---` でなく、フロントマターが無い。

```text
会議のメモ
リリースの日を話した。
```

既定では書ける。値を保存すると、先頭にフロントマターを足し、本文はそのまま。設定のファイルに `add_frontmatter = false` と書くと、このノートは読むだけになり、理由を出す。

1行目が `+++` のノート(Hugo・Zola の TOML のフロントマター)は、設定によらず読むだけ。上に YAML の区画を足すと、生成器が読めないページになるため。

### `empty_frontmatter`

フロントマターが開きと閉じの `---` だけで、間に何も無い。

```text
---
---
会議のメモ
```

既定では書ける。値を保存すると、2つの `---` の間にキーの行を足す。設定のファイルに `add_frontmatter = false` と書くと、このノートは読むだけになり、理由を出す。区切りの間に空行やコメントの行だけがあるものは空ではなく、普通のフロントマターとして扱う。

### `bom`

ファイルが UTF-8 の BOM で始まる。

```text
<BOM>---
status: todo
---
会議のメモ
```

BOM の後ろのフロントマターが読めれば、値は見せる(`--print` でも出す)。断るのは書き込みだけ。

### `not_utf8`

ファイルが UTF-8 として読めない(Latin-1 や Shift_JIS で保存したノートなど)。

```text
---
title: Caf<E9>
---
会議のメモ
```

### `mixed_newlines`

フロントマターの中で改行コード(CRLF と LF)が混ざる、または行の中に CR だけがある。見るのは開きの `---` から閉じの `---` までの行だけで、本文の改行コードは混ざっていてよい。

```text
---<CRLF>
status: todo
---<CRLF>
会議のメモ
```

### `duplicate_key`

同じ第1階層のキーが2回以上あり、直す値を1つに決められない。

```text
---
status: todo
status: done
---
会議のメモ
```

### `unclosed`

フロントマターが `---` で始まるが、閉じの `---` が無い。

```text
---
status: todo
会議のメモ
```

### `invalid_yaml`

フロントマターが、mdgrid が YAML として安全に読める形でない。よくあるのは、クオートの無い値に `: ` を含むもの(YAML では誤り)。ほかに、閉じないまま終わり続きの行も無いフローのリスト(次の行に続くものは、その値だけが読むだけになる。[読むだけの値](#読むだけの値)を見る)、字下げのタブ、最初のキーより前の字下げの行など。

```text
---
title: Re: リリースの日
---
会議のメモ
```

区切りの間を1つの JSON・フローの形のマップ(`---` の間に `{"status": "todo"}`)で書いたフロントマターも読むだけだが、値は見せる(`--print` でも出し、`file.tags` にも入れる)。

### `hard_link`

ノートのファイルにハードリンクが2つ以上ある(Unix)。保存はファイルを新しいファイルで置き換えるので、書くとこの名前がほかのリンクから切り離される。そのため書かない。ノートの中身でなくファイルシステムから分かるので、例のノートは無い。ノートを読んだときに行を読むだけにし、保存のときにも(置き換える直前にも)もう一度確かめる。

## 読むだけの値

書けるノートの中でも、セルによっては読むだけになり、それぞれ理由を出す:

- フロントマターのキーでない列: ファイルの属性(`file.*`)と式の列(`formula.*`)。
- ネストした map(`key:` の次の行から字下げした `sub: 値`、または `{a: 1}`)と、ブロックスカラー(`|` と `>`)。表には出すが書き換えない。
- アンカーや別名を使った値(`&a`・`*a`)、タグつきの値(`!!str 12`)、複数行にまたがる値(次の行に続く素のスカラーや引用符つきの値、`[a,` の次の行に ` b]` と続くフローのリスト)。
- 保管庫の根ごとの `types.json` で型が違う列。
- 元の書き方を保って書き直せないリスト。リストの列では、要素の付け外しの画面を開かず、形ごとの理由を出す: 要素の間の空行やコメント、要素の行末のコメント、字下げの違う要素、`-` のあとのタブ、次の行に続く要素、入れ子の要素(要素の中のリストや map)、文字列でない要素(`- 2024` など。書き直すと型が変わる)。リストの列で1つの文字列で書かれた値(`tags: x`)は1つの要素のリストとして開き、直すと `tags: [x, y]` に書き換える。文字列でない1つの値(`tags: 2024`)は読むだけ。

たとえば次のノートでは、`notes` と `aliases` は読むだけで、`status` は直せる:

```yaml
---
status: todo
notes: |
  1行目
  2行目
aliases:
  - one

  - two
---
```

## 外の変更

mdgrid で開いている間に、ノートがディスクの上で変わることがある。Obsidian や `e` で開いたエディタで直したとき、同期の道具が書き換えたときなど。

- **見つけ方。** mdgrid はファイルの更新時刻と大きさを見回る(`poll_ms` ごと。既定は 1000 ミリ秒)。ためた変更の無いノートは、そのまま読み直す。ためた変更のあるノートも読み直して表に新しい値を出すが、ためた変更は残し、行に「外で変更」の印(`!`)を付ける。ためた値がファイルの値と同じになったら、そのセルはためる変更から外れる。
- **保存の基準。** ノートごとに基準を持つ: そのノートに最初に変更をためた時点で、最後に読んだ内容の更新時刻・大きさ・SHA-256 のハッシュ。外の変更で読み直しても、基準は変えない。mdgrid が自分で書いたあとは、書いた内容を新しい基準にするので、同じノートの2回目の保存を外の変更と誤らない。
- **保存が止まる。** 書く直前にノートを読み直し、更新時刻・大きさ・ハッシュのどれかが基準と違えば、そのノートは書かない。ほかのノートは保存する。止まったノートのためた変更は残り、保存の確認の画面にその差分と「外で変更」の印が出る。
- **上に書く・捨てる。** 止まったノートでは、`o` で外の変更の上に書くか、`d` でそのノートのためた変更を捨てる(ファイルは外の変更のまま)かを選ぶ。上に書くときは、ファイルを読み直し、それが差分で見せた内容と同じときだけ新しい基準にする。そのうえで直した値だけを書くので、ほかのキーや本文への外の変更は残る。差分を見たあとにまた外で変わっていたら書かず、差分を作り直して見直してもらう。戻る(`Esc` か `q`)を選べば、ためた変更をあとのために残せる。

同期の道具の競合ファイル(名前に `.sync-conflict-` か `conflicted copy` を含むもの)にも印を付けるので、気づいて手で片づけられる。

## ファイルの書き方

ノートの保存は、次の順に進む。どの段で失敗しても、元のノートには触らず、一時ファイルを消し、ためた変更は残す。

1. **基準を確かめる。** シンボリックリンクを辿り、辿った先のファイルを対象にする。ハードリンクが2つ以上あるノートと、書き込みの権限の無いノートは断り、ノートを読み、基準と違えば止める。
2. **新しい内容をメモリの上で作って検査する。** 直した値の範囲だけを置き換え、結果を読み直して、直したキーが意図した値で、ほかのキーの値と形が前と同じで、知らないキーが増えておらず、本文が変わっていないことを確かめる。どれかが違えば書かない。
3. **同じフォルダに一時ファイルを書く。** 一時ファイルはノートの隣に作る(`.` で始まり `.mdgrid-tmp.` を含む隠れた名前)ので、最後の名前の変更は1つのファイルシステムの中で済む。ノートの権限を一時ファイルに写し、Unix では持ち主とグループも写す。
4. **書いて fsync し、読み直す。** 新しい内容を一時ファイルに書き、`fsync` でディスクに書き切る。それから一時ファイルを読み直し、検査した内容と1バイトずつ同じか確かめる。
5. **置き換える直前にもう一度確かめる。** ハードリンクの数と書き込みの権限と基準をもう一度検査する。その間にノートが変わっていたら止める。
6. **名前を変えて置き換える。** 一時ファイルの名前をノートの名前に変えて置き換える。名前の変更は不可分なので、ノートはいつも古い版か新しい版のどちらかで、書きかけにはならない。そのあと、ファイルシステムが対応していればフォルダも fsync する。

ここから言えること:

- **シンボリックリンク**はリンクのまま残る。書くのはリンクの指す先のファイルで、リンクそのものは変わらない。
- **権限**は保つ。新しいファイルは古いファイルと同じモード(Unix では持ち主とグループも)になる。写せなければ保存は失敗する。保つのはこれだけで、新しいファイルで置き換えるので、拡張属性・ACL・作成日時は新しいファイルのものになる(Obsidian に出る作成日時が変わりうる)。
- **書き込みの権限の無いノート**(モード `0444` など)は読むだけにする。名前の変更による置き換えに要るのはフォルダの書き込みの権限だけなので、mdgrid はファイルそのものを確かめる。利用者がそのファイルに書けなければ(書き込みに開けるかで確かめ、書かずに閉じる。そのため `root` は書ける。Linux では、ファイルの監視(inotify の `IN_CLOSE_WRITE` など)を見る外の道具がこれに反応しうる)、そのノートのセルはどれも読むだけになり、選ぶと理由「書き込めない権限」が出る。複数の行に一度に値を設定すると、そのノートは飛ばして数に入る。変更をためたあとに権限が無くなったら、保存はそのノートで書かずに止まり(中身もモードも変わらない)、同じ理由を出して、ためた変更は残す。ほかのノートは保存する。フォルダ自体に書き込めなければ一時ファイルを作れないので、保存は失敗し、ノートは変わらない。
- **新しい基準**は、名前を変える前に一時ファイルと検査した内容から作る。そのため、名前の変更から次に読むまでの間にほかの人が変えても、外の変更として見つかる。

書くおそれなしにノートを見るだけなら、mdgrid を `--readonly` で起動する。
