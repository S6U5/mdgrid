## ノートが表になる

フォルダを開くと、その中(下のフォルダも含む)の Markdown のノートが1つずつ**行**になります。どれかのノートが使っているフロントマターのキーが**列**になります。左にはノートのファイル名が出ます。ファイル名が行の鍵なので、ID の列を管理する必要はありません。

```
タスク/                          ノート          status   due         tags
├── ログインを直す.md   ──►      ログインを直す  doing    2026-10-05  [bug, web]
├── v0.2 を出す.md               v0.2 を出す     todo     2026-10-10  [release]
└── 説明書を書く.md              説明書を書く    done     2026-10-01  [docs]
```

mdgrid は列の値を見て、その列の型(文字・数・日付・チェック・リスト)を決めます。型によって、セルの直し方(日付はカレンダー、くり返す文字は候補の一覧、リストはチェック)と見せ方が変わります。列の型に合わない値は、`!` を付けてそのまま見せ、勝手には変えません。

キーが無いノートのセルは空欄、空の文字列は `""`、null は `∅` と見せるので、3つはいつも見分けられます。

## ビュー: 同じノートの見せ方

**ビュー**は表の見せ方です。どの列をどの順に出すか、どの行を出すか(絞り込み)、どう並べてどうまとめるか。ヘッダーの下のタブが、開いた表のビューです。

- **既定の表**: フォルダを開けば必ずあります。全部のノートと全部のキー。
- **`.base` のビュー**: Obsidian Bases の `.base` を開くと、その table ビューがタブになります。mdgrid は読むだけで、`.base` は書き換えません。
- **mdgrid のビュー**: **ビューの設定**(`o`)で列・絞り込み・並べ替え・まとまり・見せ方を決め、**名前を付けて保存**するとタブが増えます。保存したビューは設定のフォルダの `views.toml` に入り、ノートの横には書きません。

保存したビューのほかに、mdgrid は表ごとに、最後の見た目(列の幅・隠した列・選んでいたビュー)を黙って覚えていて、次に同じフォルダや `.base` を開くと戻します。

## 保存するまで何も書かない

直した値は、まず**ためた変更**になります。セルに `*` が付き、下の帯に未保存の数が出ます。`Ctrl+S` で、書く前にファイルごとの差分を見せ、`Enter` で書きます。書き換えるのは直した値だけ(新しいキーなら1行足す)で、ファイルのほかの部分(ほかのキー・キーの順・コメント・改行コード・本文)は1バイトも変えません。細かい決まりは[書き戻しの安全](../../safety.ja.md)にあります。

## 登録した表: 行き来するためのしおり

よく使う表は、名前と分類を付けて**登録**できます(パレット `:` の **この表を登録**)。引数なしの `mdgrid` で一覧が出て、**登録した表を開く**で行き来できます。登録は `places.toml` のしおりで、ノートは変えません。

表にすぐ行くもう1つの方法は、シェルの alias です: `alias tasks='mdgrid ~/notes/タスク'` で、`tasks` が自分のコマンドになります。

## リンクでフォルダが「つながった表」になる

フロントマターの値で、ほかのノートを指せます:

```yaml
project: "[[mdgrid]]"                 # ウィキリンク: mdgrid という名前のノート
assignee: "[Aさん](../メンバー/Aさん.md)"  # Markdown のリンク
related: [../プロジェクト/Webサイト]  # ただのパスでもよい
```

mdgrid はリンクを行き先の名前で見せ、セルを直すときは行き先を名前から選べ、行き先を開け(`:open_link`、セルで `x`)、今のノートを指しているノートを並べられます(`:linked_rows`)。行き先のノートが無いリンクには、前に `?` が付きます。

ファイル名が鍵なので、ノートのフォルダは表のように、リンクは外部キーのように働きます。リンクのリストは、多対多の中間の表の代わりになります。

```
 タスク ──project──► プロジェクト ──lead──► メンバー
   └────────assignee──────────────────────────┘
```

## ワークスペース: どの表が一緒か

リンクを名前で引くには、どの表から探すかを決めなければなりません。それを決めるのが**ワークスペース**です。1つの仕事のタスク・プロジェクト・メンバーのように、一緒に使う表の集まりに名前を付けたものです。リンク・つながった行・関係マップ・右上のタブは、今のワークスペースの表だけを使うので、仕事の保管庫と読書のノートが混ざりません。

開いた表のワークスペースは、次の順で決まります:

1. コマンドの `-w <名前>`。
2. フォルダかその上にある印 `.mdgrid/workspace.toml`。共有するリポで便利です(ワークスペースがノートと一緒に配られる)。
3. 設定のフォルダの `workspaces.toml` のうち、その表を含むもの。パレットか `--add-to`・`--remove-from`・`--workspaces` で管理します。
4. 自動で見つける: いちばん近い Obsidian の保管庫(`.obsidian/` のあるフォルダ)。`[workspace] detect` で git のリポも。直下のノートのあるフォルダが表になります。
5. どれでもなければ、登録した表。

使っているときは、ヘッダーに `· ワークスペース <名前>` が出ます。[ワークスペースで表をまとめる](tasks.md#ワークスペースで表をまとめる)も見てください。

## 関係マップ

`R`(か右上のタブの **関係**)で、ワークスペースを図で見られます。表ごとの箱(行の数と列)と、リンクの列から行き先の表への矢印です。矢印には `N:1`(リンク1つ)か `N:N`(リンクのリスト)が付きます。矢印のキーかマウスで表やつながりを選ぶと、詳細とつながった行が変わります。`Enter`(か2回目のクリック)でその表を開き、もう一度 `R` で表に戻ります。

## mdgrid が何をどこに置くか

| 何 | どこ |
|---|---|
| ノート | 保存した値のほかは変わらない |
| 設定 | `~/.config/mdgrid/config.toml`(`--print-config` で全項目と既定値) |
| 保存した mdgrid のビュー | `~/.config/mdgrid/views.toml` |
| 登録した表 | `~/.config/mdgrid/places.toml` |
| ワークスペース | `~/.config/mdgrid/workspaces.toml`、またはフォルダの `.mdgrid/workspace.toml` |
| 表ごとの最後の見た目(幅・隠した列・ビュー) | `~/.local/state/mdgrid/` |

`XDG_CONFIG_HOME` と `XDG_STATE_HOME` で2つのフォルダを変えられます。どれも手で直せる TOML で、`places.toml` と `workspaces.toml` は mdgrid が書き換えても手書きのコメントを残します。
