# 決める(人が明示的に呼んだとき。「決めよう」「承認待ちを見せて」)

呼ばれたときだけ読む。パス・守られる要件・人と AI・書き方は [SKILL.md](../SKILL.md) に従う(modes/ からは道具の根は `../../../`)。

ふだんは人に1件ずつ聞かない。事前に1件ずつ承認を求めるのは、守られる要件を消す・弱めるものと、承認と照合の仕組みを変えるものだけで、その承認の言葉には対象の要件 ID を含めてもらう(OM-13。承認の文(ID と旧・新)を `specs/_bundles/` に保存し、指紋(SHA-256 の先頭16文字)を添えて見せる。人の言葉は、ID と承認を示す語の両方か、独立した語としての指紋を含む)。それ以外の人の承認が要る提案は、`status: proposed` のままためて作業を続ける(仮置きは OM-3 のとおり示す)。

1. `_proposals/` の承認待ちと、前回の束の後の AI 自己採択を集める。
2. 束を最大7件で作る。危ないもの(強さを下げる・消す・範囲を広げる)から順に並べ、各行は ID と旧・新の文言をそのまま示す(要約は添えるだけ)。事後確認(AI 自己採択)は末尾に並べる。
3. 束の本文を `specs/_bundles/YYYY-MM-DD-bundle-N.md` に保存し(フロントマターは `type: Bundle`、`id`(`python3 scripts/ulid.py`)、`created`。束には載せた記録のパスを並べる)、本文のハッシュ(`shasum -a 256`)を書く。人に見せる。
4. 人の答え(例「全部いい」「3 は却下」)を受け、提案ごとに承認の記録へ `日付 人の承認(要約: …)(束 N、ハッシュ …)` を書いて(人の言葉は原文で引用しない。OM-2) `--approve` で照合し、採択・却下する。採択の前に、提案の中身が束のハッシュを取った時と同じか確かめる(違えば承認は無効。OM-16)。事後確認で却下されたものは、戻す提案を出す。
5. OM-13 の事前承認は、束とは別に、対象の要件 ID と旧・新の文言を並べた承認の文を `specs/_bundles/YYYY-MM-DD-approval-N.md` に置き(束と同じく本文を ````markdown の囲みに入れ、フロントマターを付ける)、`python3 scripts/check.py <repo-root> --fingerprint <その文>` の16文字を添えて見せる。人がその16文字を独立した語として含む言葉か、対象の要件 ID と承認を示す語(承認・OK・はい など)を含む言葉で答えたら、承認の記録に `日付 人の承認(要約: …)(承認の文 <パス>、指紋 <16文字>)` を書いて `--approve --find <16文字か ID>` で照合する。「OK」だけの返事は承認に数えない。前の版で8文字の指紋により照合した承認(2026-10-12 より前の人の発言)は、そのまま有効。会話の記録が手元に無く照合を飛ばすと `check.py` W23。文が承認のあとで変わると指紋が合わず、`check.py` E29 になる。
