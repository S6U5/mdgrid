# 検査

呼ばれたときだけ読む。パス・守られる要件・人と AI・書き方は [SKILL.md](../SKILL.md) に従う(modes/ からは道具の根は `../../../`)。

1. `check.py` の出力をそのまま報告に貼る。
2. 書込権限のないサブエージェントを1体起動し、`specs/`、AGENTS.md、手順(スキル等)、直近の `git log` を渡す。結論だけの文書は渡さない。見つけさせるもの: 仕様どうし・仕様と AGENTS.md / スキルの矛盾、実在しないパスや手順を指す要件、`decided-by` の付け違い(人の言葉が無いのに人、など)、同じ規則の二重記述、確かめようのない要件、提案を経ずに spec.md が変わった形跡(`git log` で spec.md を変えたのに `specs: 字句 / 新設 / 移行 / 採択` のどれでもないコミット)。出力は1件1行(種別 / 場所 / 内容 / 重さ / 処置案 / 安定 ID。安定 ID は種別と場所から決め、変わっていなければ再実行で同じになる)。処置案は 消す > まとめる > 片方に決める > 足す の順で選ぶ。
3. 指摘を読み、誤字・リンク切れは直し、要件の意味に関わるものは起票し、誤りは理由を書いて棄却する。黙って直さない。
4. 報告: 形式の検査の出力、指摘の表、仕分け、4つの数(前回と同じ安定 ID で再出した指摘、`decided-by` の付け違い、取り込みで未確認の要件(生成区画にある)、AI 自己採択)と ⚠ の残数。各検査項目に verified / not verified(理由)/ not applicable(理由)を付け、黙って飛ばさない。
