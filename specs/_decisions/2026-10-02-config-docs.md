# 設定の全項目の文書と、既定の設定の書き出し(config-docs)

## きっかけ

会話 2026-10-02 で、人が、OSS なので設定ファイルの管理や誰かに使ってもらうための工夫が要ると指摘した。案(全項目の文書・既定の設定の書き出し・文書と実装のずれを落とす試験)を示し、人が始める作業に選び、文書は英語を主に日本語も置くと決めた。人の依頼と選択を AI が要件の文に起こした。

## 差分

cli の spec.md の「要件: 版1 — 起動と設定」に足す。

- 追加: CLI-11「`mdgrid --print-config` は、設定の全項目を既定値と説明のコメント付きの TOML として標準出力に出し、終了コード 0 で終わるべき。出したものは、そのまま設定ファイルとして警告なしで読めて、既定と同じ振る舞いになるべき(dotfiles に貼る出発点にするため)。」(確かめ方: `mdgrid --print-config > c.toml` → `mdgrid --config c.toml` で警告なしに起動し、既定と同じ。出力に全項目の名前とコメントがある(`test_CLI_11`))
- 追加: CLI-12「設定の全項目を、名前・型・既定値・説明で並べた文書を、英語(docs/config.md)と日本語(docs/config.ja.md)で置くべきで、文書の項目と、実装が読む項目と、`--print-config` の項目が食い違えば試験で落ちるべき(文書が古くなるのを防ぐため)。」(確かめ方: 実装に項目を足して文書に足さない → 試験が落ちる(`test_CLI_12`))

## 却下した案

| 案 | 理由 |
|---|---|
| 見本の設定ファイル(examples/showcase)だけ | 全項目が無く、項目を足しても古くなるのに気づけない |
| 設定の JSON Schema を先に作る | 項目が少ないうちは文書と書き出しで足りる。後で足せる |

## 承認の記録
