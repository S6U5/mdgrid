# ビューに tab_break を書くと、そのタブの前でタブの行を改める(tab-break)

## きっかけ

人が、台帳の絞り込みのタブが今は1行に並んでいるのを2行にしたい、期限のタブと状態のタブで行を分けたい、と言った(中継 2026-10-19。プロジェクトのチャットからまとめ役が写した)。

本物の台帳(タブ11個)は `tab_wrap = true` で、検索の欄の行の下にタブが幅いっぱいに並ぶ。どこで折り返すかは幅で決まり、期限で選ぶタブ(期限切れ・今日まで…)と状態で選ぶタブ(todo・doing…)が同じ行に混ざる。まとまりの切れ目を書く場所が無い。書き方(ビューのキー `tab_break`)は AI が足した細部。

## 差分

- 追加: NV-32「`.base` のビュー(ワークスペースの印の `[table.base]` のビューを含む。WS-9)に `tab_break = true`(YAML では `tab_break: true`)を書くと、タブの行をそのタブの前で改めるべき(期限で選ぶタブと状態で選ぶタブのように、まとまりごとに行を分けて見られるように。どこで折り返すかを幅に任せると、まとまりが行の途中で混ざるため)。タブの行に出すタブ(NV-26 の見せる順で、隠したタブを除いたもの)のうち先頭でないものに切れ目があるときは、NV-23 の今のでないタブを省く決まりと NV-31 の入りきるとき・`display.tab_wrap = false` のときは1行のままの決まりより先に、端末の幅と `tab_wrap` に依らず、タブを全部真ん中の行から外して、NV-31 と同じ置き場(真ん中の行の下。`tab_wrap_gap` の空き行(タブの行の前に1つだけで、行の間には入れない)・`buttons = "box"` の囲みの下・下の余白と地の色・クリックで選べること・検索の欄を出さないときと低い端末の扱いも NV-31 と同じ)に、切れ目のタブの前で行を改めて左から並べるべき。1つの行が幅に入らないときは、その行の中で折り返し、タブを省かないべき(`tab_break` は `tab_wrap` を含む)。隠したタブの `tab_break` は、次に見せるタブに移すべき(まとまりの先頭を隠しても、まとまりが混ざらないように)。先頭のタブの `tab_break` と、タブを出さないとき(SR-34)は何もしないべき(そのときは NV-23・NV-31 のまま)。`tab_break` はビューと一緒に動き(NV-26 で並べ替えると切れ目もそのタブと動く)、行の置き方だけを変え、`[` `]` の順(NV-26)は変えないべき。mdgrid のビュー(views.toml)には今は書けない。」(確かめ方: 4つのタブ A・B・C・D の表で C に `tab_break = true`、幅 200・`tab_wrap = false` → 検索の欄の行にタブが無く、すぐ下の行に A と B、その下の行に C と D があり、表はタブの行の2行ぶん下がる。下の行の D をクリック → D のビュー。`tab_wrap_gap = true` → 検索の欄の行とタブの行の間に空き行が1つで、2つのタブの行の間には空き行が無い。幅を狭めて A・B の行が入らない → その行の中で折り返し、4つのタブの名前が全部画面にある。A にだけ `tab_break` → 今のまま、真ん中の行にタブ(NV-23)。C を隠す → 下の1行目に A と B、2行目に D。`tabs = "never"` → タブの行は無い(`test_nv_32_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 期限のタブと状態のタブが同じ行に混ざる(本物の台帳で確かめた) |
| 台帳のビューの並びだけを入れ替えて、幅で折り返す位置を合わせる | 折り返す位置は端末の幅と今のタブの括弧で変わり、まとまりの切れ目と合わせられない |
| 行の名前(`tab_row = "期限"`)で同じ名前のタブを1つの行に集める | 見せる順(NV-26)と行の中の順がずれ、`[` `]` の順と画面の順が食い違う。切れ目だけを書けば足りる |
| `display` の項目に、行ごとのビューの名前の配列を書く | ビューの名前を二重に持ち、名前を変えるとずれる。表示の項目(SR-21)の数も増える |
| `tab_break` があっても、入りきるときは1行のままにする | 人は行を分けて見たいと言っており、広い端末でもまとまりが混ざる |

## 錨との照合

新しい文脈の検証役(書込なし)が、原則と人の軌跡(タブの置き場の人の決定 2026-10-15-tab-wrap-below と 2026-10-11-view-bar など)に照らして確かめた。

- 原則: `principles.md` は無く、人の軌跡だけで照らした。
- 向き: 2026-10-15-tab-wrap(状態のタブを何行かに置きたい)、2026-10-15-tab-wrap-below(人の決定。タブは検索の欄の行の下に要る行の数だけ並べる)、2026-10-12-search-box(行を増やしてよい)に続き、タブを省かず検索の欄の行の下にまとまりで見せる向きを強める。置き場・空き行・囲みを NV-31 と揃えたので tab-wrap-below の形と合う。
- 食い違い: 人の決定とは食い違わない。NV-31 の「入りきるときは1行のまま」は tab-wrap-below が AI の足した細部と書いたもので、`tab_break` を書いたときだけ効く形なら既定の見た目は変わらない。2026-10-15-tab-wrap が「ビューごとに置く行を書かせる」を別の提案に回しており、これがその提案に当たる。2026-10-11-view-bar(人の決定)の「1行の帯」は tab-wrap-below ですでに緩められている。
- 指摘と直し: NV-23・NV-31 との文の食い違い → NV-32 に「より先に効く」と書いた。まとまりの先頭を隠すと混ざる → 隠したタブの切れ目を次に見せるタブに移すことにした。並べ替えると切れ目が動くこと、mdgrid のビューは対象外、検索の欄を出さないとき・低い端末は NV-31 と同じ、空き行は1つだけ、`tab_break` は `tab_wrap` を含むことを文に書いた。

判定: 向きに沿う(指摘を直したうえで)
