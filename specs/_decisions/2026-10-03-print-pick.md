# --print と --pick を版1に入れる(print-pick)

## きっかけ

docs/todo.md の F-5(公開の前にあるとよい機能)。表の結果を画面を出さずに外へ渡す(`--print`)と、画面で選んだ行をパイプへ渡す(`--pick`)を、次の段から版1に上げ、細部を AI が決める(守られる要件に触らない。CLI-5・OUT-3 は AI の決定 v1-full-spec・rename-mdgrid のもの)。引数の読み取りは clap(D-5)の上に足す。

## 差分

- 変更: CLI-5 旧「画面を出さずに(`--print`)、`.base` の結果を CSV・JSON・Markdown の表として標準出力に出してよい。」→ 新「`mdgrid [<.base \| フォルダ> …] --print [--format csv\|json\|md] [--view <名前>]` は、画面を出さずに、開いたビュー(`.base` のビューか mdgrid のビュー。BV-17)の表を標準出力に出して終了コード 0 で終わるべき。行はビューの絞り込みと並べ替えのあと(グループ分けは並びだけに効かせ、見出しの行は出さない)、列はビューの列の並びとし、画面の見た目の状態(SR-12)と画面で掛けた絞り込みは使わないべき。既定の形は csv(RFC 4180、見出しの行つき、改行は LF)、json は列の名前を鍵にしたオブジェクトの配列(数・真偽・null・リストは JSON の型、日付と日時は文字列)、md は見出しと区切りの行のある表(セルの中の縦棒はバックスラッシュで逃がし、改行は空白)とするべき。評価できない列(BV-7)は csv と md で空、json で null にし、標準エラーに1行で知らせるべき。ノートを書き換えないべき(WB-15 と同じ)。起動できないとき・知らない形の名前は CLI-4 と同じく理由1行と終了コード 2 にするべき。」(確かめ方: `--print --format csv` → 見出しの行と行ごとの CSV が出て終わる。`--format json` → `[{"title": "会議", "priority": 2, "tags": ["a"]}]` の形。`--format md` → 見出しの行と区切りの行のある表。`--format xml` → 理由1行と終了コード 2。標準出力がパイプでも動く(`test_CLI_5`))。cli の spec.md の「要件: 次の段」から「要件: 版1 — 起動と設定」へ移す。
- 変更: OUT-3 旧「パイプで使えるように、印を付けた行のノートのパスか、指定の列の値を、標準出力に出して終わってよい。」→ 新「`mdgrid [<.base \| フォルダ> …] --pick path\|<列の名前>` は、画面を端末(`/dev/tty`)に出して読むだけ(WB-15 と同じ)で開き、Enter で、印を付けた行(印が無ければ選んでいる行)ごとに、`path` ならノートのパス(起動の引数のフォルダにノートの相対のパスをつないだもの)、列の名前ならその列のセルの表示と同じ文字(改行は空白)を、1行ずつ標準出力に出して終了コード 0 で終わるべき。`q` と Esc で取りやめたら何も出さずに終了コード 1 で終わるべき。標準出力がパイプでも動くべき(SR-10)。表に無い列の名前は CLI-4 と同じく理由1行と終了コード 2 にするべき。」(確かめ方: `mdgrid notes --pick path` で2行に印を付けて Enter → `notes/a.md` と `notes/b.md` の2行が出て終わる。印なしで Enter → 選んでいる行の1行。`--pick status` → 値が1行ずつ。`q` → 何も出ず終了コード 1。`--pick 無い列` → 理由1行と終了コード 2(`test_OUT_3`))。output の spec.md の「要件: 次の段」から「要件: 版1 — コピー」の次に新しい節「要件: 版1 — 標準出力」を作って移す。
- 変更: SR-10 旧「`NO_COLOR` があるときは色を出すべきでなく、`TERM=dumb` では色と絵文字を出すべきでない。標準の入出力が端末でないとき(パイプ)は、画面を出さずに理由を1行出して終わるべき。ただし、画面を出さない起動(次の段の `--print`、CLI-5)と、画面は端末(`/dev/tty`)に出して結果だけを標準出力に出す起動(次の段の `--pick`、OUT-3)は、標準出力がパイプでも動くべき。」→ 新「`NO_COLOR` があるときは色を出すべきでなく、`TERM=dumb` では色と絵文字を出すべきでない。標準の入出力が端末でないとき(パイプ)は、画面を出さずに理由を1行出して終わるべき。ただし、画面を出さない起動(`--print`、CLI-5)と、画面は端末(`/dev/tty`)に出して結果だけを標準出力に出す起動(`--pick`、OUT-3)は、標準出力がパイプでも動くべき。」

## 却下した案

| 案 | 理由 |
|---|---|
| `--print` に画面の見た目の状態(隠した列など)を当てる | 見た目の状態は利用者の画面の都合で、同じ引数で違う結果になる。ビューの定義だけにすると再現できる |
| `--pick` のパスを絶対パスにする | 引数で渡した書き方(相対か絶対か)を保つ方が、`xargs` などで今のフォルダから使いやすい |
| `--pick` を書ける画面にする | 選ぶための起動で、書き込みは要らない。読むだけにすると誤って保存しない |
