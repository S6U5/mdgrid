# 最初の版の仕様を、表の TUI の調査に合わせて書き切る(v1-full-spec)

## きっかけ

依頼の要約(会話 2026-09-30): CSV や Excel を表示する TUI と Obsidian Bases の表の、細かい機能・オプション・操作性を調べたうえで、仕様をまず全部書き切ってから実装する。変更の記録は specs/_changes/2026-09-30-v1-full-spec.md。調査の結果は research-lab の設計ログ(2026-09-30 の節: VisiData・csvlens・tabiew・xleak・sc-im・lazysql・harlequin・Obsidian Bases の table ビュー・ノート系の TUI・反証)。

人が選んだこと(選択肢への答え。会話の記録に打ち込んだ発言としては残らない形式の答えなので、承認の照合はしていない。次の決めるモードの束で見直す): 直した値はためてから保存する(WB-9)、要件を 版1・次の段・採らない に分ける(SC-13)、キーは vim 風と矢印の両方と Bases の主なキーで、すべて割り当て直せる(SR-13)。そのほかの要件は、調査から AI が起こした。

照合の指摘の残り(2026-09-30 の書込なしの検証役の17件)も入れた: WB-1 と WB-3 の食い違い(キーを足す1行を許す)、自分で書いたあとの基準の更新と置き換える直前の再検査(WB-12)、fsync(WB-8)、空の値は null でキーを残す(CE-9)、読めないノートの種類の追加(WB-5)、クオートの規則(WB-7)、複数の根の型の食い違い(BV-12)、同じノートの二重(BV-11)、`$EDITOR` をシェルを通さずに起動(SR-8)、保存が止まっても変更を残す(WB-14)、互換の言い方を「table ビューの一部と互換」に弱める、BV-4 の出典、読み直しの間隔の既定(BV-9)、`.base` なしのときの見た目の状態(SR-12)、字句の誤り(WB-5・SR-10)。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(38要件のまま) | 移動・検索・選択・コピー・起動と設定・保存の流れ・見つけやすさの仕様が無く、調査で見つけた不満(見つからない・崩れる)と事故(書き戻しの破壊・同期の衝突)への備えも無い |
| 全機能を版1にする | 機能を詰め込んだ表の TUI は学習コストと発見しにくさで不満を集めている(VisiData の作者も認める)。人も優先度で分ける案を選んだ |
| 1セルごとにすぐ書く(Obsidian Bases 型) | 書き込む前に差分を見られない。人はためてから保存を選んだ |
| VisiData のシートのスタックを採る | フロントマターの表には `.base` のビューの切り替えと詳細の表示で足りる。スタックは学習コストが高い |
