# 見せ方と編集の食い違いと抜けを直す(edit-view-gaps)

## きっかけ

仕様の点検(書込なしの点検役、2026-10-01)の指摘: (1) SR-10 は標準の入出力がパイプなら画面を出さずに終わるとするが、次の段の `--pick`(OUT-3)は結果をパイプへ出し、`--print`(CLI-5)は画面を出さない起動で、どちらも SR-10 で終わってしまう。(2) BV-7 の評価できない列の「値を空にする」は、CV-1 の「キーが無い = 空欄」と見分けられない。(3) CE-5 の日付の「空(消す)」はキーを消すとも読め、CE-9(キーは残して null)と食い違う。(4) CE-3 の候補を集める「渡したフォルダ」が、保管庫の根(BV-2)かビューの行かが決まらない。(5) CE-10 の飛ばす行が WB-5・CE-8 だけで、フロントマターの無いノート(WB-3)やリストの値(CE-6)・改行を含む値(CE-12)が抜けている。(6) 書き戻しの実装(タスク 2・3)は、タグつきの値・複数行の値・複数行のフローを読むだけにしているが、CE-8 に無い(変更の記録 v1-full-spec の実装の気づき)。

## 差分

- 変更: SR-10 旧「`NO_COLOR` があるときは色を出すべきでなく、`TERM=dumb` では色と絵文字を出すべきでない。標準の入出力が端末でないとき(パイプ)は、画面を出さずに理由を1行出して終わるべき。」→ 新「`NO_COLOR` があるときは色を出すべきでなく、`TERM=dumb` では色と絵文字を出すべきでない。標準の入出力が端末でないとき(パイプ)は、画面を出さずに理由を1行出して終わるべき。ただし、画面を出さない起動(次の段の `--print`、CLI-5)と、画面は端末(`/dev/tty`)に出して結果だけを標準出力に出す起動(次の段の `--pick`、OUT-3)は、標準出力がパイプでも動くべき。」(確かめ方: `NO_COLOR=1` で起動 → エスケープの色指定が無い。標準出力をパイプにして起動 → 画面を出さず理由1行で終わる(`test_SR_10`))
- 変更: BV-7 旧「評価できない式・関数・ビューの型に出会ったら、推測で行を作るべきでない。絞り込みが評価できないビューは開かずに理由を出し、評価できない列は値を空にして読むだけにし、どの式が未対応かを画面に出すべき。」→ 新「評価できない式・関数・ビューの型に出会ったら、推測で行を作るべきでない。絞り込みが評価できないビューは開かずに理由を出し、評価できない列は、値の代わりに未対応の印(`?`)を出して読むだけにし(空・null・キーが無い の見せ方(CV-1)と見分けられるようにする)、どの式が未対応かを画面に出すべき。」(確かめ方: 未実装の関数を使った filters → そのビューは開かず、関数名つきで未対応と表示。評価できない式の列 → 全行に `?` が出て、キーが無いときの空欄と違う(`test_BV_7`))
- 変更: CE-3 旧「テキストの列で、渡したフォルダの中の同じキーに現れる異なる値が一定数以下(既定 20)なら、その値のリストから選べるようにし、自由入力にも切り替えられるようにするべき。リストには今の値に印を付け、空の値は「なし」として並べるべき。」→ 新「テキストの列で、読み込んだノート全部(BV-2 の範囲。ビューの絞り込みの前)の同じキーに現れる異なる値が一定数以下(既定 20)なら、その値のリストから選べるようにし、自由入力にも切り替えられるようにするべき。リストには今の値に印を付け、空の値は「なし」として並べるべき。」(確かめ方: `status` の値が todo・doing・done だけ → 3つと「なし」のリストが出て、今の値に印。ビューの絞り込みで見えていないノートの値も候補に入る(`test_CE_3`))
- 変更: CE-5 旧「日付の列は `YYYY-MM-DD` と、今日からの日数(`+3`)と、空(消す)を受け付け、実在しない日付は受け付けるべきでない。」→ 新「日付の列は `YYYY-MM-DD` と、今日からの日数(`+3`)と、空(値を消す。キーは残して null と書く。CE-9)を受け付け、実在しない日付は受け付けるべきでない。」(確かめ方: `2026-02-30` → 閉じずに不正を表示。空で確定 → `due:` の行が残る(`test_CE_5`))
- 変更: CE-8 旧「ファイルの属性(`file.*`)・式の列(`formula.*`)・ネストした map・ブロックスカラー・アンカーや別名を使った値のセルは、編集できないようにし、なぜ読むだけかを表示するべき。」→ 新「ファイルの属性(`file.*`)・式の列(`formula.*`)・ネストした map・ブロックスカラー・アンカーや別名を使った値・タグつきの値(`!!str` など)・複数行にまたがる値(素のスカラー・引用符つきの値・フロー形式)のセルは、編集できないようにし、なぜ読むだけかを表示するべき。」(確かめ方: `file.mtime` の列で Enter → 読むだけと理由を表示。`title: !!str 12` と2行にまたがる `[a,\n b]` のセル → どちらも読むだけと理由(`test_CE_8`))
- 変更: CE-10 旧「選んだ複数の行の同じ列に、同じ値を、ためる変更としてまとめて入れられるべき。選んだ行のうち読むだけの行(WB-5・CE-8)は飛ばし、飛ばした数を知らせるべき。」→ 新「選んだ複数の行の同じ列に、同じ値を、ためる変更としてまとめて入れられるべき。選んだ行のうち、その列のセルを直せない行(読むだけのノート(WB-3 のフロントマターの無いノート・WB-5)と、読むだけのセル(CE-6・CE-8・CE-12))は飛ばし、飛ばした数と理由を知らせるべき。」(確かめ方: 3行を選び status に done → 3つのためる変更、保存前の差分に3ファイル。3行のうち1行がフロントマターの無いノート → 2つのためる変更と「1行を飛ばした(フロントマターが無い)」(`test_CE_10`))

要件の表の外の変更: 変更の記録 v1-full-spec の実装の気づきで「仕様で決める(未決)」とした2件(書き込みの権限の無いノート、クオートの無い日付の書き方)が、write-back の未決の問いでは「なし」になっていた。write-back の未決の問いに移す(日付のクオートはラボをまたぐ論点で人の判断待ちのため、ここでは要件を変えない)。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 次の段を足すときに SR-10 と必ずぶつかる。評価できない列とキーの無いセルが同じ見た目で、書き戻しの前に値を確かめられない(cell-view の芯) |
| CE-3 の候補をビューの行だけから集める | 絞り込みで今見えている値しか選べず、ビューによって候補が変わる |
| 権限の無いノートを AI の判断で読むだけにする | 変更の記録で「仕様で決める」とした論点で、書けないことを利用者が望むかを人に確かめたい。未決の問いに置き、AI 案を添えた |
