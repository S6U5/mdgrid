# 日本語入力の読点と中黒、キーの無いセルの Backspace、未対応の印と本当の値の見分け(ime-keys-marks)

## きっかけ

照合役(AI)の指摘(会話 2026-10-01): (1) SR-18 の `,`(同じ値の行だけに絞る)は、日本語入力が有効だと `、`(U+3001)で届き、全角の英数字と記号を半角に直す SR-17 の対象(全角の形 U+FF0C)に入らない。`/`(検索)の `・` も同じ。(2) SR-18 の Backspace は値を空(null)にするが、キーの無いセルで押したときの振る舞いが無く、キーを足して null にすると、キーが無い(CV-1)と null の区別を黙って変える。(3) BV-7 の未対応の印 `?` は、値が `?` の本当の値と同じ見た目になりうる。(4) Esc が選択の有無で動作を変える点が、key-defaults の却下の理由(同じモードで状況によって動作が変わる)と揃っていない。(5) Ctrl+A は GNU screen の接頭キーと重なる。

## 差分

- 変更: SR-17 旧「表のモードで、日本語入力(IME)が有効なまま打った全角の英数字と記号が届いたら、半角のキーとして扱うべき。入力ボックスでは、端末のカーソルを入力の位置に置き、変換の窓が入力の位置に出るようにするべき。」→ 新「表のモードで、日本語入力(IME)が有効なまま打った全角の英数字と記号が届いたら、半角のキーとして扱うべきで、日本語の読点と中黒(`、`・`・`)は、同じキーの位置の `,`・`/` として扱うべき。入力ボックスでは、端末のカーソルを入力の位置に置き、変換の窓が入力の位置に出るようにするべき。」(確かめ方: 旧「表で全角の ｊ を送る → j と同じ動き(`test_SR_17`)」→ 新「表で全角の ｊ を送る → j と同じ動き。表で `、` を送る → `,`(SR-18 の同じ値の行だけに絞る)と同じ動き。`・` → `/`(検索)と同じ動き(`test_SR_17`)」)
- 変更: SR-18 旧「表のモードで、ほかの要件で既定のキーを決めていない動作の既定は、Tab / Shift+Tab = 右 / 左のセルへ移る、Backspace と Delete = 選んだセルの値を空にする(ためる変更。CE-9)、`q` = 終わる(WB-11)、Ctrl+A = 全部の行を選ぶ、Esc = 選択を解く(選択が無ければ簡易の絞り込みを解く。NV-5・NV-2)、`*` = 選んだセルと同じ値の行を強調する、`,` = 同じ値の行だけに絞る(NV-8)、Ctrl+G = 読み込みの中止(BV-16)とするべき。」→ 新「表のモードで、ほかの要件で既定のキーを決めていない動作の既定は、Tab / Shift+Tab = 右 / 左のセルへ移る、Backspace と Delete = 選んだセルの値を空にする(ためる変更。CE-9。キーの無いセルでは何もせず、キーを足さない)、`q` = 終わる(WB-11)、Ctrl+A = 全部の行を選ぶ、Esc = 選択を解く(選択が無ければ簡易の絞り込みを解く。NV-5・NV-2)、`*` = 選んだセルと同じ値の行を強調する、`,` = 同じ値の行だけに絞る(NV-8)、Ctrl+G = 読み込みの中止(BV-16)とするべき。」(確かめ方: 旧「表で Backspace → そのセルが null のためる変更になり「未保存 1」。読むだけのセルでは理由を表示して何もしない。読み込み中に Ctrl+C → コピーになり、読み込みは止まらない(`test_SR_18`)」→ 新「表で Backspace → そのセルが null のためる変更になり「未保存 1」。読むだけのセルでは理由を表示して何もしない。キーの無いセルで Backspace → 何も変わらず「未保存 0」。読み込み中に Ctrl+C → コピーになり、読み込みは止まらない(`test_SR_18`)」)
- 変更: BV-7 旧「評価できない式・関数・ビューの型に出会ったら、推測で行を作るべきでない。絞り込みが評価できないビューは開かずに理由を出し、評価できない列は、値の代わりに未対応の印(`?`)を出して読むだけにし(空・null・キーが無い の見せ方(CV-1)と見分けられるようにする)、どの式が未対応かを画面に出すべき。」→ 新「評価できない式・関数・ビューの型に出会ったら、推測で行を作るべきでない。絞り込みが評価できないビューは開かずに理由を出し、評価できない列は、値の代わりに未対応の印(`?`)を出して読むだけにし(空・null・キーが無い の見せ方(CV-1)とも、本当の値の `?` とも見分けられるように、印は薄い表示にし、そのセルを選んだら下の帯に未対応と出す。色だけに頼らない(SR-15))、どの式が未対応かを画面に出すべき。」(確かめ方: 旧「未実装の関数を使った filters → そのビューは開かず、関数名つきで未対応と表示。評価できない式の列 → 全行に `?` が出て、キーが無いときの空欄と違う(`test_BV_7`)」→ 新「未実装の関数を使った filters → そのビューは開かず、関数名つきで未対応と表示。評価できない式の列 → 全行に薄い `?` が出て、キーが無いときの空欄と違う。値が `?` のテキストの列 → 普通の `?`。評価できない式のセルを選ぶ → 下の帯に未対応の式が出る(`TERM=dumb` で薄い表示が出なくても、選べば見分けられる)(`test_BV_7`)」)

要件の表の外の変更(screen の前提): (4) と (5) を注記する。Esc は変えない: key-defaults で却下したのは、読み込み中だけ Ctrl+C を中止にする案で、コピーのつもりの人の読み込みが止まり、やり直せないものを失う。Esc は、どちらの場合も「今かかっている一時的なもの」を解く1つの動作で、解いた選択や絞り込みは押し直しや打ち直しで戻せ、ファイルも読み込みも失わない。Ctrl+A は SR-13 のとおり割り当て直せ、screen の中では screen の側の `C-a a` でも届く。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 日本語入力のまま `,` と `/` が効かず、キーの無いセルの Backspace で表の見え方(空欄 → `∅`)が変わり、未対応の印と本当の値が同じ見た目になる |
| 未対応の印を、値に現れない記号の並び(`⟨?⟩` など)にする | どんな文字列も値になりうるので、見た目だけでは見分けを保証できない。選んだときの下の帯のほうが確か |
| Esc を選択を解くだけにし、簡易の絞り込みの解除に別のキーを足す | NV-2 は Esc で簡易の絞り込みを解くと決めており、別のキーを足すと NV-2 を変えることになる。一時的なものを順に解く動作は、失うものが無い |

## 承認の記録

AI 自己採択(守られる要件に触らない。SR-17・SR-18・BV-7 は AI の決定の要件で、強さは変えない。SR-13(人が選んだキーの流儀)の文は変えない。承認待ちの strict-write-safety の BV-7 の旧の引用は、この採択のあとで今の文言に合わせる。次の決めるモードの束の末尾で事後確認)
