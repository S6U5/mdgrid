# 表から新しいノートを作る(new-note)

## きっかけ

会話 2026-10-02 で、人が、右上でもどこでもよいのでファイルを足す機能が要ると依頼した。作る場所・最初の中身・操作を尋ね、人は次を選んだ: 作る場所は開いたフォルダで変えられる、ビューの絞り込みの値を前もって入れる、設定などで作るときに何を入力させるかのルールも選べるとよい、操作は右上の「+ 新規」とキー。人の依頼と選択を AI が要件の文に起こした。次の段の CE-14 を版1に上げる。

## 差分

cell-edit の spec.md の「要件: 版1 — 編集の入り方」に足し、「次の段」の CE-14 を消す(範囲外に「CE-14 は 2026-10-02 に CE-25・CE-26 に置き換えて版1に上げた」と残す)。

- 削除: CE-14 旧「表から新しいノートを作れてよい。そのときビューの絞り込みの条件にある値を前もって入れてよい。」(次の段。CE-25・CE-26 に置き換えて版1に上げる)

- 追加: CE-25「表から新しいノートを作れるべきで、ヘッダーの右の端の「+ 新規」のクリックと、キーの操作(SR-4 のキーの表で割り当て直せる)とコマンドのパレットから始められるべき。名前を打つ欄を出し、Enter で `<名前>.md` を作り、表のその行を選ぶべき。作る場所は開いたフォルダ(`.base` で開いたときはその `.base` のフォルダ)を既定とし、名前に `下のフォルダ/名前` と書けば下のフォルダに作り(無ければ作る)、設定で既定のフォルダを変えられるべき。開いたフォルダの外(`..` や絶対パス)と、既にある名前には作らず理由を出すべき。読むだけの起動(`--readonly`)では作らないべき。作るのは新しいファイルだけで、既にあるファイルは書き換えないべき(WB-2)。ビューの絞り込みの条件のうち値が1つに決まるもの(`status == "todo"`・タグを含む など)は、その値をフロントマターに入れて作り、作った行がそのビューに残るようにするべき。」(確かめ方: 「status が todo」のビューで「+ 新規」→「会議の準備」と打って Enter → `会議の準備.md` が `---\nstatus: todo\n---\n` で作られ、表にその行が選ばれて出る。`プロジェクト/新しい` → `プロジェクト/新しい.md`。`../外` → 作らず理由。同じ名前 → 作らず理由。`--readonly` → 作らない(`test_CE_25`))
- 追加: CE-26「新しいノートを作るときに入力させる項目と、前もって入れる値と、名前の雛形を、設定で決められるべきで、ビューごとにも決められてよい(mdgrid のビュー、BV-17)。入力させる項目は名前の欄のあとに1つずつ型に合った入力(CE-2)で聞き、空のまま進めればその項目は書かないべき。」(確かめ方: 設定に「priority を聞く・tags に `inbox` を入れる」と書く → 名前のあとに priority の入力が出て、作ったノートに `priority` と `tags: [inbox]`(縦の形)が入る。priority を空で進める → priority の行は無い(`test_CE_26`))

## 却下した案

| 案 | 理由 |
|---|---|
| 今の行と同じフォルダに作る | 人は開いたフォルダを既定にし、変えられる形を選んだ |
| 表の一番下の空の行から作る | 人は右上のボタンとキーを選んだ |
| テンプレートのファイルを写す | 人は選ばなかった(設定のルールで入力させる項目と前もって入れる値を決める形を選んだ)。後で足せる |
