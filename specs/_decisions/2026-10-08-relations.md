# ノートのリンクをリレーションとして扱う(relations)

## きっかけ

人が、表と表をつなぐリレーション(行き先の表・1対多と多対多・つながった行・関係マップ)をできるようにしたいと、デザイン案の画像(手元の inbox/ の2枚)を見せて頼んだ(会話 2026-10-08)。話し合いで次を決めた: 行を見分けるキー(PK)はノートのファイル名(パス)。値は Obsidian のリンクなどで行き先のノートを指す。`.base` 以外(フォルダを開いたとき)でも効き、パスはいくつかの書き方を受け付ける。表のつながりは登録した表(CLI-18)から自動で見つける。どのノートの集まりもデザイン案の表の形にそろうわけではない。最初は表の中のリレーションから作り、関係マップの画面は次の段。右上のタブで画面を切り替えられるとよく、画面の幅に合わせた段組み(レスポンシブ)がよい。

人の依頼を AI が要件の文に起こした。依頼に無い細部(行き先が無いリンクの印・名前の変更でのリンクの書き直し)は別の提案(relations-details、AI)にした。

## 差分

新しいケイパビリティ relations(`specs/relations/spec.md`。ID の接頭辞 REL)を作る。

節「版1 — 表の中のリレーション」:

- 追加: REL-1「フロントマターの値(文字か、文字のリスト)のうち、`[[名前]]`・`[[パス\|表示]]`・`[[名前#見出し]]` の形、`[文字](相対のパス)` の形、実際にあるノートを指すただのパス(`projects/mdgrid.md`・`../projects/mdgrid`。`.md` は省いてよい)を、行き先のノートへのリンク(リレーション)とみなすべき。行を見分けるキーはノートのファイル名(パス)で、id の列は要らない。行き先は、値を持つノートのフォルダからの相対、開いた根からのパス、ファイル名(同じ名前が複数なら根に近い・パスの短いもの。BV-22 と同じ)の順で解く。`.base` を開いたときもフォルダを開いたときも同じに扱い、行き先は開いたフォルダの外(登録した表のフォルダ)にあってもよい。普通の値を誤ってリンクにしないため、どのノートも指さないただの文字は、リンクとみなしてはならない。」(確かめ方: `project: "[[mdgrid]]"` で projects/mdgrid.md がある → リンク。`parent: ../projects/mdgrid` → projects/mdgrid.md へのリンク。`status: done` で done.md が無い → ただの文字。フォルダを開いても `.base` を開いても同じ(`test_rel_1_*`))
- 追加: REL-2「リンクの値のセルは、行き先のノートの名前(拡張子なし。`[[…\|表示]]` なら表示の文字)で見せ、リストのときは名前を並べて見せるべき。」(確かめ方: `project: "[[projects/mdgrid\|mdgrid]]"` → `mdgrid`。`tags: ["[[tui]]", "[[relations]]"]` → `[tui, relations]`(`test_rel_2_*`))
- 追加: REL-3「リンクの列(値の多くがリンクの列)のセルを直すときは、候補に、その列のリンクの行き先があるフォルダのノートの名前を出し、選んだノートへのリンクを書くべき。書く形は、その列で使われている形(`[[…]]`・`[…](…)`・パス)に合わせ、無ければ `[[名前]]` にする。同じ名前のノートが複数あるときは、パスで区別できる形で書く。リストの列(多対多)では、複数のノートを選んで書けるべき。」(確かめ方: project の列の値がどれも `[[…]]` で projects/ を指す → 候補は projects/ のノート。選ぶと `"[[mdgrid]]"` と書く(`test_rel_3_*`))
- 追加: REL-4「リンクのセルから、行き先のノートを含む表(登録した表のうち行き先を含むもの、無ければ行き先のフォルダ)を開いて、その行を選べるべき(操作の一覧とパレットから)。保存していない変更があれば、移る前に CLI-19 と同じに確かめる。行き先が無いときは、理由を出し、移ってはならない。」(確かめ方: project のセルで「行き先を開く」→ projects の表が開き mdgrid の行が選ばれている。無い行き先 → 理由を出す(`test_rel_4_*`))
- 追加: REL-5「選んだノートを指しているノート(つながった行・被リンク)を、どの表のどの列から指しているかと一緒に一覧で出し、選んで開けるべき。探す範囲は、開いたフォルダと登録した表にするべき。」(確かめ方: projects/mdgrid.md を選んで「つながった行」→ tasks の project の列から指す3行が出る。選ぶとその行を開く(`test_rel_5_*`))
- 追加: REL-6「登録した表(CLI-18)をワークスペースの表とみなし、ある表の列の値の行き先が別の表のノートなら、設定を書かなくても、その列をその表へのつながり(リストの列なら多対多、そうでなければ多対一)とみなすべき。どのノートの集まりも表の形にそろうわけではないため、行き先がどの表にも無いリンクや、列の形がそろっていないノートの集まりでも、リンクとして扱い、動きを止めてはならない。」(確かめ方: tasks と projects を登録 → tasks.project は projects への多対一。tags の列(リスト)→ 多対多。行き先がどの表にも無いリンク → リンクとして見せ、つながりには数えない(`test_rel_6_*`))

節「次の段」:

- 追加: REL-7「表どうしのつながり(REL-6)を図で見せる関係マップの画面を、表の画面とは別の画面の型(SC-9)として持ち、表ごとの箱(名前・行の数・列)と、列から行き先の表への矢印(1対多・多対多)を描き、選んだつながりの詳細(元の列・行き先の表・種類・逆向きの列)と、つながった行を見せるべき。」(確かめ方: 読んで判定)
- 追加: REL-8「画面の上の端のタブ(表・関係 など)で、画面の型を切り替えられるべき。」(確かめ方: 読んで判定)
- 追加: REL-9「左の欄(ワークスペースの表の一覧)・真ん中・右の詳細・下のつながった行のような段組みは、端末の幅と高さに合わせて変えるべき(広ければ並べ、狭ければ1つずつにしてタブかキーで切り替える)。どの幅でも、文字が重なったり切れて読めなくなったりしてはならない。」(確かめ方: 幅 160・100・60 の端末で関係マップの画面を出す → それぞれ並べる・2つ・1つになり、どれも重ならない(`test_rel_9_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 表どうしをつなぐ方法が無く、プロジェクトとタスクのような集まりを行き来できない |
| id の列(P-01 など)で行き先を指す | ノートにはもともとファイル名という一意のキーがあり、Obsidian のリンクとして動く。id の列を管理する手間が増える |
| 多対多に中間の表(task_tags)を使う | リンクのリストで書けるので要らない |
| 設定でつながりを明示したものだけをリレーションにする | 書く手間が要る。登録した表とリンクの行き先から見つけられる |

## 承認の記録

2026-10-08 人の承認(要約: リンクを .base 以外でも効かせ、パスの書き方を複数受け付け、PK はファイル名、表のつながりは登録した表から自動で見つけ、最初は表の中のリレーションから作り関係マップは次の段、という AI のまとめに同意した。あわせて、どのノートも表の形にそろうわけではないこと、右上のタブで切り替えられるとよいこと、画面の幅に合わせた段組みがよいことを頼んだ)
