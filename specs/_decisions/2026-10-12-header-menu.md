# 設定を右上の別のボタンに、画面の型をメニューに、「+ 新規」をビューの帯に移し、ボタンのキーの字を目立たせる(header-menu)

## きっかけ

view-bar の画面を見た人が、ビューの帯の右の端の「o ⚙」を設定の歯車だと気づかず、頭の `o` を数字の 0 だと思った。設定はビューの帯に無い方がよいのではと言い、inbox に置いた配置の見本(右上に画面の切り替えと歯車)のように右上でもよいと言った。AI が「+ 新規」の隣に置く形を示すと、人は、行を足す「+ 新規」の横に設定があるのはおかしいと言い、画面の型(表・関係)はプルダウンにして、ガントチャートのような型が増えたらそこに出す案を出した。設定をそのメニューに入れる形も見て、設定は別のボタンがよいと決めた(会話 2026-10-12 の要約)。

まとめた形(80桁より広い画面):

```
 w Relations sample › tasks ▾  4行                      ▦ 表 ▾   o ⚙ 設定
 既定の表   \ 検索…   | 絞り込み 1   S 並べ替え   分類   列        a + 新規
```

## 却下した案

| 案 | 理由 |
|---|---|
| 設定をビューの帯に「o ⚙ 設定」として残す | 毎日触る操作の行に、たまにしか使わない入口が混ざる。分類・列のボタンからも設定の画面に入れる |
| 設定を「+ 新規」の隣に置く | 行を足す操作と見え方を変える操作が並び、種類が混ざる |
| 設定を画面の型のメニューの中に入れる | ボタンの字が「表」なので、設定を探す人が開こうと思いにくい |
| 表の上を3行にして、タブだけの行を持つ | 表が1行減り、ビューが1つの人には空の行が増える |
