# --check の要件の ID を CLI-22 から CLI-23 に付け替える(check-id)

## きっかけ

type-check の変更を公開リポへ出す PR を作っている間に、公開リポの main に別の変更(AI エージェント向けのスキル。決定記録 2026-10-14-agent-skill.md、人の決定)が入り、同じ ID の CLI-22 を使っていた。その CLI-22 は公開リポで先にマージ済みで、こちらの CLI-22(`--check`)はまだ公開していない。公開済みの ID を変えると、公開した記録と試験の名前がずれるので、まだ公開していないこちらを、空いている次の番号 CLI-23 に付け替える。要件の文と確かめ方は変えない。

## 差分

- 追加: CLI-23「`mdgrid [<.base \| フォルダ> …] --check [--view <名前>]` は、画面を出さずに、開いたビュー(CLI-5 と同じく、ビューの絞り込みのあとの行。画面の見た目の状態は使わない)の各ノートの全部のフロントマターのキーと、決まり(CE-36)のある列を確かめ、問題(CV-9)を1つ1行で `<パス>:<行>: <列>: <理由>`(キーが無いときは行を付けず `<パス>: <列>: <理由>`)の形でパスと行の順に標準出力に出し、問題の数を標準エラーに1行で出すべき。列の型は、画面と同じく CE-2 の順(設定・ルートフォルダの型の設定・読み込んだ全部のノート(BV-2 の範囲)からの推定)で決めるべき(画面と `--check` で同じ値の判定が食い違わないため)。起動の引数に `.md` のファイルを渡したときは、`--print` と同じく(CLI-15)そのノートの行だけを確かめるべき。問題が無ければ終了コード 0、あれば 1、起動できないときは CLI-4 と同じく理由1行と 2 にするべき(CI と pre-commit で止められるようにするため)。パスは `--pick path`(OUT-3)と同じ形にし、ノートを書き換えないべき。」(確かめ方: `[types] due = "date"` で `due: someday` のノートと、`[rules.status] required = true` で status の無いノート → `notes/a.md:3: due: 型が合わない(日付ではない)` と `notes/b.md: status: 必須のキーが無い`、標準エラーに「問題 2」、終了コード 1。直したあと → 出力なし、終了コード 0。無いパス → 理由1行と終了コード 2。ビューの絞り込みで日付の値の行だけが残っても、ほかの行の値で決まる列の型は画面と同じ。`notes/a.md --check` → a.md の問題だけ(`test_cli_23_*`))
- 削除: CLI-22(理由: `--check` の要件を、文と確かめ方を変えずに CLI-23 へ移した。CLI-22 の ID は、公開リポで先にマージしたエージェントのスキルの要件(2026-10-14-agent-skill.md)のものとして使う)
- 錠: CLI-22(`--check` の試験の関数の名前と頭の要件 ID を CLI-23 に付け替える。確かめる中身は変えない。tests/test_check_cli.rs の test_cli_22_reports_type_and_required_problems・test_cli_22_no_problems_prints_nothing_and_exits_0・test_cli_22_missing_path_exits_2・test_cli_22_values_violation_lines_in_line_order と、tests/test_check_cli_more.rs の test_cli_22_md_arg_checks_only_that_note・test_cli_22_view_filter_keeps_column_kind)

## 却下した案

| 案 | 理由 |
|---|---|
| 公開リポの CLI-22(エージェントのスキル)を付け替える | 公開済みの記録と試験の名前がずれ、先にマージした変更を後から変えることになる |
| 何もしない | 同じ ID の要件が2つになり、試験と記録がどちらを指すか分からなくなる |

## 錨との照合

新しい文脈の検証役(書込なし)の照合: 沿う。
- 原則: specs/ に principles.md が無く、照らせる原則は無い。
- 人の軌跡: 2026-10-14-type-check.md(人)が決めたのは `--check` の中身と目的(CI と pre-commit で止める・問題を1つにまとめる)で、番号の CLI-22 は AI が置いた札。文と確かめ方を残し番号だけを変える。公開リポの 2026-10-14-agent-skill.md(人。CLI-22、試験 test_cli_22_skill_examples_run・test_cli_22_plugin_versions_match_crate)は公開済みで、その記録と試験の名前を後から変えないで済むので、人の決定を守る向き。CLI-23 は手元にも公開リポにも無い。
- 食い違う人の決定: 無し。採択済みの type-check と check-kinds の記録の「CLI-22」は旧い番号のまま残る(記録は書き換えない)。
- 要件の文と確かめ方は、差分の追加の全文が今の CLI-22 と同じで、違いは番号と試験の名前の `test_cli_22_*` → `test_cli_23_*` だけ。
