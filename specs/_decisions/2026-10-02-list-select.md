# リストの値(tags など)を候補から選んで付け外しする(list-select)

## きっかけ

会話 2026-10-02 で人が依頼した: tags を画面でうまく選べるようにしたい。今あるタグの中から打って検索し、候補を出す形で。続く問いへの答えで、リストの列の全部を対象にし、選んだ行への一括の足す・外すを入れ、キーが無いノートには Obsidian と同じ縦の形で書く、と決まった。人の依頼を AI が要件の文に起こした。

## 差分

cell-edit の spec.md を変える。

- 追加: CE-16「リストの値の列(tags に限らず、列の型がリストの列)は、表から要素を付け外しできるべき。候補は、読み込んだノート全部(BV-2 の範囲)のその列に今ある要素とし、打つたびに候補を絞り込んで出し、候補に無い要素も打って足せるべき。」(確かめ方: tags のセルで Enter → 保管庫の中のタグの一覧が出る。「会」と打つ → 会議・会計 だけに絞られる。会議 を付けて確定 → tags に 会議 が足されたためる変更。一覧に無い 新規 を打って足す → 新規 が足される(`test_CE_16`))
- 追加: CE-17「選んだ複数の行(NV-5)のリストの値の列に、要素を一括で足す・外すことができ、各行のほかの要素は残すべきで、一部の行だけが持つ要素は、その旨の印で示すべき。」(確かめ方: 3行を選び、tags に 会議 を足す → 3行とも 会議 が足され、元のタグは残る。1行だけが持つ 本 は「一部」の印。本 を外す → その1行から 本 が消える(`test_CE_17`))
- 追加: CE-18「要素を足し引きして書き戻すときは、元の書き方(1行の `[a, b]` か、複数行の `- a`)と字下げを保つべきで、キーが無い・値が空のノートに初めて書くときは、Obsidian と同じ複数行の形(`key:` の次の行から `  - a`)で書くべき。」(確かめ方: `tags: [a, b]` に c を足す → `tags: [a, b, c]`。字下げ2の `- a` の縦のリストに c を足す → 同じ字下げの `- c` が1行増え、ほかの行は1バイトも変わらない。tags の無いノートに a を足す → `tags:` と `  - a` の2行が足される(`test_CE_18`))
- 削除: CE-6(理由: リストの値を読むだけにしてよいとした版1の許しは、CE-16 で編集できるようにしたので要らない。CE-8 の読むだけの形はそのまま)
- 削除: CE-13(理由: 次の段の要素の足し引きを、CE-16・CE-18 として版1に入れた)

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | タグを付けるには $EDITOR で開いて手で書くしかなく、表の道具としての使い勝手が足りない(人の依頼) |
| tags だけを選べるようにする | 人の答えで、リストの列の全部を対象にすると決まった。リレーションの複数のリンクも同じ仕組みに乗る |
| リストを丸ごと1行の形で書き直す | 元の書き方と字下げが変わり、WB-1(ほかのバイトを変えない)の心に反する。人の答えで、初めて書くときは Obsidian と同じ縦の形と決まった |
