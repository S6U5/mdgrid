# 部品の形とテーマを設定で選べるようにし、選ぶためのカタログをリポに置く(style-catalog)

## きっかけ

人が、表のデザイン(色味・組み立て・形)を改善したいと言い、AI に色味を任せ、値に必ずしも色を付けたいわけではなく、四角い地の札は古い UI の感じがすると言った。AI が出した見本(UI カタログ)を見て、部品の形は設定で変えられてよい、パターンが欲しい、丸い札もあってよい、SaaS 風も、選びは十字のハイライトもよい、カタログで設定ファイルを作れるようにしてリポに入れればよい、と言った(会話 2026-10-09)。選択肢の答えで、既定は墨、カタログは GitHub Pages で公開すると選んだ。

人の依頼を AI が要件の文に起こした。部品の形の名前と組の中身は、カタログの見本(AI が作った)のとおり。行の間に線を引く形(lines・rows)は、行の位置の計算が変わるので、この提案には入れない(別の提案にする)。

## 差分

- 変更: SR-33 旧「色を使える表示では、設定の `look` が `"modern"`(既定)のとき、lazygit のような見た目にするべき: 窓の枠は薄い色で、今操作している窓の枠と題はアクセントの色。選んでいる行・候補・項目は、反転でなく背景の色と太字。下の帯は、キーをアクセントの色の太字、説明を薄い色。ビューのタブの選んでいるものは色の付いた札、ほかは薄い色。列の見出しは太字でアクセントの色。色はテーマ(SR-26)のものを使い、テーマが既定(色の表が無い)なら端末の地の色を変えない控えめな組(薄い灰色・アクセントの水色・暗い灰色の背景)を使う。`look` が `"classic"` のときと色を使わない表示(SR-10)では今の見た目にする。どちらでも、画面の文字・印・構成は変えない(SR-26)。」→ 新「色を使える表示では、設定の `look` が `"modern"`(既定)のとき、今どきの道具のような見た目にするべき: 窓の枠は薄い色で、今操作している窓の枠と題はアクセントの色。選んでいる行・候補・項目は、反転でなく背景の色と太字(形は SR-36 の `select`)。下の帯・ビューのタブ・列の見出しの形は SR-36 の `band`・`tabs`・`icons` に従う。色はテーマ(SR-26)のものを使い、テーマが既定(色の表が無い)なら端末の地の色を変えない控えめな組を使う。`look` が `"classic"` のときと色を使わない表示(SR-10)では今までの見た目(反転)にする。どちらでも、値の文字・印・構成は変えない(SR-26)。」
- 変更: SR-35 旧「色を使う表示(SR-10)では、設定の `cells` が `"rich"`(既定)のとき、表のセルを値の型に合わせた部品で見せるべき: 真偽の値は `☑`・`☐`、リストの要素は1つずつ色の付いた札、種類の少ない短い文字の列(status など)の値は色の付いた札、リンク(REL-2)はアクセントの色、列の見出しには型の印(数 `#`・日付 `◷`・真偽 `☑`・リスト `⋮`・札の列 `◉`)。札の色は値ごとに決まった色にし、どの値も文字はそのまま見せる(色だけで値を伝えない。SR-15)。部品は設定で選べるべき: `cells` は文字列(`"rich"`・`"plain"`)か表で、表なら `style`(全体)と、部品の種類ごとの真偽(`checkbox`・`chips`・`select`・`links`・`icons`)と、列ごとの見せ方 `[cells.columns]`(`"rich"`・`"plain"`・`"chip"`(自動で札にならない列も札に))を書ける。列ごとの設定は種類ごとの設定より優先する。`"plain"` と色を使わない表示では今の見た目にする。ファイルに書く値と、編集・検索・出力(`--print`)の値は変えない。」→ 新「色を使う表示(SR-10)では、設定の `cells` が `"rich"`(既定)のとき、表のセルを値の型に合わせた部品で見せるべき: 真偽の値、リストの要素、種類の少ない短い文字の列(status など)の値、リンク(REL-2)、列の見出しの型の印を、SR-36 の形(`check`・`tags`・`status`・`icons`)で見せる。部品の色は値ごとに決まった色にし、どの値も文字はそのまま見せる(色だけで値を伝えない。SR-15)。部品は設定で選べるべき: `cells` は文字列(`"rich"`・`"plain"`)か表で、表なら `style`(全体)と、部品の種類ごとの真偽(`checkbox`・`chips`・`select`・`links`・`icons`)と、列ごとの見せ方 `[cells.columns]`(`"rich"`・`"plain"`・`"chip"`(自動で部品にならない列も部品に))を書ける。列ごとの設定は種類ごとの設定より優先する。`"plain"` と色を使わない表示では今の見た目にする。ファイルに書く値と、編集・検索・出力(`--print`)の値は変えない。」
- 追加: SR-36(節「版1 — 設定と見た目の状態」)「設定の `[style]` で、表と窓の部品の形を選べるべき: くり返す短い値(`status`: `dot`・`shape`・`text`・`pill`・`tint`・`soft`・`chip`・`plain`)、リスト(`tags`: `dots`・`hash`・`brackets`・`pill`・`tint`・`soft`・`chip`・`plain`)、真偽(`check`: `box`・`tick`・`bracket`・`text`)、選び(`select`: `bar`・`cross`・`tint`・`outline`・`fill`・`reverse`)、区切り(`rules`: `none`・`header`・`columns`・`grid`)、ビューのタブ(`tabs`: `underline`・`pill`・`segment`・`brackets`・`dim`)、窓の枠(`frames`: `rounded`・`square`・`heavy`・`ascii`・`none`)、下の帯(`band`: `keys`・`boxed`・`quiet`)、列の見出しの型の印(`icons`)。`[style]` の `preset` に組の名前(`sumi`・`slate`・`saas`・`paper`・`grid`・`classic`)を書けば部品をまとめて選び、ほかの項目はそれを上書きする。既定は `sumi`(点と文字・`·` で区切るタグ・`✓`・左の線の選び・見出しの下の線・下線のタブ・角の丸い枠・薄い下の帯・印なし)。`pill` は Nerd Font の字を使うので、`nerd_font = true` のときだけ使い、そうでなければ `soft` で描くべき。今までの `borders = "ascii"` は `frames = "ascii"` として受けるべき。知らない値は警告して既定にするべき。」(確かめ方: 既定(設定なし)で色のある表示 → status の値は `● doing`(点だけに色)、tags は `ui · web`、選んだ行の左に `▌`。`[style] preset = "saas"` → 淡い地の丸い札と切り替えの枠のタブ。`status = "chip"` → 今までの札。`pill` で `nerd_font` なし → `soft`。`borders = "ascii"` → 枠が ASCII。知らない値 → 警告(`test_sr_36_*`))
- 追加: SR-37(節「版1 — 設定と見た目の状態」)「テーマ(SR-26)に、落ち着いた色の組 `sumi`(墨。暗い地・薄い灰・青緑のアクセント)・`slate`(石板。紫寄りのアクセント)・`saas`(明るい灰の地・藍のアクセント)・`paper`(明るい地・青のアクセント)・`saas-dark`(saas の暗い地の版)を足すべき。足したテーマも SR-26 と同じく色だけを変え、画面の文字・印・構成は変えない。」(確かめ方: `theme = "sumi"` → 地が #16171b。どのテーマでも画面の文字はテーマなしと同じ(`test_sr_37_*`))
- 追加: SR-38(節「版1 — 設定と見た目の状態」)「リポの `docs/catalog/index.html` に、部品の形とテーマを見本の表と関係マップで見比べて選び、その設定(`config.toml` に貼れる文)を作れるカタログを置くべき。カタログが出す設定の項目と値は、本体の設定(SR-36・SR-37・SR-26)が受けるものと同じにし、ずれたら試験で落とすべき。カタログは1つのファイルで、外の何にも頼らず開けるべき。」(確かめ方: docs/catalog/index.html を開く → 組とテーマを選ぶと見本が変わり、設定の文が出る。カタログの `status` の候補に本体に無い値 → 試験が落ちる(`test_sr_38_*`))
- 追加: SR-39(節「版1 — 設定と見た目の状態」)「設定の `theme` が `"auto"` のとき、端末の地が明るいか暗いかで、`theme_light`(既定 `saas`)と `theme_dark`(既定 `sumi`)のどちらかを使うべき。地の明るさは環境変数 `COLORFGBG` か端末への問い合わせ(短い待ち時間で、答えが無ければ諦める)で決め、分からなければ暗い地とみなす。色を使わない表示ではテーマを使わない(SR-26)。」(確かめ方: `theme = "auto"` で `COLORFGBG=0;15`(明るい地)→ saas。`COLORFGBG=15;0` → sumi。どちらも無く問い合わせに答えない → sumi(`test_sr_39_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(今の四角い札のまま) | 人が、四角い地の札は古い UI の感じがすると言った |
| 形を1つに決める | 人が、部品は設定で変えられてよく、パターンが欲しいと言った |
| カタログをリポの外(見本の頁だけ)に置く | 人が、リポに入れて設定ファイルを作れるようにすればよいと言った。本体とずれないよう試験で突き合わせる |
