# 印のあるフォルダを開いたら、印に書いた表を開く(marker-open)

## きっかけ

人が、タスクの台帳のフォルダ(根に `tasks.base` があり、todo などのフォルダと並んで AGENTS.md・CLAUDE.md・README.md がある)で引数なしに mdgrid を起動したところ、台帳でないそれらのファイルまで表に入ったと言い、そのフォルダで開いたら決めたビューを先に開くようにできないか、`.base` ではなく汎用の設定ファイルで決める方がよいのではと尋ねた(会話 2026-10-15)。AI が、フォルダの印 `.mdgrid/workspace.toml`(WS-7)に「引数なしで開く表」を書けるようにする案(ビューは `.base` に残すので Obsidian でも同じビューが出る)を含む4案を出し、人はその案を選んだ。続けて、引数なしのときだけでよいかを問い、AI の出した効かせ方の3案から「フォルダを開くたび」を選び、素の表やほかの設定を開きたいときはそれを指定する形にしたいと言った(会話 2026-10-15。どれもプロジェクトのチャット)。

人の依頼を AI が要件の文に起こした。項目の名前 `open`・効くのは開くフォルダが印の根のときだけ(上へたどらない・2つ以上のフォルダと `.md` のファイルでは使わない)・`--print` と `--check` も同じ表を使う・無い名前は警告して今までどおり・素の表を開く旗の名前 `--raw`、は AI が足した細部だが、人の選んだ案を使える形にするのに要るので同じ提案に入れた(前例: 2026-10-09-workspace-marker)。

## 差分

- 変更: CLI-1 旧「`mdgrid [<.base のパス \\| フォルダ> …]` で起動し、引数が無ければ、登録した表(CLI-18)が無いときは今のフォルダを開き、あるときは CLI-19 の一覧を出すべき。」→ 新「`mdgrid [<.base のパス \\| フォルダ> …]` で起動し、引数が無ければ、登録した表(CLI-18)が無いときは今のフォルダを開き、あるときは CLI-19 の一覧を出すべき。開くフォルダ(引数に渡したフォルダ1つか、引数が無いときの今のフォルダ)に印 `.mdgrid/workspace.toml` があり、その `open` が印の表を指すとき(WS-7)は、そのフォルダの既定の表と CLI-19 の一覧の代わりに、その表を開くべき。画面を出さない起動(`--print`・`--check`・`--print-config --resolved`)でも同じに使うべき(画面と書き出しで開く表が食い違わないため)。フォルダを2つ以上渡したときと、`.md` のファイルを渡したとき(CLI-15。そのノートの行を選ぶため)は使わないべき。`--raw` を添えたときは `open` を使わずに、そのフォルダの既定の表(BV-1)を開くべきで(素の表を見たいときに印を消さずに済むため)、印の無いフォルダでの `--raw` は何も変えないべき。印の表と別の `.base` は、そのパスを渡して開く。」(確かめ方: 引数なしでノートのフォルダから起動 → そのフォルダの既定の表。places.toml に登録がある → 一覧(先頭は今のフォルダ)。根に `tasks.base` と AGENTS.md のあるフォルダに、`open = "台帳"` と `[[table]] name = "台帳"`・`path = "tasks.base"` の印 → そのフォルダで引数なしの起動・`mdgrid .`・ほかのフォルダからそのフォルダのパスを渡した起動のどれでも tasks.base の表が開き、AGENTS.md の行は無い。places.toml に登録があっても一覧を出さずにその表。同じフォルダで `mdgrid --print` → tasks.base の最初のビューの行。下の `todo/` を開く → todo の既定の表(印は上へたどらない)。`mdgrid AGENTS.md` → 根の既定の表で AGENTS.md の行を選ぶ。根と別のフォルダの2つを渡す → 2つの既定の表。`mdgrid --raw`(根で)と `mdgrid . --raw` → AGENTS.md の行もある既定の表。`mdgrid --raw --print` → 既定の表の行。印の無いフォルダで `--raw` → 今までどおり(`test_CLI_1`・`test_cli_19_*`・`test_cli_1_marker_open_*`))
- 変更: WS-7 旧「フォルダの `.mdgrid/workspace.toml` を、そのフォルダを根とするワークスペースの印として受けるべき。形はアプリの側の1つのワークスペースと同じ(`name`(無ければフォルダの名前)と表の並び `table`。`path` は根からの相対。ワークスペースの表のプロファイルは最上位に、表のものは `[table.look]` などに書く。SR-44)で、表を書かなければ根の直下の、ノートのあるフォルダを表にする(`.base` は WS-5 と同じ理由で入れない)。`mdgrid [<フォルダ>] --init-workspace` で、そのフォルダ(無ければ今のフォルダ)に表を書かない印を作り、既にあれば書かずに理由を出すべき。」→ 新「フォルダの `.mdgrid/workspace.toml` を、そのフォルダを根とするワークスペースの印として受けるべき。形はアプリの側の1つのワークスペースと同じ(`name`(無ければフォルダの名前)と表の並び `table`。`path` は根からの相対。ワークスペースの表のプロファイルは最上位に、表のものは `[table.look]` などに書く。SR-44)で、表を書かなければ根の直下の、ノートのあるフォルダを表にする(`.base` は WS-5 と同じ理由で入れない)。印の最上位の `open` に印の表の名前(書いた表なら `name`、自動の表ならフォルダの名前)を書けば、根のフォルダを開いたときに開く表になり(CLI-1)、その表に `view` があればそのビューで開くべき。`open` が印の表のどれも指さないときは、CLI-3 の形で警告して、`open` が無いときと同じに開くべき。`mdgrid [<フォルダ>] --init-workspace` で、そのフォルダ(無ければ今のフォルダ)に表を書かない印を作り、既にあれば書かずに理由を出すべき。」(確かめ方: notes/.mdgrid/workspace.toml(表なし)→ notes の直下の tasks・projects がワークスペースの表。table を1つ書く → その表だけ。印に `[look] theme = "nord"` → その下の表が nord。`open = "tasks"` と `[[table]] name = "tasks"`・`path = "tasks.base"`・`view = "人だけ"` → `mdgrid notes` が tasks.base の「人だけ」のビュー。表なしの印に `open = "projects"` → projects の表。`open = "無い"` → `.mdgrid/workspace.toml: open:` で始まる警告と、notes の既定の表。`mdgrid notes --init-workspace` → notes/.mdgrid/workspace.toml ができる(`test_ws_7_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(`tasks` のような別名で `.base` を渡す運用だけ) | そのフォルダで `mdgrid` と打つと台帳でないファイルの表が出るのは変わらない |
| ビューも `.base` をやめて印の TOML に書く | Obsidian でビューが見えなくなる。ビューをノートのフォルダに書かない決まり(BV-17)も変えることになる |
| 外すファイル(`exclude`)を印に書けるようにする | 人は選ばなかった。要れば別の提案にする |
| 印を上へたどって、根の下のどのフォルダからでも `open` を使う | 下のフォルダ(`todo/` など)をそのまま開きたいときに開けなくなる。根を開いたときだけにする |
| 引数が無いときだけ `open` を使う | パスを渡して開くと台帳でないファイルの入った表に戻り、別名や登録した表(CLI-18)からは効かない |
| 専用の指定(`mdgrid view` のような語か旗)で開く | 毎回打つ手間が増える。語にすると同じ名前のフォルダを開けなくなる(WS-3 の決定 2026-10-09-workspace-flags) |
