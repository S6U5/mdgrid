# その場の操作の一覧と、前置きのキーの続きの案内(action-menu)

## きっかけ

会話 2026-10-05 で、人が lazygit のような操作感について尋ね、AI が「その場の操作の一覧」と「前置きのキーの続きの案内」の2つを推した。人は進めると答え、開くキーは `x` と右クリック、並べる操作は推しに任せる、案内は下の帯にすぐ出す、を選んだ。人の依頼と選択を AI が要件の文に起こした。screen の範囲外の「次の段: 前置きのキーを押したあとに続きの候補を出す案内」を版1に上げる。

## 差分

screen の spec.md の「要件: 版1 — 操作と見つけやすさ」に足し、範囲外の次の段の行を消す。

- 追加: SR-24「表のモードで、選んでいるセルに対して今使える操作の一覧(メニュー)を、キー(既定 `x`。SR-4 のキーの表で割り当て直せる)とセルの右クリックで開けるべき。一覧はセル(編集・空にする・コピー・エディタで開く・詳細)・列(この列で並べ替え・同じ値で絞る・同じ値を強調・隠す・幅・左右に移す)・行(印・選んだ行にまとめて入れる・行をコピー)・ビューとファイル(新しいノート・ビューの設定・`.base` に書き出す・保存)の節に分け、各行に動作の名前と、その動作の今のキー(割り当て直したあとのキー)を添え、その場で使えない操作(読むだけのセルの編集と空にする、印の無いときのまとめて入れる、読むだけの起動での保存と新しいノートなど)は出さないべき。↑↓(`j` `k`)で選んで Enter で実行し、Esc で閉じ、行に添えたキーを押してもその操作を実行するべき。実行はキーで直接行ったときと同じ振る舞いにするべき。」(確かめ方: status のセルで `x` → 「セル」「列」「行」「ビューとファイル」の節の一覧が出て、「編集  Enter」「この列で並べ替え  s」が並ぶ。「この列で並べ替え」で Enter → `s` と同じに並ぶ。一覧で `s` → 同じ。読むだけのセルで `x` → 「編集」「空にする」が無い。`[keys.table] "m" = "action_menu"` → `m` で開く。セルを右クリック → そのセルを選んで一覧が開く。Esc → 何もせず閉じる(`test_SR_24`))
- 追加: SR-25「前置きのキー(`g g` の `g` のように、キーの表で2つ以上の打鍵の頭になるキー。設定で足したものも含む)を押したら、すぐに下の帯を、続けて押せるキーと動作の名前の並びに替えるべきで、続きを押すか Esc で元の帯に戻すべき。」(確かめ方: 表で `g` → 下の帯が「g → g 先頭の行」になる。続けて `g` → 先頭の行へ動き、帯が元に戻る。`g` のあと Esc → 動かず帯が戻る。設定で `"z z" = "bottom"` を足す → `z` で「z → z 末尾の行」(`test_SR_25`))

## 却下した案

| 案 | 理由 |
|---|---|
| 複数の枠(パネル)の画面 | 表1枚が芯。別の画面は別の画面の型として足す(SC-9) |
| 前置きのキーの案内を窓で出す・少し待ってから出す | 人は下の帯にすぐ出す形を選んだ |
