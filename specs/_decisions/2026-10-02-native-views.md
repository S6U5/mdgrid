# mdgrid 独自のビューの定義(native-views)

## きっかけ

会話 2026-10-02 で人が依頼した: `.base` はおまけ(オプション)にし、それを経由しないで表を組んで見られるようにしたい。続く問いへの答えで定義の置き場を mdgrid の設定の置き場に決め、さらに、独自の定義で構わず `.base` より機能が多くてよい、`.base` と相互に変換できるとなおよい、と添えた。人の依頼を AI が要件の文に起こした。

## 差分

base-view の spec.md に「要件: 版1 — mdgrid のビュー」の節を足す。

- 追加: BV-17「`.base` を使わずに、開いた対象(フォルダか `.base`)ごとに、mdgrid 独自のビューを名前つきで複数持ち、ビューのタブで切り替えられるべきで、その定義は mdgrid の設定の置き場の、人が読み書きできる TOML に置き、ノートのフォルダには書かないべき。mdgrid のビューは、`.base` のビューより多くの機能を持ってよい。」(確かめ方: `.base` の無いフォルダで開き、ビューを2つ作る → タブに「既定の表」と2つの名前が並び、切り替えると絞り込みや列が変わる。終了して開き直すと同じ。設定の置き場の TOML を手で書き足す → タブが増える。ノートのフォルダに新しいファイルが無い(`test_BV_17`))
- 追加: BV-18「ビューの設定の画面(NV-13)から、今の見せ方を名前を付けて mdgrid のビューとして保存でき、今のビューへの上書き・名前の変更・削除ができるべき。」(確かめ方: `o` で done を外し「名前を付けて保存」で「未完了」→ タブに「未完了」が増える。別の絞り込みにして上書き → 開き直しても上書きした見せ方。名前を変える・消す → タブが変わる(`test_BV_18`))
- 追加: BV-19「mdgrid のビューを `.base` のビューとして書き出し、`.base` のビューを mdgrid のビューとして取り込めてよい。`.base` で表せない部分(または mdgrid で解釈できない部分)は落とし、何を落としたかを知らせてよい。書き出しは、利用者が名前を決めた新しい `.base` に書き、既存の `.base` を書き換えないべき(BV-3)。」(確かめ方: 絞り込みと並べ替えとグループのあるビューを書き出す → Obsidian で開ける `.base` ができ、同じ行が出る。表せない設定を持つビュー → 書き出しで落とした項目の一覧が出る。既存の `.base` の名前を選ぶ → 書かずに理由(読んで判定))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | `.base` なしではビューを複数持てず、名前で残せず、手で書けない(人の依頼) |
| ビューの定義を `.base` の形で持つ | 人の答えで、独自の定義で構わず `.base` より機能が多くてよいと決まった |
| 定義をノートのフォルダに置く | 人の答えで、mdgrid の設定の置き場に決まった(SR-11 と同じ考え) |
