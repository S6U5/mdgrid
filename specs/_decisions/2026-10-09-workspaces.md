# ワークスペース(表をまとめる範囲)をアプリの側で持ち、画面とコマンドで管理し、.git と保管庫を検知できるようにする(workspaces)

## きっかけ

人が、リポジトリや保管庫のように、まとめる範囲を決められる方式もあるとよいと言った(会話 2026-10-09)。話し合いで次を決めた: ワークスペースはフォルダに印を置かず、アプリの側(設定のフォルダのファイル)に持ち、画面とコマンドで管理する。.git の検知と保管庫(Obsidian の .obsidian/)の検知は全体の設定で選ぶ。今の「登録した表」(places.toml)はブックマークとして別に残す(案 A)。

人の依頼を AI が要件の文に起こした。今のリレーションの範囲(REL-5・REL-6 の「登録した表」)は、ワークスペースがあればワークスペースに変える。

## 差分

新しいケイパビリティ workspace(`specs/workspace/spec.md`。ID の接頭辞 WS)を作る。節「版1 — ワークスペース」:

- 追加: WS-1「ワークスペース(名前の付いた表の集まり)を、設定のフォルダの `workspaces.toml`(`[[workspace]]` の並び。`name` と、表の並び `table`(`name`・`path`(フォルダか `.base`)・`view`))に持つべき。ノートのフォルダには何も書かない。`path` の先頭の `~` はホームのフォルダ。読めない行は警告にして飛ばし、起動を止めてはならない。」(確かめ方: `[[workspace]]` に name = "Product"、表を2つ → 2つの表のワークスペース。path の無い表 → 警告して飛ばす(`test_ws_1_*`))
- 追加: WS-2「画面のパレットから、ワークスペースを作る・今の表をワークスペースに足す(今のワークスペースから選ぶか新しく作る)・今の表をワークスペースから外す・ワークスペースを開く(一覧から選び、その表を開く)ができるべき。」(確かめ方: 「この表をワークスペースに足す」→ 名前を選ぶ → workspaces.toml にその表が入る。「ワークスペースを外す」→ 消える(`test_ws_2_*`))
- 追加: WS-3「コマンドの引数で、ワークスペースの一覧を出す(`mdgrid workspace list`)・表を足す(`mdgrid workspace add <名前> <パス> [--as <表の名前>]`。ワークスペースが無ければ作る)・外す(`mdgrid workspace remove <名前> [<パス>]`。パスが無ければワークスペースごと)・ワークスペースで開く(`mdgrid -w <名前> [<パス>]`。パスが無ければ最初の表)ができるべき。画面を出さない操作は、標準出力がパイプでも動くべき。」(確かめ方: `mdgrid workspace add Product ~/notes/tasks` → 一覧に出る。`mdgrid -w Product` → 最初の表で開く。無い名前 → 理由1行と 0 以外の終了コード(`test_ws_3_*`))
- 追加: WS-4「開いた表が属するワークスペース(`-w` で選んだもの、無ければ開いた表を含む最初のワークスペース)があれば、リンクの行き先を探す範囲・つながった行・表どうしのつながり・関係マップ・上の端のタブは、そのワークスペースの表(と今の表)だけを使うべき。」(確かめ方: ワークスペース Work に tasks と projects、Hobby に books → tasks で関係マップを開くと tasks と projects だけ。books を指すリンクは行き先の表に数えない(`test_ws_4_*`))
- 追加: WS-5「全体の設定 `workspace_detect`(`"vault"`・`"git"` の並び。既定は `["vault"]`)で、書いたワークスペースが無い表を開いたときに、開いたフォルダから上へたどって最初に見つかった Obsidian の保管庫の根(`.obsidian/` のあるフォルダ)か git のリポの根(`.git` のあるフォルダ)を、名前の無いワークスペースとみなすべき。その表は、根の直下の、ノートのあるフォルダと `.base` のファイルにするべき。」(確かめ方: `.obsidian/` のある保管庫の tasks を開く → 保管庫の直下の projects も関係マップに出る。`workspace_detect = []` → 検知しない(`test_ws_5_*`))
- 追加: WS-6「範囲の決め方は、`-w` で選んだワークスペース → 開いた表を含む書いたワークスペース → 検知(WS-5)→ 登録した表(CLI-18)の順にするべき。今どの範囲かを、ヘッダーかメッセージ行に示すべき。」(確かめ方: 書いたワークスペースと保管庫の両方に入る表 → 書いたほう。どれにも入らない → 登録した表(今までどおり)。ヘッダーにワークスペースの名前(`test_ws_6_*`))

relations の要件を変える:

- 変更: REL-5 旧「選んだノートを指しているノート(つながった行・被リンク)を、どの表のどの列から指しているかと一緒に一覧で出し、選んで開けるべき。探す範囲は、開いたフォルダと登録した表にするべき。」→ 新「選んだノートを指しているノート(つながった行・被リンク)を、どの表のどの列から指しているかと一緒に一覧で出し、選んで開けるべき。探す範囲は、開いたフォルダと、ワークスペース(WS-6 の順で決めたもの。無ければ登録した表)の表にするべき。」
- 変更: REL-6 旧「登録した表(CLI-18)をワークスペースの表とみなし、ある表の列の値の行き先が別の表のノートなら、設定を書かなくても、その列をその表へのつながり(リストの列なら多対多、そうでなければ多対一)とみなすべき。どのノートの集まりも表の形にそろうわけではないため、行き先がどの表にも無いリンクや、列の形がそろっていないノートの集まりでも、リンクとして扱い、動きを止めてはならない。」→ 新「ワークスペース(WS-6 の順で決めたもの。無ければ登録した表(CLI-18))の表について、ある表の列の値の行き先が別の表のノートなら、設定を書かなくても、その列をその表へのつながり(リストの列なら多対多、そうでなければ多対一)とみなすべき。どのノートの集まりも表の形にそろうわけではないため、行き先がどの表にも無いリンクや、列の形がそろっていないノートの集まりでも、リンクとして扱い、動きを止めてはならない。」

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 範囲が人ごとの登録だけで、仕事と趣味の表が同じマップに混ざる。範囲を名前で切り替えられない |
| フォルダに印(.mdgrid/ や mdgrid.toml)を置く | 人が、アプリの側で持ち画面とコマンドで管理するほうが素直とした |
| 登録した表の分類をワークスペースにする(案 B) | 人が A(登録はブックマークとして別に残す)を選んだ。今の places の仕様を変えずに済む |
