# 検索の欄と絞り込み・並べ替えのボタンを線で四角く囲み、ビューの帯を3行にする(search-box)

## きっかけ

人が、検索の欄を普通に線で囲んで作らないかと言った。AI が、1行のまま両端に線・欄とボタンを四角く囲む(3行)・欄だけ四角く囲む(3行)の3つを画面図で示し、人が欄とボタンを四角く囲む形を選んだ(会話 2026-10-12 の要約)。前に人は、行を増やしてもよいとも言っている。

```
 w Tasks ▾  12行                                ▦ 表 ▾   o ⚙ 設定
          ╭──────────────────╮ ╭──────────╮╭──────────╮
 既定の表 │ \ 検索…          │ │| 絞り込み││S 並べ替え│ 分類  列  a + 新規
          ╰──────────────────╯ ╰──────────╯╰──────────╯
 ノート          status  due
```

## 差分

- 変更: SR-1 旧「画面は上から、ヘッダー(範囲と表のパンくずと行数。右の端に画面の型のメニュー(REL-8)と設定のボタン。SR-42)・ビューの帯(左にビューのタブ、右に検索の欄(NV-23)と、絞り込み・並べ替え・分類・列のボタン、右の端に、作れるときは「+ 新規」(CE-25))・設定の帯(条件が効いているとき。NV-16)・表・下の帯(今のモード、選んだセルの位置、未保存の数、今押せるキー)・メッセージ行で構成するべき。ビューの帯のタブと検索の欄、設定の帯は SR-20 で隠せ、タブと検索の欄を両方隠せばビューの帯の行ごと出さない。」→ 新「画面は上から、ヘッダー(範囲と表のパンくずと行数。右の端に画面の型のメニュー(REL-8)と設定のボタン。SR-42)・ビューの帯(左にビューのタブ、右に検索の欄(NV-23)と、絞り込み・並べ替え・分類・列のボタン、右の端に、作れるときは「+ 新規」(CE-25)。検索の欄と絞り込み・並べ替えのボタンを線で四角く囲むので、高さは3行。NV-23)・設定の帯(条件が効いているとき。NV-16)・表・下の帯(今のモード、選んだセルの位置、未保存の数、今押せるキー)・メッセージ行で構成するべき。ビューの帯のタブと検索の欄、設定の帯は SR-20 で隠せ、タブと検索の欄を両方隠せばビューの帯の行ごと出さない。」
- 確かめ方: SR-1 旧の例「80×24 の端末で起動 → 1行目にヘッダー、2行目にタブと検索の欄とボタン、3行目から表、下の帯に「未保存 0」(ゴールデン `test_SR_1`)」→ 新の例「80×24 の端末で起動 → 1行目にヘッダー、2〜4行目にビューの帯(3行目にタブと、線で囲んだ検索の欄とボタン)、5行目から表、下の帯に「未保存 0」(ゴールデン `test_SR_1`)」
- 変更: NV-23 旧「ビューの帯(SR-1)の、ビューのタブの右に、検索(NV-2)の欄を常に出し、欄の頭にキーと「検索」を示し(例「\ 検索」)、効いている語と、合う行の数(例「12/80行」)を見せるべき。欄の右には、ボタン「絞り込み」(NV-29)・「並べ替え」(NV-24)・「分類」・「列」をこの順に並べ、帯の右の端には、作れるときは「+ 新規」(CE-25)を置き、キーのあるボタンにはそのキーを添えるべき(例「S 並べ替え」。マウスで使う人もキーを覚えられるように)。ボタンの頭のキーの字は、名前と見分けられる見た目(太字で、名前と違う色。色を使わない表示では太字)にするべき(キーの字を名前の一部や数字と取り違えないように。ヘッダーのボタン(SR-42)も同じ)。「分類」と「列」は、ビューの設定の画面(NV-18)をその区画で開くべき。端末の幅が足りないときは、列・分類のボタン、今のでないビューのタブの順に省き、今のビューのタブと検索の欄と、絞り込み・並べ替え・「+ 新規」のボタンをなるべく残すべき。欄は設定で出さないこともできてよい。」→ 新「ビューの帯(SR-1)の、ビューのタブの右に、検索(NV-2)の欄を常に出し、欄の頭にキーと「検索」を示し(例「\ 検索」)、効いている語と、合う行の数(例「12/80行」)を見せるべき。欄の右には、ボタン「絞り込み」(NV-29)・「並べ替え」(NV-24)・「分類」・「列」をこの順に並べ、帯の右の端には、作れるときは「+ 新規」(CE-25)を置き、キーのあるボタンにはそのキーを添えるべき(例「S 並べ替え」。マウスで使う人もキーを覚えられるように)。ボタンの頭のキーの字は、名前と見分けられる見た目(太字で、名前と違う色。色を使わない表示では太字)にするべき(キーの字を名前の一部や数字と取り違えないように。ヘッダーのボタン(SR-42)も同じ)。「分類」と「列」は、ビューの設定の画面(NV-18)をその区画で開くべき。端末の幅が足りないときは、列・分類のボタン、今のでないビューのタブの順に省き、今のビューのタブと検索の欄と、絞り込み・並べ替え・「+ 新規」のボタンをなるべく残すべき。検索の欄と、絞り込み・並べ替えのボタンは、それぞれ線で四角く囲み(上下の線を含めて3行の高さ)、ほかのボタンとビューのタブは囲みの真ん中の行に並べるべき(打てる欄とよく使うボタンだと、見てすぐ分かるように)。窓(NV-24・NV-29)は囲みの下の線のすぐ下に開くべき。囲むかどうかは設定 `display.buttons` で選べ、`"box"`(線で囲む。既定)か `"flat"`(囲まず1行)にできるべき(合わない人や、表の行を多く残したい人のため)。`"box"` でも、端末の高さが16行に満たないときは、囲まずに1行で描くべき(表の行を残すため)。欄は設定で出さないこともでき、出さないときは囲みも出さず1行にしてよい。」
- 確かめ方: NV-23 旧の例「起動 → 2行目にタブ「既定の表」、その右に空の検索の欄「\ 検索…」と、キーを添えた絞り込み・並べ替えのボタン(例「S 並べ替え」)、「分類」「列」、右の端に「a + 新規」。設定の ⚙ は無い。「会議」で絞る → 欄に「会議」と「3/16行」。「分類」を押す → ビューの設定の画面の分類の区画。幅 60 → 列・分類が無く、絞り込みと並べ替えと「+ 新規」は出る。ボタンの頭のキーの字は太字で、名前と見た目が違う。設定で欄を消す → 欄が無く、`\` を押せば最下行で打てる(`test_NV_23`)」→ 新の例「起動(80×24)→ 2〜4行目がビューの帯で、3行目にタブ「既定の表」、その右に線で四角く囲んだ空の検索の欄「\ 検索…」と、線で囲んだキーを添えた絞り込み・並べ替えのボタン(例「S 並べ替え」)、「分類」「列」、右の端に「a + 新規」。設定の ⚙ は無い。「会議」で絞る → 欄に「会議」と「3/16行」。「分類」を押す → ビューの設定の画面の分類の区画。幅 60 → 列・分類が無く、絞り込みと並べ替えと「+ 新規」は出る。ボタンの頭のキーの字は太字で、名前と見た目が違う。「| 絞り込み」を押す → 窓は囲みの下の線のすぐ下に開く。高さ 14 → 囲みが無く、ビューの帯は1行。設定 `display.buttons = "flat"` → 囲みが無く、ビューの帯は1行。設定で欄を消す → 欄が無く、`\` を押せば最下行で打てる(`test_NV_23`)」

## 補足

人は、一旦やってみる形で戻すかもしれないと言い、設定でボタンの形を選べるようにする案も出した。仕様は AI に任せると言った(会話 2026-10-12)。

## 却下した案

| 案 | 理由 |
|---|---|
| 1行のまま、欄の両端に縦の線を引く | 上下が開いていて、打てる欄に見えにくい |
| 欄だけ四角く囲み、ボタンは囲まない | 欄とボタンの高さがそろわない |
