# 画面の型「ガント」を足し、WBS の行を時間軸の横棒で見る(gantt)

## きっかけ

人が、サイトの一覧を見てガントチャートが無いことに気づき、画面の型の順(カンバン → ギャラリー → ガント → カレンダー)を変えてガントを先に作るよう指示し、WBS(親子の字下げ・番号・進み具合)をそのままガントで見られることを求めた(会話 2026-10-31)。あわせて、ガントのあとにおすすめの図(カンバン・カレンダー・マトリクス・集計の棒グラフ)を足すよう言った。scope の SC-9 は、タスクの画面をテーマの切り替えでなく別の画面の型として足すと決めている(2026-10-12 のヘッダーのメニューの決定でも、ガントのような型が増えたらプルダウンに出す案が人から出ている)。新しいケイパビリティ `gantt`(GA)を置き、木(TR)と同じ仕組み(印の `[[table]]` の設定 → 画面の型のメニュー → 画面のモジュール)で足す。GA-7 は、型が増えても台帳ごとの設定が重くならないための一般の形(設定の形をそろえ、無ければ推定)で、人の「設定を負荷なくする工夫」(会話 2026-10-25)に沿う。

## 差分

新しいケイパビリティ `specs/gantt/spec.md`(ガント)。

- 追加: GA-1「ワークスペースの印の `[[table]]` に `gantt = { start = "<列>", end = "<列>" }` を書いてよく、`start` と `end` の列の日付をその行の棒の始まりと終わりとみなすべき。`end` の代わりに `days = "<列>"`(始まりからの日数)でもよい。設定が無いときは、日付の列の名前から推定してよい(始まりは start・begin・from・開始、終わりは end・due・finish・until・to・期限・終了。大文字小文字を問わない)。推定でも決まらないときは、理由を出してガントを出さないべき。設定の `start`・`end`・`days` の列が表に無いときは、CLI-3 の形で警告して出さないべき。」(確かめ方: `gantt = { start = "start", end = "due" }` の表 → メニューに「ガント」が出て `C` で開く。設定なしで start と due の日付の列がある → 推定して開き、画面の題に推定した列を示す。設定なしで日付の列が無い → 理由1行で開かない。`start = "none"` → 警告1行で、メニューに出ない(`test_ga_1_*`))
- 追加: GA-2「`C`(か画面の型のメニューの「ガント」)で、今のビューの行(絞り込み・並べ替えのあと)を、左に行の名前、右に時間軸と横棒で見せるべき。時間軸は日・週・月の単位を持ち、開くときは行の範囲が幅に収まる最も細かい単位にするべき。今日の列に印を付け、始まりか終わりの片方しか無い行はその日に印(◆)を置き、どちらも無い行は棒なしで並べるべき。色なしでも棒・印・今日・選んでいる行を見分けられるべき(SR-15)。」(確かめ方: start 2026-10-01・due 2026-10-07 の行 → 日の単位で7マスの棒。due だけの行 → ◆が1つ。MDGRID_TODAY=2026-10-06 → 10/06 の列に今日の印。幅 100 で範囲 400 日 → 週か月の単位で開く。`--no-color` でも棒と印が文字で出る(`test_ga_2_*`))
- 追加: GA-3「ビューの設定の親子(NV-27)が効いているときは、ガントの行も表と同じ並び・字下げ・畳みにし、WBS が効いていれば同じ番号と進み具合を使うべき。親の棒は、親に自分の日付があればそれ、無ければ子孫の始まりの最小から終わりの最大までにし、WBS の進み具合の割合を棒の塗りの長さにするべき。`Z` で畳む・開く。」(確かめ方: parent で子2件(10/01〜10/03、10/05〜10/07)、親に日付なし → 親の棒は 10/01〜10/07。WBS で子の割合が 100 と 0 → 親の棒の塗りは半分。`Z` で親を畳む → 子の行が消える(`test_ga_3_*`))
- 追加: GA-4「ガントの画面では、`j` `k` で行を選び、`h` `l` で時間軸を1単位動かし、`+` `-` で単位を細かく・粗くし、`t` で今日が見える位置に戻し、`Enter` で表に戻ってその行を選び、`Esc`・`q`・`C` で表に戻るべき。マウスは、行のクリックで選び、選んでいる行をもう一度クリックすると表のその行へ、ホイールで行、横のホイールで時間軸を動かすべき。」(確かめ方: `C` → `j` `j` → `Enter` で表の3行目が選ばれる。`l` を3回 → 時間軸が3単位進む。`-` → 日から週へ(`test_ga_4_*`))
- 追加: GA-5「ガントの画面では値を直せないべき(棒の端のドラッグや日付の入力はしない。日付は表で直す)。開いているあいだにノートが外で変わったら、組み直して同じ行を選び直すべき。」(確かめ方: ガントで `Enter` 以外の編集のキーを押しても何も変わらない。開いたまま外でノートの due を変える → 棒が変わり、選んでいた行は同じ(`test_ga_5_*`))
- 追加: GA-6「見せ方の一覧(SR-49)・できることの一覧(SR-51)・キーの文書(SR-22)・設定の文書にガントの項を持ち、組み込みの tasks のスターターに `start` の列と `gantt` の設定を同梱し、場面の台本にガントの場面を持つべき。」(確かめ方: docs/manual/ja・en の views.md に「ガント」の節(画像 images/gantt.svg)。starters/tasks の印に `gantt = { start = "start", end = "due" }`、見本のノートに start。docs/manual-scenarios.toml に id = "gantt"(読んで判定と `test_ga_6_*`))
- 追加: GA-7「画面の型ごとの設定は、`[[table]]` に型の名前のキー(`tree`・`gantt`・以後の `kanban` など)で同じ形(列の名前を指す表)で書き、設定が無いときの推定の規則を型ごとに持ち、画面の型のメニューには設定か推定で開ける型だけを並べるべき(型が増えても台帳ごとの設定を増やさないため)。」(確かめ方: 印に `tree` と `gantt` の両方がある表 → メニューに 表・木・ガント。どちらも無く日付の列が start・due の表 → 表・ガント(推定)。読んで判定: 設定の読み方が同じ形(`test_ga_7_*`))

- 変更: specs/scope/spec.md の範囲外の文「次の段: タスクの画面(cellops のガント・カード等)。SC-9 の別の画面の型として足す。」→ ガントは `gantt` のケイパビリティへ移り、カンバン・カレンダー・マトリクス・集計の棒グラフが次の段(要件の文は変えない。範囲外の節の文だけ)

## 却下した案

| 案 | 理由 |
|---|---|
| 表のテーマの切り替えでガント風に見せる | SC-9 が退けている(同じ核の上の別の画面の型として足す)。 |
| 設定を必ず書かせる(推定しない) | 型が増えるたびに台帳ごとの設定が増える。人は設定の負荷を減らす工夫を求めている。名前からの推定は外れたら画面の題で分かり、印で上書きできる。 |
| 木の画面に棒を足す | 木はフォルダの階層、ガントは時間軸で、行の並びも操作も違う。混ぜると両方が読みにくい。 |
| 棒の端をドラッグして日付を直す | 書き戻しの安全(WB)の確かめが要り、v1 の範囲を越える。日付は表で直し、ガントは読むだけにする(次の段)。 |
| ガントのキーを `G` にする | `G` は表の最後の行(Vim)。`C`(chart)は表のモードで空いている。 |
