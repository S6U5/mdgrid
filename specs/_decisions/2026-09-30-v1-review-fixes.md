# 仕様の点検の指摘を直す(v1-review-fixes)

## きっかけ

書込なしの点検役(2026-09-30)が、v1-full-spec の仕様を調査と照らして点検した。主な指摘: キーの割り当てが要件どうしでぶつかる(Enter・Space・`:`・Ctrl+R、Ctrl+V は貼り付けが次の段なのに必須)、外や `$EDITOR` での変更とためた変更がぶつかったときの扱いが設計にしか無い、日本語入力(IME)の備えが無い、型と合わない値・null と空とキーなしの見分け・改行を含む値の見せ方が無い、大きな保管庫の読み込み(進捗・中断)が無い、SC-13 の確かめ方を scope・output・cli の節の名前が満たさない、WB-4 の確かめ方がためる方式より前のまま、SR-7 が SR-13 と重なる。

直し方: 表示の決まりを新しいケイパビリティ cell-view にまとめ、SR-9・SR-10・SR-15 を screen から、WB-15 を write-back から cli へ移した(ID と文言は変えない。SR-10 は文言も直した)。人の決定の要件(scope の SC-1〜SC-4・SC-6・SC-7・SC-10・SC-11)には触らない。scope・output・cli は、要件の文言を変えずに節の名前だけを「版1 — …」の形にした。検証の指摘なので、足す要件は「するべき」以下にした。

点検のうち、仕様ではなく設計と進め方で受けたもの: 版1が「最初の縦切り(表示・1セルの編集・安全な保存)」より大きい → 変更の記録のタスクに縦切りの順を書く。テストの名前が Rust の命名の警告になる → docs/design.md に、関数名は小文字で本文に `[WB-1]` を書く形と書く。依存の更新で壊れる回帰 → docs/design.md の試験表。端末で区別できないキー(Ctrl+Shift+Z など) → docs/design.md に代わりのキー。仕様の量の上限 → 未決の問いとして人に返す。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 同じキーに2つの動作があり、実装の段で必ずぶつかる。IME が無いと日本語の利用者が表のモードで打てない |
| 表示の要件を screen に足す | screen が15を超える。表示の決まりは1つのケイパビリティに集めた方が読む人が探しやすい |
| 版1を縦切りだけに縮める | 人が選んだ「全部を書いて優先度で分ける」を崩す。縦切りは作る順で表す |
