# キーの割り当ての一覧の文書(keys-docs)

## きっかけ

docs/todo.md の D-2(公開の前に要る文書)。既定のキーと、設定で割り当て直すときに書く動作の名前(SR-13)は、今は画面のヘルプ(SR-5)でしか見られず、設定を書く人が動作の名前を知る手段が無い。設定の文書(CLI-12)と同じく、英・日の文書を置き、キーの表(SR-4)とのずれを試験で落とす。依頼に無い細部を AI が決めるので AI の決定とする(守られる要件に触らない)。

## 差分

screen の spec.md の「要件: 版1 — 操作と見つけやすさ」に足す。

- 追加: SR-22「既定のキーの割り当てと、割り当て直し(SR-13)に書く動作の名前の一覧を、英語(`docs/keys.md`)と日本語(`docs/keys.ja.md`)の文書に置くべき。文書はモードごと(設定の `[keys.<モード>]` の名前)に、キー・動作の名前・説明を並べ、キーの表(SR-4)のモード・キー・動作と、動作の名前の一覧が文書と食い違えば試験で落ちるべき(文書が古くなるのを防ぐため)。」(確かめ方: キーの表に `table` の `x` → 何かの動作を足して文書を直さない → 試験が落ちる。文書から1行消す → 落ちる。文書の動作の名前を設定の `[keys.table]` に書くと、その動作に割り当たる(`test_SR_22`))

## 却下した案

| 案 | 理由 |
|---|---|
| 設定の文書(docs/config.md)の `keys` の節に全部を並べる | 設定の項目の文書が長くなり、キーの一覧を探しにくい。`keys` の節からはキーの文書へリンクする |
| 文書をキーの表から生成するコマンドを足す | 生成物と手で書く説明が混ざる。試験で突き合わせれば十分 |
