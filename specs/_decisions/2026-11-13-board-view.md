# 列の値ごとのレーンにノートをカードとして並べる「ボード」の画面を足す(board-view)

## きっかけ

人から機能の改善と追加の依頼があり、仕様で「次の段」に残っている候補を選択肢で見せたところ、「カンバンの画面」(status などの列の値ごとに、縦の列へカードを並べる別の画面の型を足す)が選ばれた(会話 2026-11-13)。人の依頼を AI が要件の文に起こした。まとめる列の決め方・レーンの並び・カードの中身・カードを移すキー・段組みは AI が起こした細部で、記録の「不明点と仮定」と新しい仕様の「前提」に仮定として置いた。

scope の範囲外の「次の段: タスクの画面(cellops のガント・カード等)。SC-9 の別の画面の型として足す」のうち、カードの画面にあたる。新しい仕様 `specs/board/spec.md`(ボードの画面)を作る。`.base` の kanban のビューは、これまでどおり開かない(SC-8 は変えない)。

## 差分

新しい仕様 `specs/board/spec.md`(ボードの画面)を作り、次の要件を置く。冒頭の文: 「タスクの台帳のように、1件1ノートで、進み具合を `status: doing` のような列の値で持つ表を、値ごとのレーンにカードを並べて見せる画面の型(いわゆるカンバン)。表の画面とは別の画面の型(SC-9)で、関係マップ・木の画面と同じくヘッダーのメニューとキーから切り替える。設定は要らず、切り替えたときにカーソルのあった列でまとめる。カードを隣のレーンへ移すと、その列の値を書き換える変更としてためられ、保存の流れ(差分を見せてから書く)に乗る。`.base` の kanban のビューの解釈はしない(SC-8 のまま)。」

### 版1 — ボードの画面

- 追加: BD-1「表の画面とは別の画面の型(SC-9)として、ボードの画面を持つべき。表の画面で、キー(既定 `B`)・画面の型のメニュー(REL-8)・パレットから切り替えられ、切り替えたときにカーソルのあった列の値ごとに、今の表のビュー(絞り込み・where・計算の列。BV-5・WS-9・WS-10)を通った行だけをレーン(縦の並び)に分け、1行を1枚のカードとして並べるべき。まとめる列にできるのは、ノートのキーの列で、列の型がテキスト(CE-2・CE-35)の列だけにし、ほかの列(`file.*`・計算の列・数・日付・リスト・チェックボックス)では切り替えずに理由を出すべき(型と合わない値を作らないため)。ボードの画面では、同じキー・Esc・`q` で表の画面に戻れるべき。」(確かめ方: 列 status が todo(2行)・doing(1行)・done(1行)の表で、status の列にカーソルを置いて `B` → 「todo」「doing」「done」の3つのレーンに4枚のカードが出る。Esc → 表に戻る。数の列 estimate で `B` → 切り替わらず理由が出る。status = done の行を絞り込みで外してから `B` → done のカードは出ない(`test_bd_1_*`))
- 追加: BD-2「レーンは、まとめる列の値の文字ごとに1つ作り(ためた値があればその値)、見出しに値と、そのレーンのカードの数を出すべき。レーンの並びは、その列の決まりの `values`(CE-36)があればその順を先にし、`values` にある値は、その値の行が無くてもレーンを出すべき(カードを移す先になるため)。残りの値のレーンは文字の順に続け、値が空の行(キーが無い・null・空の文字)のレーン「(なし)」は、空の行があるときだけ最後に出すべき。」(確かめ方: `[rules.status] values = ["todo", "doing", "done"]` と、status が done・todo・review・空 の4行 → レーンは todo(1)・doing(0)・done(1)・review(1)・(なし)(1)の順。決まりが無い → doing・done・todo の文字の順。空の行が無い → 「(なし)」は出ない(`test_bd_2_*`))
- 追加: BD-3「カードには、1行目にノートの名前(表の左のノートの欄と同じ名前。SR-29)を、2行目に、今のビューで見えている列のうち、まとめる列を除いた先頭の2つの列の値を出すべき。ためた変更のある行のカードには、ためた変更の印(`*`。SR-15)を付けるべき。レーンの中のカードの並びは、今のビューの行の並び(並べ替え。NV-3)と同じにするべき。カードを選んで Enter で、表の画面に戻ってその行を選べるべき。」(確かめ方: ビューの列が status・due・owner・tags、ノート `write-spec.md` が due 2026-11-20・owner mika → カードの1行目に write-spec、2行目に 2026-11-20 と mika。due の昇順のビュー → レーンの中も due の昇順。カードで Enter → 表の画面でその行が選ばれている(`test_bd_3_*`))
- 追加: BD-4「ボードの画面で、選んだカードを左・右の隣のレーンへ移せるべき(既定 `H`・`L` と Shift+←・Shift+→)。移すと、その行のまとめる列の値を、移した先のレーンの値にする変更を、ためる変更の1手(WB-10)としてためるべきで、ファイルは保存の流れ(差分を見せてから書く。WB-9)でだけ書かなければならない。レーン「(なし)」へ移すと、値を空にする変更(CE-9)をためるべき。読むだけのセル(CE-8・CE-12・WB-5)の行のカードは移さずに理由を出し、読むだけの起動(WB-15)では移してはならない。移したあとも同じカードを選んだままにし、ボードの画面の中で取り消し・やり直し(WB-10)ができるべき。保存の操作(既定 Ctrl+S)は、表の画面に戻って保存の確認(WB-9)を開くべき。」(確かめ方: todo のレーンのカード write-spec で `L` → doing のレーンに移り、カードに `*`、下の帯に「未保存 1」、ファイルは変わらない。`u` → todo に戻って「未保存 0」。左の端のレーンで `H` → 動かない。Ctrl+S → 保存の確認に `-status: todo`・`+status: doing`。読めないフロントマターのノートのカードで `L` → 移らず理由。`--readonly` で `L` → 移らない(`test_bd_4_*`))
- 追加: BD-5「レーンは横に並べ、レーンの幅は画面の幅をレーンの数で分けた幅(下限 18 桁)にし、入りきらないレーンは、選んでいるレーンが見えるように横に送るべき。レーンの中のカードが高さに入りきらないときは、選んでいるカードが見えるように縦に送るべき。隠れているレーンとカードがあることを、端の印で示すべき。どの幅と高さでも、文字が重なったり、隣のレーンにはみ出したりしてはならない。」(確かめ方: レーンが5つで幅 100 → 5つとも出る。幅 40 → 2つだけ出て、`l` で右へ動くと選んだレーンが見える所まで送られ、左に隠れたレーンの印が出る。1つのレーンにカード 30 枚・高さ 24 → `j` で下へ動くと選んだカードが見える。どの行も画面の幅を超えない(`test_bd_5_*`))
- 追加: BD-6「ボードの画面は、マウスでも操作できるべき。カードのクリックで選び、選んでいるカードをもう一度クリックしたら表の画面のその行に移り、レーンの見出しのクリックでそのレーンを選び、ホイールで選んでいるレーンのカードを上下に選ぶ。」(確かめ方: doing のレーンのカードをクリック → そのカードが選ばれる。もう一度クリック → 表の画面でその行。done の見出しをクリック → done のレーンが選ばれる(`test_bd_6_*`))

### 次の段

- 追加: BD-7「ワークスペースの印の `[[table]]` に、ボードの設定(まとめる列・レーンの順・カードに出す列)を書いて、列にカーソルを置かなくても同じボードを開けるべき。」(確かめ方: 読んで判定)
- 追加: BD-8「レーンの中でカードを上下に動かして並びを変え、並びの列の値を振り直す変更としてためられるべき。」(確かめ方: 読んで判定)

### 範囲外(新しい仕様に書く)

- 次の段: リストの列(`tags` など)でまとめること(1枚のカードが2つ以上のレーンに出る)。版1 はテキストの列だけ(BD-1)。
- 次の段: マウスでカードを掴んで別のレーンへ動かすこと。版1 はキーで移す(BD-4)。
- 採らない: `.base` の kanban のビューを読んでボードにすること(SC-8。mdgrid のボードは、表のビューの上の画面の型)。
- 採らない: 表のテーマの切り替えでボードを作ること(SC-9)。

### 前提(AI の仮定。新しい仕様に書く)

- まとめる列は、切り替えたときにカーソルのあった列にする(設定を要らなくするため。印に書く形は BD-7)。
- レーンの順は、列の決まりの `values`(CE-36)を使う(新しい設定を足さず、値の候補の順をそのまま使えるため)。
- カードの2行目に出す列は、ビューの見えている列の先頭の2つ(まとめる列を除く)にする。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(グループ分けで見る) | BV-5 のグループ分けは縦に1列で、状態ごとの量と偏りを横に見比べられず、状態を変えるにはセルを1つずつ開いて値を選ぶことになる。 |
| `.base` の kanban のビューを読んで出す | Obsidian の側の形に引きずられ、.base を持たないフォルダでは使えない。SC-8 のとおり table だけを読み、ボードは mdgrid の画面の型にする。 |
| 印の設定があるときだけ出す(木の画面と同じ) | 木は階層の列と区切りを決めないと作れないが、ボードは列が1つ決まれば作れる。設定なしで、開いた列でまとめるほうが試しやすい。印に書く形は次の段(BD-7)。 |
| カードを移したらすぐ書く | ためてから差分を見て保存する(WB-9)が、この道具の信用の芯。 |
