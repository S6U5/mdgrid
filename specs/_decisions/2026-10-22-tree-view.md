# 階層の列でノートを木に並べて見せる「木」の画面を足す(tree-view)

## きっかけ

ブラウザのブックマークを1件1ノートで持つ台帳(フォルダの位置を「根 > フォルダ > …」の列に書く)を作ったところ、人から、関係マップのように、ブックマークをうまく見られる画面を mdgrid に足そうという依頼があった(会話 2026-10-22)。人の依頼を AI が要件の文に起こした。木の形・設定の書き方・操作の細部は AI が起こし、この提案を人に見せて承認を受けた。

表は1行1ノートで並ぶため、「どのフォルダに何が入っているか」「フォルダの中の並び」を見るには、グループ分け(BV-5)だけでは深い階層が平らになり、見通しにくい。新しい仕様 `specs/tree/spec.md`(木の画面)を作り、SC-9 の別の画面の型として足す。ブックマーク専用にはせず、階層を文字の列で持つどの台帳(資料の分類・部署の木など)にも使える形にする(SC-1 の芯の「表の表示」に役立つ範囲)。

## 差分

新しい仕様 `specs/tree/spec.md`(木の画面)を作り、次の要件を置く。

### 版1 — 木の画面

- 追加: TR-1「表の画面とは別の画面の型(SC-9)として、木の画面を持つべき。表に階層の列の設定(TR-2)があるときだけ、画面の型のメニュー(REL-8)に「木」を出して切り替えられ、設定が無い表では出さないべき。木の画面は、今の表のビュー(絞り込み・where・計算の列。BV-5・WS-9・WS-10)を通った行だけを扱うべき(ビューで外した行を木に出さないため)。」(確かめ方: 印に階層の列を書いた表で「▦ 表 ▾」を押す → 窓に「木」がある。選ぶ → 木の画面になる。設定の無い表 → 窓に「木」が無い。ビュー「使う」(status が active だけ)で木を開く → archived の行が木に出ない。`test_tr_1_*`)
- 追加: TR-2「ワークスペースの印の `[[table]]` に `tree = { path = "<列>", separator = "<区切り>", order = "<列>" }` を書いてよく、`path` の列の値を `separator`(省略は ` > `)で切ったものを、その行の置き場の階層とみなすべき。`order` は省略してよい。`path` の列が無い表や、区切りが空の文字のときは、CLI-3 の形で警告して木を出さないべき。」(確かめ方: `tree = { path = "folder", order = "order" }` と folder が `bar > 開発 > Web` の行 → bar の下の 開発 の下の Web に置かれる。`separator = ""` → 警告1行で、メニューに「木」が出ない。`test_tr_2_*`)
- 追加: TR-3「木の画面の左に、階層の木を描くべき。行の値に出てくる途中の階層もフォルダとして作り(`a > b > c` だけでも a と b を作る)、各フォルダに、その下にある行の数(下の階層も含む)を添え、フォルダを開く・閉じるができるべき。階層の列が空の行は、根の「(なし)」にまとめるべき。同じ名前のフォルダは、親が違えば別のフォルダにするべき。フォルダの並びは名前の順にするべき。」(確かめ方: `bar > 開発`(2行)・`bar > 開発 > Web`(1行)・`other`(1行)・空(1行) → 木は bar(3)・開発(3)・Web(1)・other(1)・(なし)(1)。開発を閉じる → Web が隠れ、数は3のまま。`test_tr_3_*`)
- 追加: TR-4「木の画面の右に、選んだフォルダの直下にある行を、今のビューの列(`order` の並び)で並べるべき。並びは TR-2 の `order` の列の小さい順(数として読めない値と空は後ろに、同じ値はノートの名前の順)にし、`order` が無ければノートの名前の順にするべき。行を選んで Enter で、表の画面のその行に移れるべき。」(確かめ方: 開発 を選ぶ → order 10・20・空 の3行がその順に出る。order が `abc` の行は空と同じく後ろ。行で Enter → 表の画面に戻り、その行が選ばれている。`test_tr_4_*`)
- 追加: TR-5「右の欄で選んだ行に `http://` か `https://` で始まる値の列があれば、その URL を OS の既定のブラウザで開く操作を、操作の一覧とパレットから出せるべき。開く前に URL を下の帯に見せ、`http`・`https` 以外の値は開いてはならない(ノートの値から任意のコマンドやファイルを開かないため)。」(確かめ方: url が `https://example.com` の行で「URL を開く」→ 帯に URL が出て、OS の開くコマンドに渡る(試験では開く口を差し替えて渡った値を確かめる)。`file:///etc/passwd`・`javascript:` の行 → 出さないか、理由を出して開かない。`test_tr_5_*`)
- 追加: TR-6「木の画面の段組み(左の木・右の行)は、端末の幅と高さに合わせて変えるべき(広ければ並べ、狭ければ1つずつにしてキーかタブで切り替える)。どの幅でも、文字が重なったり切れて読めなくなったりしてはならない。」(確かめ方: 幅 160・100・60 で木の画面を出す → 160・100 は並べ、60 は1つずつ。どれも重ならない。`test_tr_6_*`)
- 追加: TR-7「木の画面は、マウスでも操作できるべき。フォルダのクリックで選び、開閉の印のクリックで開く・閉じる、右の行のクリックで選び、選んでいる行をもう一度クリックしたら表のその行に移り、ホイールで上下に選ぶ。」(確かめ方: 開発 の印をクリック → 閉じる。Web をクリック → 選ぶ。右の行をクリック2回 → 表のその行へ。`test_tr_7_*`)

### 次の段

- 追加: TR-8「木の画面で、右の行を別のフォルダへ移せるべき(左のフォルダを選んで移す)。移すと、その行の `path` の列の値を新しいフォルダの階層の文字に書き換える変更としてため、保存の流れ(差分を見せてから書く。WB-9)に乗せるべき。」(確かめ方: 読んで判定)
- 追加: TR-9「木の画面で、右の行を上下に動かして並びを変えられるべき。動かすと、そのフォルダの行の `order` の列を、並びどおりの値(10 刻み)に振り直す変更としてため、保存の流れに乗せるべき。」(確かめ方: 読んで判定)

### 範囲外(新しい仕様に書く)

- 次の段: フォルダの並びをノートの外の一覧(例: 台帳の設定のフォルダの順)から読むこと。版1 は名前の順(TR-3)。
- 採らない: ブックマーク専用の画面や、ブラウザのブックマークのファイルを直接読むこと(SC-1・SC-2。台帳の側の道具の役目)。
- 採らない: 表のテーマの切り替えで木を作ること(SC-9)。

### 前提(AI の仮定。新しい仕様に書く)

- 木の画面への切り替えのキーは設計で決める(関係マップの `R` と同じく、窓を開かずに切り替えるキーを1つ持つ)。
- 階層の列が文字のリスト(`[a, b]`)のときは、版1 では最初の要素だけを使う。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(グループ分けで見る) | BV-5 のグループ分けは1段で、`bar > 開発 > Web` のような深い階層が平らな見出しの並びになり、フォルダの中の並びも見通せない。 |
| 階層を表すフォルダ(ディレクトリ)でノートを分ける | ブックマークの台帳はフォルダの移動を値の書き換えで済ませたい。ディレクトリにすると移動がファイルの移動になり、リンクや履歴が崩れやすい。 |
| 関係マップに木を描く | 関係マップは表どうしのつながり(REL-6)の図で、1つの表の中の階層とは別の目的。同じ画面に入れると両方が読みにくくなる。 |
