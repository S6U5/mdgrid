# 範囲外の項目に「次の段:」「採らない:」の印を付ける(scope-priority-marks)

## きっかけ

仕様の点検(書込なしの点検役、2026-10-01)の指摘: SC-13 は「範囲外 = 採らない」と定めるが、各 spec の範囲外には「次の段:」の行と印の無い行が混ざっていて、範囲外の行が次の段なのか採らないのかが読めない。範囲外の行に印を付ける決まりに変え、印の無い行(scope・write-back)に印を付ける。

## 差分

- 変更: SC-13 旧「仕様の要件は、版1・次の段・採らない の3つの優先度に分け(版1 と次の段は各仕様の節の名前で、採らないは「範囲外」で示す)、実装は版1から行わなければならない。」→ 新「仕様の要件は、版1・次の段・採らない の3つの優先度に分け(版1 と次の段の要件は各仕様の節の名前で示す)、実装は版1から行わなければならない。範囲外に書く項目には(削除した要件の記録の行を除く)、頭に「次の段:」か「採らない:」を付けるべき。」(確かめ方: 各 spec.md の要件の節の名前が「版1 — …」か「次の段」で始まり、範囲外の行が「次の段:」「採らない:」か「… は … に削除」で始まる。印の無い範囲外の行 → 違反(読んで判定))

要件の表の外の変更(範囲外の行に印を付ける。要件の文は変えない):

- scope: AI エージェントの機能 → 次の段(SC-6 は「今後載せる」なので採らないにしない)。タスクの画面 → 次の段(SC-9)。table 以外のビューとノートの中の base の埋め込み → 2行に分けてどちらも次の段(SC-8 は「最初の版は」と限る。表の見た目の切り替えで作るのは base-view で採らない)。`.base` 自体の編集 → 採らない(base-view の BV-3 と範囲外の「`.base` への書き戻し」と同じ)。
- write-back: リストの要素の足し引き → 次の段(CE-13)。ネストした map・ブロックスカラーの書き換え → 採らない(元の文のまま)。本文の編集 → 採らない(`$EDITOR` に渡す)。保存したあとの取り消し → 次の段(元の文のまま)。

新しい印の強さは、予防の決まりなので「するべき」にした(元の SC-13 の「しなければならない」は、優先度に分けることと版1から作ることにだけ残す)。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 範囲外の行が次の段か採らないかを、読む人が行ごとに推測する。SC-13 の文と実物が食い違ったまま |
| 次の段の項目を、範囲外から各 spec の「次の段」の要件の節に移す | 要件の文と確かめ方を書くほど固まっていない項目が多い。範囲外の印で足りる |

## 承認の記録

AI 自己採択(検証の指摘の直し。SC-13 は v1-full-spec の AI の決定で、人の決定の要件ではない(人が選んだのは「優先度で分ける」ことで、分け方の書き方は AI が起こした)。SC-6 の文は変えない。次の決めるモードの束の末尾で事後確認)
