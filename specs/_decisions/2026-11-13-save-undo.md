# 最後の保存で書いたファイルを、保存の前の中身に戻せるようにする(save-undo)

## きっかけ

人から機能の改善と追加の依頼があり、仕様で「次の段」に残っている候補を選択肢で見せたところ、「保存後の取り消し」(保存したあと、ファイルを保存の前の中身に戻せるようにする)が選ばれた(会話 2026-11-13)。人の依頼を AI が要件の文に起こした。戻す範囲(最後の1回)・確認の出し方・ためる変更に戻すことは AI が起こした細部で、記録の「不明点と仮定」に仮定として置いた。

write-back の範囲外の「次の段: 保存したあとの取り消し(ファイルを元に戻す)」を、版1の要件にする。

## 差分

- 追加: WB-21「最後の保存(WB-9)で書いたファイルを、保存の前の中身に戻せるべき(パレットの「保存を取り消す」から。既定のキーは割り当てない)。戻す前に、ファイルごとの差分(今の中身から保存の前の中身へ)を見せて確認をとり、確定したら WB-8 の手順で書き、戻したファイルは保存の前と1バイトも違わないようにするべき。保存のあとに外で変わったファイル(今の中身が、保存で書いた中身と違う)は、書かずに飛ばして知らせなければならない(外の変更を消さないため)。戻したファイルの、その保存で書いた値は、ためる変更として戻し(取り消し・やり直しの1手。WB-10)、直してもう一度保存できるべき。覚えるのは最後の1回の保存だけで、起動している間だけにし、ノートのフォルダに控えのファイルを作ってはならない(WB-2)。読むだけの起動(WB-15)ではコマンドを出さない。」(確かめ方: `status: todo` を done に直して保存 → ファイルは `status: done`。「保存を取り消す」→ 差分に `-status: done` と `+status: todo`。確定 → ファイルは保存の前と1バイトも違わず、status のセルは done のまま「未保存 1」。`u` → 「未保存 0」。保存のあとに外で title を直してから「保存を取り消す」→ 差分の代わりに外で変わったと出て、確定してもそのファイルは書かれない。まだ保存していないとき → 何も書かず、取り消す保存が無いと知らせる。2回保存したあと → 戻るのは2回目の保存だけ。`test_wb_21_*`)
- 範囲外の行を消す: 「次の段: 保存したあとの取り消し(ファイルを元に戻す)。」(WB-21 で版1に入れたため)

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 保存の前なら `u` で戻せるが、書いたあとは戻す手が無く、差分を見て確定しても間違いに気づくのは書いたあとのことがある。 |
| 前の値をためて保存し直す(逆の編集) | クオートや空白が保存の前と同じになる保証が無く、「保存の前に戻す」と言えない。バイトの控えで戻す。 |
| ノートの隣に控えのファイルを作る | ノートのフォルダに道具のファイルを増やし、WB-2 に反する。 |
| `u` を保存の直後に押したら戻す | ファイルを書く操作が、ためる変更の取り消しと同じキーで始まり、違いが分かりにくい。 |
