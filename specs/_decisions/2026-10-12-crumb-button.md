# ヘッダーのパンくずを、キーと ▾ を添えた引き出しのボタンにする(crumb-button)

## きっかけ

view-bar(2026-10-11)で1行目をパンくず「範囲 › 表  N行」にしたところ、人が、タスクの表から別の表へ切り替えるときにどこを押せばいいのか分かりにくいと言った(前は右上に「▾ ワークスペース」のボタンがあった)。AI が、パンくずをボタンにする・左の端に別のボタンを置く・下の案内に出すだけ、の3つを画面図で示し、人がパンくずをボタンにする案を選んだ(会話 2026-10-12 の要約)。

## 差分

- 変更: SR-42 旧「ヘッダー(SR-1)の左に、今の範囲と表を「範囲 › 表」の形(パンくず)で行の数とともに見せ、範囲がワークスペースでなければ範囲を省くべき。パンくずの範囲と表の名前は押せ、押すと表の一覧の引き出し(WS-8)を開け閉めするべき。右の端には画面の型のタブ(REL-8)と「+ 新規」(CE-25)を置き、パンくずとともに表の画面と関係マップで同じ位置に出し、関係マップで押したら表の画面に戻ってから開くべき。ビューの設定の画面(`o`)を開くボタンは、ヘッダーでなくビューの帯(NV-23)に置くべき(ビューに関わる操作を1か所に集めるため)。」→ 新「ヘッダー(SR-1)の左に、今の範囲と表を「範囲 › 表」の形(パンくず)で見せ、その右に行の数を見せ、範囲がワークスペースでなければ範囲を省くべき。パンくずは、表の一覧の引き出し(WS-8)を開け閉めする1つのボタンとし、ビューの帯のボタン(NV-23)と同じ見た目にして、頭に引き出しのキー(SR-13 で割り当てたキー。割り当てが無ければ添えない)、後ろに「▾」を添えるべき(押せることと、何が開くかが見て分かるように)。右の端には画面の型のタブ(REL-8)と「+ 新規」(CE-25)を置き、パンくずとともに表の画面と関係マップで同じ位置に出し、関係マップで押したら表の画面に戻ってから開くべき。ビューの設定の画面(`o`)を開くボタンは、ヘッダーでなくビューの帯(NV-23)に置くべき(ビューに関わる操作を1か所に集めるため)。」
- 確かめ方: SR-42 旧の例「ワークスペース「仕事」の tasks を開く → 1行目の左が「仕事 › tasks  3行」。「仕事」をクリック → 表の一覧の引き出しが開き、もう一度で閉じる。」→ 新の例「ワークスペース「仕事」の tasks を開く → 1行目の左が「w 仕事 › tasks ▾  3行」で、「w 仕事 › tasks ▾」がボタンの見た目。そこをクリック → 表の一覧の引き出しが開き、もう一度で閉じる。範囲が無い → 「w tasks ▾  3行」。引き出しのキーを外す → 「仕事 › tasks ▾」。」(ほかの例は変えない)

## 却下した案

| 案 | 理由 |
|---|---|
| パンくずの左の端に別のボタン「w ≡ 表」を置く | 1行目が狭くなり、表の名前と入口が分かれる |
| 下の帯の案内に「w 表の一覧」を足すだけ | マウスで押せる所が分かりにくいまま |
