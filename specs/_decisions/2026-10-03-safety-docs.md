# 書き戻しの安全の文書(safety-docs)

## きっかけ

docs/todo.md の D-4(公開の前に要る文書)。mdgrid の芯は「直したキーの値の外を1バイトも変えない」書き戻しだが、何を保ち、いつ書かずに止め、どのノートを読むだけにするかを利用者が読める文書が無い。F-3(strict-write-safety)は 2026-10-03 の判断の束で人が「採る」と決めた(承認の一文は待ち)。文書は要件の強さでなく今の振る舞いを書くので、強さの採択を待たずに置ける。依頼に無い細部を AI が決める(守られる要件に触らない)。

## 差分

write-back の spec.md の「要件: 版1 — 書き方」に足す。

- 追加: WB-19「書き戻しの安全(1バイトも変えない範囲(WB-1・WB-2)、読むだけにするノートの形と理由(WB-3・WB-5。形ごとに例のノートを添える)、外の変更とのぶつかり(WB-4・WB-12・WB-16)、書き込みの手順(一時ファイル・読み直し・fsync・名前の変更・権限とシンボリックリンク。WB-6・WB-8))を、英語(`docs/safety.md`)と日本語(`docs/safety.ja.md`)の文書に書くべき。文書の読むだけの形の例は試験で読み取りに通し、読むだけにならなければ落ち、読むだけの理由の種類が文書に無ければ落ちるべき(文書が古くなるのを防ぐため)。」(確かめ方: 読み取りに読むだけの理由を1つ足して文書を直さない → 試験が落ちる。文書の BOM の例から BOM を消す → 落ちる(`test_WB_19`))

## 却下した案

| 案 | 理由 |
|---|---|
| README に短く書くだけにする | 読むだけの形と理由は多く、ずれを試験で落とせない |
| F-3 の採択まで待つ | 文書は今の振る舞いを書くので、強さの採択に左右されない。0444(F-2)が入ったら文書を直す |
