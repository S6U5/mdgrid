# ビューの設定の画面と、表の上のフィルターの帯(view-settings)

## きっかけ

会話 2026-10-01 で人が依頼した: todo 以外の用途にも使うので、画面の中の設定で表の見せ方を変え、反映の操作で効かせたい(例: done の行を出すか出さないか、グループ分けをするかしないか)。項目は Notion や Excel のような表の道具を参考に好きに組めるようにし、効いているフィルターは表の上に並べたい。続く問いへの答えで、隠す行は列と値を選ぶ形(どの列でも)、設定はビューごとの見た目の状態に覚える、と決まった。人の依頼を AI が要件の文に起こした。

## 差分

navigation の spec.md に「要件: 版1 — ビューの設定」の節を足す。

- 追加: NV-13「表の見せ方を変えるビューの設定の画面を持ち、そこでフィルター・並べ替え・グループ分け・表示する列を組んで、反映の操作で表に効かせるべきで、反映するまでは表を変えず、取り消せば元のままにするべき。」(確かめ方: 設定の画面で status の done を隠す → 反映の前は表に done の行が残り、反映で消える。取り消しで閉じる → 表は開く前のまま(`test_NV_13`))
- 追加: NV-14「設定のフィルターは、todo の status に限らない用途で使うため、特定の列に決め打ちせず、どの列でも、その列の値を選んで、その値の行を隠すか、その値の行だけを出すかを決められるべき。」(確かめ方: status の done を外す → done の行が消える。種別の列の 本 だけを残す → 本 の行だけ。キーの無いノートは「(空)」として選べる(`test_NV_14`))
- 追加: NV-15「設定で、グループ分けをする列を選ぶことと、グループ分けをしないことを選べるべきで、`.base` の groupBy より設定を優先し、`.base` は書き換えないべき。」(確かめ方: groupBy のある `.base` のビューで「しない」を選んで反映 → 見出しの行が消える。種別の列を選ぶ → 種別ごとの見出し。`.base` のバイトは同じ(`test_NV_15`))
- 追加: NV-16「設定で効いているフィルター・並べ替え・グループ分けを、表の上の帯に並べて見せるべき。何も効いていなければ帯を出さないでよい。」(確かめ方: status の done を外して反映 → 表の上に「status: done を除く」の項目が出る(`test_NV_16`))
- 追加: NV-17「設定は、開いた対象とビューごとの見た目の状態(SR-11・SR-12)に覚え、次に同じものを開いたときに当て、`.base` とノートには書かないべき。」(確かめ方: 設定を反映して終了 → 同じ `.base` の同じビューで開き直すと同じ設定。`.base` とノートのフォルダは変わらない(`test_NV_17`))
- 追加: NV-18「設定の画面の項目は、表の道具(Notion のビューの設定・Excel のオートフィルター)に倣い、表示する列(表示・非表示と順)・フィルター・並べ替え(複数の列と向き)・グループ分けを1つの画面にまとめるべき。」(確かめ方: 設定の画面に4つの項目が並び、それぞれから変えられる(ゴールデン `test_NV_18`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 今の絞り込み(NV-2 の文字、NV-8 の同じ値)と一時的な並べ替え(NV-3)は覚えず、グループ分けは `.base` でしか決められない。todo 以外の表で、見せ方を画面から組めない |
| done を隠す切り替えだけを足す | 列と値を決め打ちにすると、todo 以外の用途で使えない(人の答えで、列と値を選ぶ形に決まった) |
| 設定を `.base` に書き込む | BV-3(`.base` を書き換えない)と SR-11 に反する。人の答えで、見た目の状態に覚える形に決まった |

## 承認の記録

2026-10-01 人の承認(要約: 画面の設定で見せ方を変え反映で効かせること、done の行の表示の切り替えとグループ分けの切り替え、表の道具を参考に組めること、表の上のフィルター、を依頼した。続く問いで、列と値を選ぶ形とビューごとの見た目の状態に覚える形を選んだ。依頼が承認)
