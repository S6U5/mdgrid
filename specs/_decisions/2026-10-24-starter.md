# 台帳のスターター(組み込みの印・雛形・見本)から表を作れるようにする(starter)

## きっかけ

人から、タスク・ブックマークのような台帳の「形」の定義を、見せ方のテンプレートとして mdgrid に持ち、いくつかの型を組み込んでおいてそこから台帳を作れるようにしたいという依頼があった(会話 2026-10-24)。人の依頼を AI が要件の文に起こした。組み込む4つ・入口(CLI と画面)・自分のスターターも同じ仕組みで使うこと・見本のノートを入れるかを選べること・呼び名(日本語「スターター」、英語 `starter`)・見本 examples/bookmarks をスターターから作ったものにすること・中身を英語と日本語の両方で持つことは、選択肢の問いで人が選んだ。

今は、印 `.mdgrid/workspace.toml` を手で書くか、`--init-workspace`(WS-7)で空の印を作って育てるしかない。印の完成形はリポの見本(examples/)や別のリポの雛形にあるが、mdgrid の中から選んで作ることはできない。新しい仕様 `specs/starter/spec.md`(台帳のスターター)を作る。スターターは台帳の「見せ方」(印・新しいノートの本文の雛形・見本のノート)だけを持ち、ノートの形の決まり(スキーマ・lint)は持たない(SC-1 の芯「表の表示」の範囲に収め、台帳ごとの知識を mdgrid に入れないため)。

## 差分

新しい仕様 `specs/starter/spec.md`(台帳のスターター)を作り、次の要件を置く。

### 版1 — スターターの形と組み込み

- 追加: ST-1「台帳のスターターは、ワークスペースの印 `.mdgrid/workspace.toml`(WS-7・WS-9・WS-10・TR-2 の中身)と、新しいノートの本文の雛形(CE-32 の `body` のファイル)と、見本のノートからなる、台帳の見せ方のひとまとまりとするべき。スターターは見せ方だけを持ち、ノートの形の決まり(スキーマ・lint)は持たないべき(ノートの形を検査する道具の役目で、mdgrid が台帳ごとの知識を持たないため)。名前と1行の説明は言語ごとに `starter.toml`(`[name]`・`[description]` に、文言の台帳と同じ言語の符号の鍵)に持ち、無ければフォルダの名前と空の説明にするべき。印と雛形は `ledger/`、見本は `samples/` に、台帳の根からの相対パスのまま置き、`ledger.<言語>/`・`samples.<言語>/` があれば、その言語のときはそれを丸ごと代わりに使うべき(重ねない)。」(確かめ方: `starters/tasks/` に `starter.toml`・`ledger/.mdgrid/workspace.toml`・`ledger/.mdgrid/templates/task.md`・`samples/tasks/Write the plan.md` → スターターとして読め、名前は ja で「タスク」、en で「Tasks」。`starter.toml` の無いユーザーのスターター → 名前はフォルダの名前、説明は空。`ledger.ja/` があり言語が ja → `ledger/` は使わず `ledger.ja/` の中身だけ。`test_st_1_*`)
- 追加: ST-2「mdgrid は組み込みのスターター `tasks`(タスク)・`bookmarks`(ブックマーク)・`reading`(読書・視聴の記録)・`people`(人・連絡先・会議メモ)を実行ファイルの中に持つべき。組み込みはユーザーのスターター(ST-3)と同じ形・同じ読み方の見本で、組み込みだけに効く特例を作らないべき。組み込みのスターターは、どの言語の変種でも、印が警告なしに読め(印の読み込み・木の設定・`open` の警告が空)、`open` が印の表を指し、見本のノートが `--check` で問題 0 になるべき。」(確かめ方: 4つの組み込みから見本つきで作る → `--print-config --resolved` の標準エラーに `mdgrid:` の行が無く、`--print` が見本の行を出し、`--check` の問題が 0。`LANG=en_US.UTF-8` でも同じ。`test_st_2_*`)
- 追加: ST-3「ユーザーのスターターは、設定の置き場(CLI-3)の `starters/<名前>/` に、組み込みと同じ形で置けるべき。一覧はユーザーのスターターを名前の順に先に、組み込みをその後に並べ、同じ名前はユーザーのものを使って組み込みを出さないべき。`mdgrid --starters` は、スターターの名前と今の言語の1行の説明を1行ずつ標準出力に出して終了コード 0 で終わり、設定の置き場が無くても組み込みを出すべき。読めないスターター(壊れた `starter.toml`・`ledger/.mdgrid/workspace.toml` の無いもの)は CLI-3 の形で警告して飛ばすべき。画面を開かず、ファイルは書かないべき。」(確かめ方: `starters/kanban/` を置く → `--starters` の先頭に kanban。`starters/tasks/` を置く → tasks は1つで、ユーザーのもの。置き場なし → 組み込みの4つ。壊れた `starter.toml` → `starters/kanban/starter.toml:` で始まる警告1行で、ほかは出る。`test_st_3_*`)

### 版1 — 作る(CLI と画面)

- 追加: ST-4「`mdgrid [<フォルダ>] --init-workspace --starter <名前> [--with-samples]` は、そのフォルダ(無ければ今のフォルダ。フォルダが無ければ作る)に、スターターの `ledger/` の中身を同じ相対のパスで書き、`--with-samples` のときは見本のノートも書くべき。見本のノートの中の `{date}`・`{date+N}`・`{now}` などは CE-32 と同じ変数として書くときに埋め、`ledger/` の中身(印と本文の雛形)はそのまま写すべき(雛形の変数は新しいノートを作るときに埋まるため)。書く先に同じパスのファイルが1つでもあれば、どれも書かずに理由を出して終了コード 2 にするべき(WS-7 と同じく上書きしない)。無い名前・2つ以上のフォルダ・`--init-workspace` の無い `--starter`・`--starter` の無い `--with-samples` は、CLI-4 と同じく理由1行と終了コード 2 にするべき。作ったファイルを1行ずつ標準出力に出し、画面は出さないべき。」(確かめ方: `mdgrid books --init-workspace --starter reading` → `books/.mdgrid/workspace.toml` と `books/.mdgrid/templates/` の雛形ができ、見本は無い。`--with-samples` と `MDGRID_TODAY=2026-10-06` → 見本の `{date-10}` が `2026-09-26` で書かれ、雛形の `{date}` は文字のまま。もう一度 → 理由1行と終了コード 2 で何も変わらない。`--starter nope` → 理由1行(`--starters` で一覧を見られることを添える)と終了コード 2。`test_st_4_*`)
- 追加: ST-5「コマンドのパレット(SR-14)の「スターターから台帳を作る」で、スターターを一覧(名前と説明。打った字で絞る)から選び、作る場所(開いたフォルダからの相対・`~`・絶対のパス。既定は開いたフォルダの下のスターターの名前)を打ち、見本のノートを入れるかを `y`/`n` で答えると、ST-4 と同じに作って、その台帳の印の `open` の表(無ければ根)を開くべき。ためた変更があれば CLI-19 と同じく保存か取りやめを確かめるべき。Esc はどの段でも取りやめにし、何も作らないべき。読むだけの起動(WB-15)ではパレットに出さないべき。」(確かめ方: `:` → 「スターター」→ 一覧に組み込みの4つ → reading を Enter → 「作る場所」の欄に `reading` が入っているのを `~/notes/books` に直して Enter → 「見本のノートも入れる?(y/n)」→ `y` → books の Reading の表が開き、パンくずに books。途中の Esc → 「やめた」で何も作らない。`--readonly` → パレットに無い。`test_st_5_*`)
- 追加: ST-6「スターターから作った台帳は、ふだんの印のあるフォルダと同じに扱い、開いて見るだけでは印・雛形・見本のバイトを変えないべき。スターターの中身は、文書にある印の項目(CLI-12)と雛形の変数(CE-32)の範囲に収め、スターターだけに効く項目を作らないべき(スターターから作った台帳と手で書いた台帳の間に差を作らないため)。」(確かめ方: 作った直後と、開いて閉じたあとの印のバイトが同じ。組み込みの印に知らない項目が無い(ST-2 の警告なしで確かめる)。`test_st_6_*`)

### 範囲外(新しい仕様に書く)

- 次の段: 今の表(印・ビュー)からスターターを書き出すこと(逆の向き)。版1 はスターターから作るだけ。
- 採らない: スキーマ・lint・ノートの形の検査(ノートの形を検査する道具の役目。ST-1)。
- 採らない: ネットからスターターを取ってくること(置き場は組み込みと設定のフォルダだけ。ST-3)。

### 前提(AI の仮定。新しい仕様に書く)

- 組み込みのスターターの印には `name` を書かない(作った先のフォルダの名前がワークスペースの名前になる。WS-7)。
- 言語の変種(`ledger.ja/` など)は丸ごとの差し替えで、`ledger/` に重ねない(見本のノートの名前が英語と日本語で混ざらないため)。英語(接尾なし)が正本。
- 呼び名: 「型」は列の型・画面の型に、「テンプレート」は CLI-3 の `[templates]` と CE-32 の雛形に使っているので、この機能は「スターター」(`starter`)と呼ぶ。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(印を手で書く・見本を写す) | 印の書き方(WS-7・WS-9・WS-10・TR-2・CE-32)は文書にあるが、初めての人が完成形にたどり着くまでが長い。見本(examples/)は手で写す物で、設定の置き場からも画面からも選べない。 |
| ノートの形(スキーマ・lint)もスターターに持つ | mdgrid は表の表示の道具(SC-1)で、台帳ごとの形の約束は別のリポの道具の役目。持つと台帳の知識が mdgrid に入り、見せ方と形の2つの正本ができる。 |
| 組み込みだけ(ユーザーのスターターは持たない) | 組み込みが特例になり、自分の台帳の形を同じ仕組みで使い回せない。設定の置き場の `starters/` に同じ形で置ける方が一般的で、組み込みはその見本になる。 |
| `workspace::init`(WS-7)の旗を変えて `--init-workspace <名前>` にする | WS-7 の `--init-workspace` は表を書かない印を作る旗で、既存の試験が形を縛っている。スターターは別の旗 `--starter` で添える方が、今の振る舞いを変えずに済む。 |
