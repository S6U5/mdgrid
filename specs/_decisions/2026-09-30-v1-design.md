# 最初の版の設計(v1-design)

## きっかけ

人が TUI の仕様書を頼んだ(2026-09-30。原文は取り込みの記録 [import-scope](2026-09-30-import-scope.md) の「表の外にあった人の記述」)。人の言葉から写せる規範は scope に取り込んだので、残りの表の組み立て・セルの編集・書き戻し・画面を、AI が次の3つの調べから起こした。(1) cellops の TUI の仕様とコードのうち、タスクに依らない部分(edit.rs の壊れ方の実測を含む)。(2) Obsidian Bases の `.base` の形式・プロパティの型・Bases の書き戻しの挙動。(3) 需要の調査の「最初の版の範囲」の見立て。調べの要点と出典は、非公開の設計ログ(research-lab `research-logs/2026-09-25-personal-lab-architecture.md` の 2026-09-30 の節、コミット 0817bdb)にある。

AI の提案なので、要件はすべて「するべき」以下で足した。書き戻しの安全に関わるものを「しなければならない」に上げる案は、別の提案(承認待ち)にした。

AI の自己採択。守られる要件(人の決定)は触らない。次の決めるモードの束の末尾に、事後確認として並べる。

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(scope だけで作り始める) | 書き戻しの規則が無いまま作ると、cellops の edit.rs と同じ壊し方(ブロックリスト・ネスト・キーの重複)を繰り返す |
| cellops の edit.rs を行単位の置換のまま流用する | 実測でブロックリスト・ブロックスカラー・ネストした map・キーの重複を壊す |
| Obsidian と同じく、フロントマター全体を読み直して出力し直す | コメント・引用符・フロー形式が変わる。1バイトも変えない書き戻しがこの道具の差別化の芯 |
| `.base` の未対応の式を無視して、評価できる部分だけで行を作る | 利用者が気づかずに違う行を見て直してしまう。正直に未対応と出す(BV-7) |
| 見た目の状態をノートのフォルダ(`.fmgrid/`)に置く | 他人の保管庫に書かない。更新時刻や git の差分と干渉する(cellops ADR-0018 の理由) |
| 列挙値の候補を設定ファイルで宣言させる | 設定なしで動く方が先。Obsidian も既存の値から候補を出す。宣言は次の段で足してよい |
