# 色の上書き [colors] と値の色、カタログの色の欄、透けない札 solid(colors)

## きっかけ

人が、色味のカスタマイズは無いのかと尋ね、AI が示した3つ(テーマの役割ごとの色の上書き、値ごとの色、カタログの色の選択の欄)を採用すると言った。あわせて、タグの札が半透明(淡い地)なので、透けない版も欲しいと言った(会話 2026-10-09 の要約)。人の依頼を AI が要件の文に起こした。値ごとの色は、状態の意味の色が英語の語にしか付かない(SR-23 でコードに日本語の語を置かない)問題も、設定で解く。

## 差分

- 変更: SR-36 旧「設定の `[style]` で、表と窓の部品の形を選べるべき: くり返す短い値(`status`: `dot`・`shape`・`text`・`pill`・`tint`・`soft`・`chip`・`plain`)、リスト(`tags`: `dots`・`hash`・`brackets`・`pill`・`tint`・`soft`・`chip`・`plain`)、真偽(`check`: `box`・`tick`・`bracket`・`text`)、選び(`select`: `bar`・`cross`・`tint`・`outline`・`fill`・`reverse`)、区切り(`rules`: `none`・`header`・`columns`・`grid`)、ビューのタブ(`tabs`: `underline`・`pill`・`segment`・`brackets`・`dim`)、窓の枠(`frames`: `rounded`・`square`・`heavy`・`ascii`・`none`)、下の帯(`band`: `keys`・`boxed`・`quiet`)、列の見出しの型の印(`icons`)。`[style]` の `preset` に組の名前(`sumi`・`slate`・`saas`・`paper`・`grid`・`classic`)を書けば部品をまとめて選び、ほかの項目はそれを上書きする。既定は `sumi`(点と文字・`·` で区切るタグ・`✓`・左の線の選び・見出しの下の線・下線のタブ・角の丸い枠・薄い下の帯・印なし)。`pill` は Nerd Font の字を使うので、`nerd_font = true` のときだけ使い、そうでなければ `soft` で描くべき。今までの `borders = "ascii"` は `frames = "ascii"` として受けるべき。知らない値は警告して既定にするべき。」→ 新「設定の `[style]` で、表と窓の部品の形を選べるべき: くり返す短い値(`status`: `dot`・`shape`・`text`・`pill`・`tint`・`solid`・`soft`・`chip`・`plain`)、リスト(`tags`: `dots`・`hash`・`brackets`・`pill`・`tint`・`solid`・`soft`・`chip`・`plain`。`solid` は値の色をそのまま地に塗った、透けない札)、真偽(`check`: `box`・`tick`・`bracket`・`text`)、選び(`select`: `bar`・`cross`・`tint`・`outline`・`fill`・`reverse`)、区切り(`rules`: `none`・`header`・`columns`・`grid`)、ビューのタブ(`tabs`: `underline`・`pill`・`segment`・`brackets`・`dim`)、窓の枠(`frames`: `rounded`・`square`・`heavy`・`ascii`・`none`)、下の帯(`band`: `keys`・`boxed`・`quiet`)、列の見出しの型の印(`icons`)。`[style]` の `preset` に組の名前(`sumi`・`slate`・`saas`・`paper`・`grid`・`classic`)を書けば部品をまとめて選び、ほかの項目はそれを上書きする。既定は `sumi`(点と文字・`·` で区切るタグ・`✓`・左の線の選び・見出しの下の線・下線のタブ・角の丸い枠・薄い下の帯・印なし)。`pill` は Nerd Font の字を使うので、`nerd_font = true` のときだけ使い、そうでなければ `soft` で描くべき。今までの `borders = "ascii"` は `frames = "ascii"` として受けるべき。知らない値は警告して既定にするべき。」
- 変更: SR-38 旧「リポの `docs/catalog/index.html` に、部品の形とテーマを見本の表と関係マップで見比べて選び、その設定(`config.toml` に貼れる文)を作れるカタログを置くべき。カタログが出す設定の項目と値は、本体の設定(SR-36・SR-37・SR-26)が受けるものと同じにし、ずれたら試験で落とすべき。カタログは1つのファイルで、外の何にも頼らず開けるべき。」→ 新「リポの `docs/catalog/index.html` に、部品の形とテーマを見本の表と関係マップで見比べて選び、その設定(`config.toml` に貼れる文)を作れるカタログを置くべき。カタログでは色の役割(SR-40)と値の色(SR-41)も選べ、その設定の文も作れるべき。カタログが出す設定の項目と値は、本体の設定(SR-36・SR-37・SR-26・SR-40)が受けるものと同じにし、ずれたら試験で落とすべき。カタログは1つのファイルで、外の何にも頼らず開けるべき。」
- 追加: SR-40(節「要件」)「設定の `[colors]` で、テーマ(SR-26)の色のうち役割ごとに色を上書きできるべき: `background`(地)・`text`(文字)・`header`(1行目)・`selection`(選んだ行の地)・`selection_text`・`band`(下の帯の地)・`band_text`・`accent`(見出し・キー・枠)・`strong`(強調)・`zebra`(一行おきの地)・`zebra_text`・`mark`(左端の印)・`added`(足した行)・`removed`(消した行)・`pending`(ためた変更)・`highlight`(検索の一致の地)。色は `"#rrggbb"`・`"#rgb"` か、色の名前(`black`・`white`・`gray`・`red`・`orange`・`yellow`・`green`・`teal`・`cyan`・`blue`・`purple`・`magenta`・`pink`・`brown`)で書く。上書きしなかった役割はテーマの色のまま。テーマが `default`(色の表なし)のときは、端末の地と文字は変えず、`accent`・`selection` と値の色(SR-41)だけを使うべき。色を使わない表示では効かない(SR-10)。知らない役割と読めない色は警告して無視するべき。」(確かめ方: `theme = "sumi"` と `[colors] accent = "#e0a458"` → 列の見出しと下の帯のキーが #e0a458、地は sumi のまま。`accent = "orange"` → 名前の色。`accent = "#zz"`・`foo = "red"` → 警告して無視。`--no-color` → 効かない(`test_sr_40_*`))
- 追加: SR-41(節「要件」)「設定の `[colors.values]` で、値ごとの色を決められるべき(キーは値の文字、値は SR-40 と同じ色の書き方)。決めた値は、部品(SR-36 の `status`・`tags` のどの形でも、窓の候補でも)でその色を使い、決めていない値は今までの色(状態の語の意味の色か、値の文字から決まる色)のまま。値の文字の照合は前後の空白を除き、大文字・小文字を区別しない。日本語の値にも色を付けられる。」(確かめ方: `[colors.values] "進行中" = "#d6a85c"` → status が 進行中 の点・札がその色。`Done = "green"` → done の札が緑(大文字・小文字によらない)。決めていない値 → 今までの色。読めない色 → 警告して無視(`test_sr_41_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| テーマのファイルを別に書かせる | 色を1つ変えたいだけのときに重い。役割ごとの上書きで足りる |
| 状態の日本語の語の表を本体に持つ | SR-23(コードに日本語のリテラルを置かない)とぶつかる。値の色の設定で解く |
