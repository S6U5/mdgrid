# 日付と数の入力でも、開いた直後に打つと今の値を置き換える(type-replaces-date-number)

## きっかけ

会話 2026-10-06 の改善の繰り返しで、3回目の点検(docs/todo.md の A-3・A-4)が、日付のセルで入力の案内どおり `+3` と打つと `2026-10-05+3` で弾かれ、数のセルで `5` と打つと `15` になると指摘した。入力は今の値で始まり、打った文字が後ろに足されるため。CE-3 のリストはもう置き換える(list-type-replaces)。日付と数もそろえる。

## 差分

- 変更: CE-5 旧「日付の列は `YYYY-MM-DD` と、今日からの日数(`+3`)と、空(値を消す。キーは残して null と書く。CE-9)を受け付け、実在しない日付は受け付けるべきでない。」→ 新「日付の列は `YYYY-MM-DD` と、今日からの日数(`+3`)と、空(値を消す。キーは残して null と書く。CE-9)を受け付け、実在しない日付は受け付けるべきでない。入力を開いた直後に文字を打ったときは、`+3` が今日からの日数として読めるよう、今の日付の続きでなく打った文字から入力を始めるべき。」(確かめ方: `2026-02-30` → 閉じずに不正を表示。空で確定 → `due:` の行が残る(`test_CE_5`)。`due: 2026-10-05` のセルで Enter のあと `+3` → 今日の3日後(`test_ce_5_type_replaces_*`))
- 変更: CE-7 旧「数値の列は、数として読める値だけを受け付けるべき。」→ 新「数値の列は、数として読める値だけを受け付けるべき。入力を開いた直後に文字を打ったときは、今の数の続きでなく打った文字から入力を始めるべき。」(確かめ方: `12a` → 閉じずに不正を表示(`test_CE_7`)。`priority: 1` のセルで Enter のあと `5` → 5(15 ではない)(`test_ce_7_type_replaces_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 案内の例が通らず、数の誤りがためる変更になる |
| 入力を空で始める | 今の値を少し直したいとき(← → で動かして直す)に打ち直しが要る。開いた直後の最初の文字だけ置き換えれば両方できる |
