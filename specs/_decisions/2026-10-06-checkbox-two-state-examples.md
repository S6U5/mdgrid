# チェックボックスの真と偽の切り替えを、一括と元に戻す例にも書く(checkbox-two-state-examples)

## きっかけ

会話 2026-10-06。人がおすすめどおりと承認した checkbox-two-state(CE-4 を真と偽の切り替えにする)を入れると、その振る舞いを一括の切り替え(CE-10)と元の値に戻す(WB-17)の場面で確かめる試験も変わる。要件の文は変わらないが、確かめ方の例に2つの状態の切り替えを書き、試験が確かめることと仕様の例をそろえる。人の依頼を AI が要件の例に起こした(要件の文は変えない)。

## 差分

- 変更: CE-4 旧「チェックボックスの列は、1回の操作で、真と偽を切り替えるべき(Obsidian のチェックボックスと同じ手触りにするため)。値が空かキーの無いノートでは真にするべき。空(CE-9 と同じく `key:`)にするのは、空にする操作(BS・Delete)だけにするべき。」→ 新「チェックボックスの列は、1回の操作で、真と偽を切り替えるべき(Obsidian のチェックボックスと同じ手触りにするため)。値が空かキーの無いノートでは真にするべき。空(CE-9 と同じく `key:`)にするのは、空にする操作(BS・Delete)だけにするべき。」(確かめ方: `done: false` のセルで Enter → `done: true`。`done: true` で Enter → `done: false`。キーの無いノートで Enter → `done: true`、もう一度 → `done: false`。`done:` の空のセルで Enter → `done: true`。BS → `done:`。全部の行を選んで Enter → 今の行の次の状態(true の次は false、ほかは true)が全部の行に入る(CE-10)(`test_ce_4_two_state_*`))
- 変更: CE-10 旧「選んだ複数の行の同じ列に、同じ値を、ためる変更としてまとめて入れられるべき。選んだ行のうち、その列のセルを直せない行(読むだけのノート(WB-5)と、読むだけのセル(CE-8・CE-12))と、チェックボックスの列の一括の切り替え(CE-4)で、ためた変更が無く値の型が合わない行(CV-2。1行なら入力を開く行)は飛ばし、飛ばした数と理由を知らせるべき(元の値を黙って消さないため)。」→ 新「選んだ複数の行の同じ列に、同じ値を、ためる変更としてまとめて入れられるべき。選んだ行のうち、その列のセルを直せない行(読むだけのノート(WB-5)と、読むだけのセル(CE-8・CE-12))と、チェックボックスの列の一括の切り替え(CE-4)で、ためた変更が無く値の型が合わない行(CV-2。1行なら入力を開く行)は飛ばし、飛ばした数と理由を知らせるべき(元の値を黙って消さないため)。」(確かめ方: 3行を選び status に done → 3つのためる変更、保存前の差分に3ファイル。3行のうち1行が読めないフロントマターのノート(WB-5) → 2つのためる変更と「1行を飛ばした(理由)」。フロントマターの無いノートは飛ばさず、ためる変更になる。a `done: true`・b `done: yes` を選んで切り替え → a だけ `done: false`、b はそのままで「1行を飛ばした(型が合わない)」。チェックボックスの列で全部を選んで切り替え → 今の行の次の状態(true の次は false、ほかは true)を全部の行にそろえ、元と同じになる行は外す(WB-17)(`test_CE_10`))
- 変更: WB-17 旧「ためた値が、そのセルの最後に読んだ値と同じになったら(直して元の値に戻した、一括の設定で元と同じ値を入れた、など)、そのセルをためる変更から外し、未保存の数・保存の差分・ためる変更の印に出すべきでない。戻したつもりでも書き戻すと書式やクオートが変わりうるので、元の値に戻したセルは書くべきでない。外す操作も取り消し・やり直しの1手にするべき。」→ 新「ためた値が、そのセルの最後に読んだ値と同じになったら(直して元の値に戻した、一括の設定で元と同じ値を入れた、など)、そのセルをためる変更から外し、未保存の数・保存の差分・ためる変更の印に出すべきでない。戻したつもりでも書き戻すと書式やクオートが変わりうるので、元の値に戻したセルは書くべきでない。外す操作も取り消し・やり直しの1手にするべき。」(確かめ方: `status: todo` を done に直す → 「未保存 1」。もう一度 todo に直す → 「未保存 0」で、セルに `*` が無く、Ctrl+S は「変更は無い」。`u` → done に戻って「未保存 1」。クオートの無い日付 `due: 2026-09-30` を別の日付にしてから 2026-09-30 に戻して保存 → ファイルは1バイトも変わらない。数の列の `3` に 3 を入れる → ためない。数の `3` と文字の `"3"` は違う値として扱う。`done: false` のチェックボックスで Enter を2回 → true から元の false に戻って「未保存 0」(`test_WB_17`))

## 却下した案

| 案 | 理由 |
|---|---|
| 例を変えない | 一括と元に戻す場面の試験が、仕様の例に無い振る舞いを確かめることになる |
