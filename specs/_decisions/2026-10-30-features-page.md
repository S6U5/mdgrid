# 説明書とサイトに「できることの一覧」のページを置く(features-page)

## きっかけ

「見せ方の一覧」(SR-49)を公開したあと、人が、画面の型の一覧とは別に、mdgrid にどんな機能があるかを1つのページで見たいと言った(会話 2026-10-30)。今は機能の説明が README の「できること」の段落と手引き(tasks.md)に散らばっていて、サイトで機能を見渡せるページが無い。

## 差分

- 追加: SR-51「リポの説明書(`docs/manual/<言語>/features.md`。サイトでは説明書の1章で、見せ方の一覧の次)に、できること(機能)の一覧のページを置くべき。1つの機能につき、本物の画面の画像1枚(`docs/manual-scenarios.toml` の場面)と、何ができてどう始めるかの説明と、くわしい節へのリンクを並べる。載せる機能は少なくとも、値をその場で直す・差分を見て保存する・まとめて直す・探す/絞る/並べる・新しいノートを作る・ビューを決めて保存する・`.base` を開く・リンクで表をつなぐ・スターターから台帳を作る・ほかのコマンドと組む・読むだけで開く・見た目を選ぶ。サイトの入口(`scripts/pages.py` の「見て選ぶ」)からこのページへ行けるべき。機能を足す変更は、この一覧に1項を足すべき。」(確かめ方: `docs/manual/ja/features.md` と `docs/manual/en/features.md` があり、画像が全部場面の id で、上の 12 の機能それぞれの節に画像1枚とくわしい節へのリンクがあり、相対のリンク先が全部ある(`test_sr_51_*`)。`scripts/pages.py` の `PAGES` で `features.md` が `views.md` の直後にあり、入口の文言に一覧へのリンクがある(`test_sr_51_*`)。機能を足した変更の記録で、この一覧に項が無い → 違反(読んで判定))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない(README の「できること」と手引きで足りる) | README はリポの顔で、サイトの説明書からは見えない。手引きはやりたいことから引く形で、機能を見渡す形ではない。 |
| 「見せ方の一覧」に機能も混ぜる | 見せ方(画面の型)と機能(できること)は読む目的が違う。混ぜると一覧が長くなり、どちらも探しにくい。 |
| 画面の一覧(gallery)に札を付けて絞る | 読む順と機能ごとの説明が無く、一覧として読めない(SR-49 と同じ理由)。 |

## 承認の記録

2026-10-30 人の承認(要約: どういう機能があるかは、画面の一覧とは別のページでサイトに載せる)
