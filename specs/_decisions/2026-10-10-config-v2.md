# 設定の形を作り直し、アプリ全体の項目と表のプロファイルに分け、重なる項目をまとめる(config-v2)

## きっかけ

人が、テーブルごと・ワークスペースごとに見た目を変えたいと言い、あわせて設定を広げやすい形にして今の不整合を直したい、今のうちに綺麗に組み直したい、変える手間は問わないと言った(会話 2026-10-10)。AI が今の設定を調べ、同じことを決める項目の重なり(`borders` と `frames`、`[cells]` と `[style]` の印と部品、`view_tabs` と `[display] tabs`、最上位の `search_bar`、`theme` と `theme_light`・`theme_dark`、config.toml と look.toml)、性質の違う項目が最上位に混ざっていること、警告と表を指す書き方がファイルごとに違うことを示した(specs/_changes/2026-10-10-config-v2.md の「調べたこと」)。人は、旧い書き方は読んで移す・錠は掛け直してよい・上書きは4段・上書きできるのはプロファイル全部、を選んだ。範囲ごとの上書きは別の提案(scope-overrides)で、この提案はその土台の形を決める。人の依頼を AI が要件の文に起こした。

## 却下した案

| 案 | 理由 |
|---|---|
| config.toml を、注釈を保つ書き方で画面から直接書き換え、ui.toml を作らない | 人が書いた注釈と並びを壊すおそれがあり、手で書いた設定と画面の操作が混ざる。別のファイルなら消せば元に戻る(look-section と同じ理由) |
| 旧い名前を読まない(知らない項目の警告だけ) | 0.3.0 の設定が黙って効かなくなる。人は読んで移すほうを選んだ |
| 今の最上位の並びのまま、範囲で上書きできる項目の一覧を別に持つ | どれが範囲で変えられるかがファイルの形から見えない。区画で分ければ、範囲のファイルに書ける区画がそのまま分かる |
| `[cells]` を残し、`[look.style]` の部品の形と両方で決める | 同じ部品を2か所で決めると、どちらが勝つかを覚える必要がある。部品の形の `plain` で足りる |
| `places.toml` を `workspaces.toml` に混ぜる | しおり(開く入口)とワークスペース(リンクと関係マップの範囲)は役目が違う |

## 錠

この提案で触る要件の試験のうち、項目の名前や設定の形(`Config` の欄)に触れる錠のある試験は、採択のあと、対象の試験を並べた錠の掛け直しの記録(config-v2-locks)で掛け直す(人の決定 Q2)。
