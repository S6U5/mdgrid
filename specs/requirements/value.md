# 価値(value) の要求

## 目的

mdgrid がなぜ要るかを言う。ここの要求は、1つの機能ではなく、いくつもの機能にまたがる価値で、機能の案と変更を測る物差しとして使う。ほかのファイルは機能の要求(何を作るか)で、`Rationale:` からここの名前(`value.keyboard` など)を指してよい。

価値の要求の受け入れ基準は、「機能の案がこの価値を損なうなら、直すか採らない(読んで判定)」の形で書く。自動のテストでは守れないので、PR を見る人が読んで守る。数で確かめられる所が決まったら(メモリの上限・切り替えの時間)、測って確かめる受け入れ基準を足す。

要求を足す・変える・消すときは、PR で人がレビューして承認する(AI だけで要求を変えない)。要求の文の「しなければならない・するべき・してよい」の読み方は [README.md](README.md)。2026-11-27 に、人の発言から足した。

## 範囲外

- 機能の要求(どの画面で・どのキーで・どのファイルに何をするか)は、能力ごとのファイルに書く。ここには書かない。
- 道具の芯と最初の版の範囲(何を入れ、何を入れないか)は [scope](scope.md)。

## 要求

### 台帳の仕事は、端末から出ずに終えられるべき
`req~value.in-terminal~1` P1
- Rationale: GUI のアプリを開くのは疲れる。CLI のコーディングエージェントを使っているときは、端末のマルチプレクサの隣の区画で、同じ端末のまま台帳を開ける
- Acceptance:
  - Given: 機能の案が、その機能を使うのに端末の外の窓やアプリを開くことを求める
  - When:
  - Then: この価値を損なうので、端末の中で終えられる形に直すか、採らない(読んで判定)。

### どの操作も、キーボードだけで手を止めずにできるべき
`req~value.keyboard~1` P1
- Rationale: キーボードの操作で効率よく作業することが、この道具の目的だから
- Acceptance:
  - Given: 機能の案が、マウスでしかできない操作を持つ
  - When:
  - Then: この価値を損なうので、キーだけでできる道を足すか、採らない(読んで判定)。

### 画面は、説明を読まなくても見て分かり、操作できる表を土台にするべき
`req~value.intuitive-table~1` P1
- Rationale: キーボードで速く操作できても、利用者が直感で見て操作できる表でなければ使われないから
- Acceptance:
  - Given: 機能の案が、説明書を読まないと、何が見えていて次に何ができるかが分からない画面を足す
  - When:
  - Then: この価値を損なうので、見て分かる形に直すか、採らない(読んで判定)。

### ノートのあいだのつながり(リレーション)は、どの画面でも見失わないようにするべき
`req~value.relations-visible~1` P1
- Rationale: AI を使って作業していると、ノートのあいだのつながりをつい見失うため
- Acceptance:
  - Given: 機能の案が、ノートを指す値を持つ行を見せるのに、指す先を見ることもたどることもできない
  - When:
  - Then: この価値を損なうので、つながりを見てたどれる形に直すか、採らない(読んで判定)。

### 仕事の場(表・ワークスペース)は、速く切り替えられるべき
`req~value.fast-switch~1` P1
- Rationale: ほかの道具より速く、仕事の場を切り替えられるようにするため
- Acceptance:
  - Given: 機能の案が、別の表やワークスペースへ移るのに、mdgrid を終えて起動し直すことを求める
  - When:
  - Then: この価値を損なうので、終えずに切り替えられる形に直すか、採らない(読んで判定)。

### 人や自分のノートを壊さないと信じて保存でき、他の人と共同で使える基盤にするべき
`req~value.trust-notes~1` P1
- Rationale: 他の人のノートやフォルダを壊さないことが、この道具の信用の芯になる。他の人と共同で使える基盤として育てたい
- Acceptance:
  - Given: 機能の案が、直した値のほかのバイトを変える・外で入った変更を知らせずに上書きする・既にあるファイルを確かめずに置き換える、のどれかをする
  - When:
  - Then: この価値を損なうので、壊さない形に直すか、採らない(読んで判定)。

## 未確定事項

### 使うメモリの上限をいくつにするか
`tbd~value.memory-budget`
- Decider: 人
- Provisional: 数は決めていない。限られたスペックの PC で、Electron などを使った GUI より少ないメモリで動くことが目的(人の発言、2026-11-27)。ノートの数と上限の数(MB)が決まったら、要求にする

### 表やワークスペースの切り替えにかけてよい時間
`tbd~value.switch-time`
- Decider: 人
- Provisional: 数は決めていない。value.fast-switch は「速く」を読んで判定する。何秒以内かが決まったら、測って確かめる受け入れ基準を足す
