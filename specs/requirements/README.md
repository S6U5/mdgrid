# mdgrid の要求

mdgrid は、Markdown のノートのフロントマターを表として見て直す端末の道具。この置き場は、何を作るか(what)の正本で、能力ごとに1つのファイルに、要求を1行1件で書く(trace-gate の形)。どう作るか(how)は `docs/design.md` に置き、ここと重ねて書かない。

要求を足す・変える・消すときは、PR で人がレビューして承認する(AI だけで要求を変えない)。テストは印 `// [utest -> req~名前~版]` で要求を指し、`python3 tools/trace_gate.py check` が要求と印を突き合わせる。書き方は trace-gate の write-requirement と write-tests のスキル。

## 能力の地図

## 読み方

- 優先度: P0 はデータの消失・ファイルの壊れ(書き戻しでほかのバイトを変える・外の変更を上書きする・既にあるファイルを置き換える)に当たるものだけ。P1 はふつう。P2 は旧い仕様の「次の段」で、まだ作っていないもの。
- 要求の文の強さは、旧い仕様の読み方を引き継ぐ: 「しなければならない」= 例外なし、「するべき」= 理由があれば外してよい、「してよい」= 任意。
- 受け入れ: の後ろは、確かめ方の具体例。「(読んで判定)」は、自動のテストでなく人が読んで確かめるもの。
- 文の中の `cell-edit.rules` のような名前は、ほかの要求を指す(`req~` と版を省いた形)。
