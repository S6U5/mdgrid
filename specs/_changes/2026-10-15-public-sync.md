## 要求

会話 2026-10-15(ラボの運用のプロジェクト)で、人が、手元のリポと公開リポ S6U5/mdgrid の履歴が分かれているので、これからクラウドの側(Dependabot のルーチンなど)も公開リポを触る前提で、両方が食い違わない運用に整えるよう頼んだ。やり方は任された。手元の履歴は壊さない。force push と履歴の書き換えはしない。公開リポの main へのマージと push は人に確かめる。

終わりの条件: 手元の変更を公開リポへ渡す手順と、公開リポだけにある変更を手元へ取り込む手順が道具になり、どちらの取りこぼしも1つのコマンドで見え、運用が文書にある。関係する要件: 該当なし。

## 不明点と仮定

- 仮定: 手元の履歴は公開しない(decidespec の OM-17。会話の記録の場所が承認の証拠に入っている)。だから2つの履歴は1つにしない。公開リポは別名の remote `github` で取ってくるだけにし、手元のブランチを公開リポへ push しない。外れたら: 手元の履歴を公開してよいと人が決めたら、remote を origin にして普通の push と pull にする。
- 仮定: 伏せ字は、今の公開リポにある形に合わせる(承認の証拠の場所 → `〔伏せ字: 会話の記録の場所〕`、手元のパス → `〔伏せ字: 手元のパス〕`)。伏せる手元の名前は公開しないので、道具には書かず、手元の git の設定に置く。
- 仮定: 最初の公開のときに手で伏せた所(人の言い回し)は、手元の記録でも伏せてある(伏せ字にした手元の基準と公開リポの main の差で確かめた)。だから書き出す木は、伏せ字にした手元の木そのものでよい。外れたら: 手元の記録の側を `〔伏せ字: 理由〕` に置き換える。

## 設計

- 道具 `scripts/public_sync.py`(python3 の標準ライブラリと git・gh だけ)。設定と印は手元の `.git/` の中だけに置く(git の設定 `publicsync.*` と ref `refs/public-sync/*`)。
- 2つの印: `refs/public-sync/github`(公開リポの main で、手元に反映済みと数えた所まで)と `refs/public-sync/local`(最後に書き出した手元のコミット。次の書き出しの基準)。
- 書き出し(`export`): 公開リポの main の未反映が無いこと(取り込み済み)を確かめてから、伏せ字にした手元の main の木を、公開リポの main(または同じ名前の書き出しのブランチ)の上の1つのコミットにし、`export/<名前>` のブランチへ push する。手元の main の履歴は push しない。結果の木の全体に、伏せ忘れ(承認の証拠の ID・手元の名前)が無いかを確かめてから push する。公開リポの側で入った伏せていない承認の証拠(クラウドのセッションの分)も、この木では伏せ字になる。
- 取り込み(`import`): 公開リポの main の未反映のコミットを `git cherry-pick -x` で手元の今のブランチへ入れる。`-x` の行が、取り込み済みの印になる。
- 印の進め方: 各コマンドの最初に、公開リポを fetch し、`refs/public-sync/github` の先のコミットを順に見て、PR の head が `export/` なら書き出しの反映(その書き出しの手元のコミットへ `refs/public-sync/local` を進める)、手元の main に `cherry picked from commit <sha>` があれば取り込み済み、どちらでもなければそこで止める。
- 手元の pre-push のフック: 公開リポへの push で、手元の main の根のコミットを含む履歴を送ろうとしたら止める。
- 却下した案: 公開リポを origin にして手元の履歴をそのまま push する(OM-17 に反する)。書き出しを、前回の書き出しを基準にした三方向のマージにする(初めはこれで作ったが、公開リポの側で作り直された specs の生成の区画が毎回ぶつかり、誤って入った __pycache__ も消せない。取り込みを先に済ませる決まりにすれば、伏せ字にした手元の木そのものを書けば足りる)。
