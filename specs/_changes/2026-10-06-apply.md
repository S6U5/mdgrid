## 不明点と仮定

- 仮定: 形はファイルの中身で決める(最初の空白でない文字が `[` なら JSON、ほかは CSV)。JSON は `--print --format json` の形(オブジェクトの配列)。
- 仮定: `path` は `--with-path` と同じ形(起動の引数のフォルダ(`.base` ならそのフォルダ)からの相対か、絶対のパス)。実体のパスで行を引く。
- 仮定: 見出しは、開いたビューの列の id か表示名(`.base` の displayName)。ビューに無い名前は、ノートのキーとして読む。
- 仮定: 値の読み方は画面の入力と同じ(列の型ごと。日付は `YYYY-MM-DD` など)。JSON の数・真偽・null・文字列の配列はその型のまま。
- 仮定: `--apply` は `--print`・`--pick` と一緒に使えない。`--yes` は `--apply` が要る。

## 設計

- 読み取り: JSON は serde_json(依存を1つ足す)、CSV は RFC 4180 の小さな読み手を main 側に。
- 当て方: ノートを全部読み、`Changes::set`(lock を見て Skip)で値をためる。今の値と同じ・キーの無いノートへの null は飛ばす。理由が1つでもあれば書かずに終了コード 2。
- 出力: 既定は `Changes::previews` の前後を ui::diff で `-`/`+` の行にして出す。`--yes` なら `Changes::save` で書き、書いたファイルを1行ずつ。外で変わって止めたものは理由と終了コード 1。

## 実装の気づき

- 書込なしのフレッシュ文脈のレビュー役が、書き出したまま戻しても値を書き直す形を見つけた(テキストの列の true・2026・1.0 が文字に、\`""\`・\`" "\` が null に、\`, \` を含む要素が分かれる、64ビットを超える整数が小数に)。examples/vault は型の合わない値(someday・高)と入れ子の値で、戻すだけで終了コード 2。どれも「列の型で読み直してから同じかを比べる」ためだった。
  - 直し: 今の値を \`--print\` と同じ形(CSV の文字・JSON の値)にして、読んだセルと同じなら何もしない(型の読み直しも、読むだけの確かめもしない)。違うセルだけを列の型で読む。
  - ほかの指摘も直した: 表示名と別の列の id が同じ見出し・同じ見出しが2つ・ビューにもノートにも無い見出し(打ち間違いでキーを足していた)・同じノートの同じ列を2回・渡したフォルダごとに別のノートに当たる path は理由(終了コード 2)。\`, \` か前後の空白を含む要素のリストは CSV から直さない(JSON は直せる)。日付は \`YYYY-MM-DD\` だけ(\`+3\` は当てる日で変わる)。CSV の囲んだ欄の CRLF を LF に、行の番号はファイルの行に。理由の文は Debug の形でなく、画面の保存の確認と同じ文に。
  - 残したもの: 書いている途中でノートが外で変わると、書き終えたノートはそのまま(終了コード 1)。全部を書く前にもう一度確かめても、確かめと書き込みの間は残るので、README に書いた。
- 錠のある src/test_main.rs は Command::Print の形を作らないので、Command::Apply を足しても影響しない。
