## 要求

人の指示(会話 2026-10-31): 画面の型の順を変えてガントチャートを先に作る。WBS(親子の字下げ・`1.2.1` の番号・進み具合)をそのままガントで見られること。ガントのあとに、おすすめの図(カンバン・カレンダー・マトリクス・集計の棒グラフ)も同じ仕組みで足す。なぜ: サイトの一覧を見た人が、ガントが無いことに気づいた。何ができたら終わり: 印の `gantt = { start, end }`(無ければ日付の列から推定)で、`C` か画面の型のメニューからガントが開き、今のビューの行(親子・WBS の並びのまま)が時間軸の横棒で見え、`Enter` で表のその行に戻れる。tasks のスターターにガントの設定と `start` の列が同梱され、見せ方の一覧に画像つきの項がある。関係する要件: GA-1〜GA-7(新)、SC-9(別の画面の型として足す)、REL-8(画面の型のメニュー)、TR-1〜TR-7(木。手本)、NV-27(親子・WBS)、SR-15(色なし)、SR-22(キーの文書)、SR-45(画面の型の記号)、SR-49・SR-51(一覧に1項)。

## 不明点と仮定

- ガントのキー → `C`(chart)。`G` は表の最後の行。仮定: 以後の型も表のモードの空きの大文字(`B` カンバン・`D` カレンダー・`M` マトリクス)。外れたら: キーの割り当てだけ変える。
- 推定の規則(GA-1)の名前の一覧は固定。仮定: 日本語の列名(開始・期限・終了)も含める。外れたら: 一覧に足す。
- 親の棒(GA-3): 親に自分の日付があればそれ、無ければ子孫の範囲。仮定: 人は「WBS を見る」を求めたので、親の棒が子を包む形が要る。
- 時間軸の既定の単位(GA-2): 開くときに範囲が幅に収まる最も細かい単位(日 → 週 → 月)。仮定: 範囲が無い(行が1つも日付を持たない)ときは今日を中心に日の単位で開き、「日付の列が無い」の理由を出す場面と分ける。
- 行の木(GA-3)の取り方: 表のビューの設定(NV-27 の tree.rs)が作る親子の順をそのまま使う(止める: その関数がガントから呼べる形でなければ、設計で切り出す)。調べ物の結果(項目 11)で決める。
- 画面の型の設定の形(GA-7): 印の `[[table]]` の `tree`・`gantt` の読み方を1つの形(型の名前 → 列の名前の表)にそろえる。仮定: 今回は `gantt` の読みを `tree` と同じ形で書き、共通化は読みの補助関数の範囲にとどめる(WsTable に欄を足さない。docs/design.md:617 の決まり)。

## 設計

木(TR)と同じ仕組みで足す: 印の設定 → 画面の型のメニュー → 画面のモジュール。画面の型の登録の仕組みは無く、型ごとに十数か所を手で分けているので(調べ物 2026-10-31)、木が触った所を全部なぞる。

- 核(画面に依存しない) `src/gantt.rs`(新。lib.rs に `pub mod gantt`): `GanttSpec { start: Option<String>, end: Option<String>, days: Option<String> }`、推定の名前 `START_NAMES`(start・begin・from・開始)・`END_NAMES`(end・due・finish・until・to・期限・終了)、`infer(cols: &[(String, bool)]) -> Option<GanttSpec>`(列の名前と日付の列かの組から。大文字小文字を問わず、始まりか終わりのどちらかが無ければ None)、`Unit { Day, Week, Month }`(`finer`・`coarser`)、`fit_unit(first, last, cols) -> Unit`(範囲が幅に収まる最も細かい単位)、`floor_unit(day, unit)`(週は月曜、月は1日)、`cell_of(day, origin, unit) -> i64`・`cell_start(k, origin, unit) -> i64`(マスと日の往復)、`Bar { start: Option<i64>, end: Option<i64> }`(1970-01-01 からの日数)と `Bar::from_values(start, end, days)`(`days` は始まりからの日数。終わりが無ければ start+days-1)、`Bar::is_point`、`Bar::span(&[Bar])`(子の範囲)。日付の読みは `types::parse_date`。
- 印の読み `src/workspace.rs`: `marker_gantt(opened) -> (Option<(GanttSpec, String)>, Vec<String>)` と `read_gantt`。`marker_tree` の表の選び方を `marker_setting(opened, key, read)` に切り出して両方から使う(TR-2 の錠のある試験は `marker_tree` の名前と振る舞いのまま)。設定は `start`(必須)と `end` か `days`(どちらか必須)。表でない → RsnGanttNotTable、start 無し → RsnGanttNeedStart、end も days も無し → RsnGanttNeedEnd、知らないキー → RsnUnknown、列が表に無い → RsnGanttNoColumn(読み終えてから `check_gantt_column`)。`read_tables` の skip の表(base と path の2か所)に "gantt" を足す。WsTable・Scope に欄は足さない(docs/design.md の決まり)。
- App(`src/ui/app.rs`)の欄: `gantt_spec: Option<(GanttSpec, String)>`(印から。startup.rs で `marker_gantt`)、`gantt: Option<Gantt>`(開いている間)。
- 画面 `src/ui/gantt.rs`(新。`impl App` の続き): `Gantt { rows: Vec<RowId>, sel, unit, origin: i64, spec: GanttSpec, inferred: bool }`。行は `self.rows` のうち `under_folded` でないもの(親子の並び・畳みは表のまま。NV-27)。深さは `self.tree`、番号は `self.wbs_num`、割合は `self.wbs_pct`。`gantt_bar(row)`: 自分の日付(`App::plain` を `parse_date`)があればそれ、無く子を持てば子孫の棒の `span`。`gantt_spec()`(印の設定があり列が揃えばそれ、無ければ `infer`)、`gantt_ready()`、`open_gantt`(GanttNotSet・GanttNoRows の理由)、`close_gantt`、`rebuild_gantt`(外の変化。app.rs の `rebuild_tree` の隣)、`gantt_action`、`gantt_click`、`gantt_show_in_table`(`select_row_id` と同じ)、`render(app, w, h)`。描画は `relmap::panel` の枠に、左に名前の欄(`番号 字下げ 名前`、幅は w の 2/5 を 16〜40 に)、右に時間軸(見出し2行: 月と、日か週の始まりの日)と棒。棒は `█`(WBS の割合ぶん)と `░`(残り)、割合が無ければ `█`、片方だけの行は `◆`、今日の列は空のマスに `┊` と見出しの日に印、選んでいる行は `>` と REVERSED(色なしでも見分く。SR-15)。
- モードとキー `src/ui/keymap.rs`: `Mode::Gantt`(msg ModeGantt、name "gantt"、ALL を 24 に、EXITS に Close)。`Action::GanttView`("gantt_view")・`ZoomIn`("zoom_in")・`ZoomOut`("zoom_out")・`Today`("today")。表のモードに `C` → GanttView(FIND)。Gantt のモード: Enter=Run、Esc/q=Close、C=GanttView、j/k/Down/Up、h/l/Left/Right(時間軸を1単位)、+/-(単位)、t=Today、Z と Space=ToggleTree(畳む・開く)、:=Palette、?=Help。パレットに CmdGanttView。
- 振り分け: screen_menu.rs(`Screen::Gantt`、screens は `gantt_ready() || gantt.is_some()`、current・entry(Glyph::Gantt "▬")・switch_screen・close_screen_menu)、bands.rs(`on_gantt`、`menu_button_text`、下の帯の位置の判定)、view.rs(render)、app.rs(モードの振り分け・表の動作 `GanttView => open_gantt()`・クリック・ホイール・設定のボタン・読み終えの `check_gantt_column`・外の変化の `rebuild_gantt`)、help.rs の `close_palette`・drawer.rs・relmap.rs(開くときは gantt を None)・menu.rs は不要。
- 文言(locales/en.toml・ja.toml): ModeGantt、SecInGantt、ScreenGantt、KeyGanttView、KeyGanttRun、KeyGanttNext・KeyGanttPrev、KeyGanttLater・KeyGanttEarlier、KeyGanttZoomIn・KeyGanttZoomOut、KeyGanttToday、CmdGanttView、GanttTitle(始まりの列 → 終わりの列)、GanttInferred(推定)、GanttUnitDay・Week・Month、GanttNotSet、GanttNoRows、GanttShowInTable(TreeShowInTable を使う)、RsnGanttNotTable・RsnGanttNeedStart・RsnGanttNeedEnd・RsnGanttNoColumn。
- 設定の形(GA-7): `[[table]]` の `tree`・`gantt` はどちらも「型の名前 = 列の名前の表」で、読みは `marker_setting` に共通化。推定は型ごと(木は推定しない。ガントは名前)。メニューは設定か推定で開ける型だけ。

## 実装の気づき

- レビューに渡した版: 0bbfcd81d2e1d39e98179cb0549c11ae2736c141(`git stash create`。HEAD は「テスト:」の 119f5c4。未追跡の新しいファイル src/gantt.rs・src/ui/gantt.rs・demos/gantt.tape はこの版に入らないので、レビュー役には作業ツリーで読ませる)。
- テスト役の試験のうち、マウスの試験は見本の行の並び(名前順で gamma が最後)を前提にしていなかったので、ホイールの順(先に上へ)を直した(試験の見本の前提の誤り。要件は変えない)。
- `Action::Today` は日付の入力(CE-21)に前からあるので、ガントの「今日へ」も同じ動作を使う(名前 `today`)。`G` は表の最後の行なので、ガントは `C`。
- スターター(`starters/`)は build.rs が実行ファイルに組み込むので、印や見本を直したら `cargo build` してから `--init-workspace --starter` で見本の台帳(examples/tasks)を作り直す(直さずに作ると古い中身になる)。
- 表のノートの欄の見せ方(`.md` を除く・`note_path`)は view.rs の `label` にあり、ガントの名前の欄もそれを使う(`pub(crate)` にした)。

- レビューの重要2件(クリックの行のずれ・見出しの月の字)は、確かめる回(別の書込なしのレビュー役)で本当と判定してから直した。クリックの行の数は、描画 `ui::draw` が高さを1つ減らして `render` を呼ぶのと同じく `popup::screen` から出す(木と同じ)。見出しは1マスが1字なので「YYYY-MM」を毎回は置けず、単位ごとに置く字を決め、次の切れ目までに収まる形(YYYY-MM → MM → 出さない)を選ぶ。
- 塗り(`█`)は見えているマスでなく棒の全長で数える(左にはみ出しても始まりから塗る)。`gantt_toggle` の畳みは表の `toggle_tree` と同じ行の並べ直しだけ(`refresh` は全部の組み直し)。ただし表の今の行は添字でなく鍵で保たないと、ガントから戻ったときに別の行になる(2回目のレビューの指摘)ので、grid.rs に `build_slots_keep_row`(鍵で保ち、畳まれて見えなくなれば畳んだ親へ)を置いた。

- 追加の試験は錠のあるファイルを変えず、新しい `src/ui/test_gantt_more.rs`(12件)に置いた。流れた状態のクリックは、行が30・高さ16で下まで動かし、選んでいる行の2つ上をクリックしてその行になることを確かめる。
