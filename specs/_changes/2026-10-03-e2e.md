## 要求

docs/todo.md の Q-10。main の配線(設定の editor・add_frontmatter・`--config`)は単体の試験では見えず、oss-config の照合で変異がすり抜けた。本物の実行ファイルを疑似端末で起動し、キーを送り、画面を読み、偽のエディタで起動の引数を確かめる試験を、cargo test(CI)で回す。見つかった配線の不具合は直す。

終わりの条件:
- 疑似端末で `mdgrid --config <一時の設定> <一時の保管庫>` を起動し、画面に表が出る。
- 設定の `editor = "<偽のエディタ> --flag"` で e を押すと、偽のエディタが `--flag` と ノートのパス(1つの引数)で呼ばれる(SR-8)。
- `add_frontmatter = false` の設定では、フロントマターの無いノートのセルを編集できず理由が出る。既定では書けて、保存でフロントマターが足される(WB-3)。
- `--config` で渡した設定が既定の置き場より先に効く(CLI-2・CLI-3)。
- 試験の子は、時間切れでも必ず止まる(後に残らない)。
関係する要件: SR-8・WB-3・CLI-2・CLI-3。

## 不明点と仮定

- 仮定: 疑似端末は Rust の portable-pty(wezterm)、画面の読み取りは vt100 を dev-dependencies に足す(Microsoft の tui-test は Node が要り、cargo test で回せない)。cargo deny のライセンスの許可に収まるかを確かめる。外れたら: expectrl。
- 仮定: Windows では疑似端末の振る舞いが違うので、この試験は unix だけで回す(`#[cfg(unix)]`)。O-11 で見直す。
- 仮定: 偽のエディタは一時フォルダに置く sh のスクリプト(引数を1行ずつファイルに書いて終わる)。
- 仮定: 試験の XDG_CONFIG_HOME・XDG_STATE_HOME は一時フォルダに向け、利用者の置き場に書かない。

## 設計

- tests/e2e/ を作らず、tests/test_e2e.rs(新)に小さい道具(起動・キーを送る・画面の文字を待つ・止める)を置く。子は Drop で kill と wait をし、待ちには上限(数秒)を付けて、上限で落ちる。
- 画面は vt100::Parser に疑似端末の出力を流して読む。待つ条件は「画面のどこかに文字列が出る」。
- 配線の不具合が見つかれば src/main.rs を直す(bugfix)。
- 却下: expect のスクリプト(シェルの外部の道具に頼る)。
- 検証: `cargo test --test test_e2e`、`./ci.sh`。試験のあと `ps` で mdgrid の子が残っていないこと。
