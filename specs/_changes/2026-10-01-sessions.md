## 要求

依頼の要約(会話 2026-10-01): TUI(mdgrid)に2つの機能がほしい。(1) Markdown のフォルダを指定すると表で表示する。(2) その表示を、値を設定した「セッション」(ショートカットのようなもの)として持ち、それを指定して起動できる。

- (1) は既存の要件で満たす: CLI-1(`mdgrid <フォルダ>` で起動)と BV-1(フォルダだけならノートを行・キーを列にした既定の表)。新しい要件は足さない。
- (2) は該当する要件が無い。近いのは CLI-2 の `--view <名前>`(`.base` の中のビューを選ぶだけ)と SR-11・SR-12(見た目の状態の自動保存。名前で呼べない)。

受け入れの条件(例):
- 表でフォルダと絞り込み・並び・列を決めてから、名前 `進行中` で保存 → 終了して `mdgrid -s 進行中` で起動すると、同じフォルダ・同じ絞り込み・並び・列の表が開く。
- 無い名前 `mdgrid -s 無い` → 理由1行(ある名前の一覧)と終了コード 2(CLI-4 と同じ)。

関係する要件: CLI-1, CLI-2, CLI-3, CLI-4, BV-1, BV-2, BV-3, BV-4, BV-5, SR-11, SR-12, WB-2。

## 不明点と仮定

- 問い → 答え(要約): セッションに何を持たせるか → 表示の全部(フォルダ・\`.base\` とビュー・絞り込み・並び・列・読むだけ)。
- 問い → 答え(要約): どこにどう保存するか → mdgrid 専用のファイル(設定の置き場の \`sessions.toml\`)。ノートのフォルダには書かない。
- 仮定: 起動の形は \`-s/--session <名前>\`、一覧は \`--sessions\`(ほかの CLI の慣習。短い \`-s\` はほかのオプションとぶつからない)。外れたら: CLI-6・CLI-9 の旗の名前を変える。
- 仮定: 版1に入れる(人が付けてほしいと頼んだ)。ただし画面(タスク 7・8)ができる前には画面からの保存(CLI-9 の前半)は作れないので、実装はセッションのファイルの読み書きと起動の解決を先にする。外れたら: 次の段に移す。

## 設計

2つ以上のモジュール(設定・起動・表の組み立て・画面)にまたがり、新しいファイルの形(`sessions.toml`)を決めるので書く。長く残る判断は docs/design.md の「セッション」にも写した。

- **形**: セッションは「起動の指定」(`Launch`: 開くフォルダ・`.base` とビュー・絞り込みの列・並び・列の並びと隠す列・読むだけ)に名前を付けて置いたもの。起動の引数(CLI-1・CLI-2)も同じ `Launch` を作り、核(base・changes・ui)はセッションを知らない。選んだ理由: セッション専用の起動の道を作ると、引数での起動と振る舞いがずれる。却下: セッションを `.base` として書き出す(WB-2 に反し、読むだけ・複数のフォルダを表せない。人も専用のファイルを選んだ)。
- **ファイル**: `src/session.rs`。`sessions.toml` の読み書き(serde と toml。依存は v1 のタスク 8 で入れるものを使う。増やさない)。書くときは同じフォルダの一時ファイル → 名前の変更(WB-8 と同じやり方。壊れた途中の状態を残さない)。知らない項目は警告(CLI-8)。壊れていたら理由1行・終了コード 2(CLI-10)。置き場は `config` の設定の置き場(CLI-3)。
- **形式の例**:
  ```toml
  [sessions.進行中]
  folders = ["~/notes/tasks"]
  base = "~/notes/tasks.base"   # 任意
  view = "表"                    # 任意
  columns = ["title", "status", "due"]
  hidden = []
  readonly = false

  [[sessions.進行中.filters]]
  kind = "value"
  key = "status"
  value = "進行中"

  [[sessions.進行中.filters]]
  kind = "text"
  value = "会議"

  [[sessions.進行中.sort]]
  key = "due"
  dir = "asc"
  ```
  絞り込みは画面で掛けた種類のまま持つ(`text` = NV-2、`value` = NV-8。NV-10 が入ったら `expr`)。版1の簡易の絞り込みは `.base` の式1つに写せないため(sessions-filters)。
- **起動**: `main.rs` の引数(clap)に `-s/--session <名前>` と `--sessions` を足す。`-s` とパスの引数は同時に受けない(clap の conflicts_with)→ 理由1行・終了コード 2(CLI-10)。`--sessions` は `名前<TAB>最初のフォルダ` を1行ずつ出して 0 で終わる(CLI-9)。
- **当て方**: セッションの `columns`・`hidden` は SR-12 の見た目の状態より先に当て、今の表に無い列は飛ばして下の帯に警告(CLI-7)。並べ替えは NV-3 の一時的な並べ替えとして当てる(見た目の状態には残さない SR-12 はそのまま。セッションは明示に保存したものなので別)。行と値は毎回ノートから作る。
- **画面から保存**: パレット(SR-14)のコマンド「セッションを保存」で名前を聞き、同じ名前があれば確認(保存の確認 WB-11 と同じ部品)。既定のキーは割り当てない(SR-16 の既定のキーとぶつけないため。パレットから呼ぶ。設定で割り当ててよい)。読むだけの起動(WB-15)でも保存できる(ノートを書かないので WB-15 に反しない)。
- **変えない場所**: frontmatter・writeback・`.base` の読み取り。セッションはノートのフォルダ・`.base` に何も書かない(CLI-8・BV-3・WB-2)。
- **要件との対応**: CLI-6 → タスク S2(起動)・S4(保存)。CLI-7 → S1(形)・S3(当て方)。CLI-8 → S1。CLI-9 → S2(一覧)・S4(上書きの確認)。CLI-10 → S1(壊れたファイル)・S2(無い名前・同時指定)。
- **検証のコマンド**: `./ci.sh`(fmt・clippy -D warnings・test)、`python3 〔伏せ字: 手元のパス〕 .`。テストは `tests/test_session.rs` に置き、本文に `[CLI-7]` などを書く(harness の XR-1)。
