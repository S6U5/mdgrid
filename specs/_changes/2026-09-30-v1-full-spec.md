## 要求

依頼の要約(会話 2026-09-30): CSV や Excel を表示する TUI(VisiData・csvlens・tabiew・sc-im・lazysql など)と Obsidian Bases の表の、細かい機能・オプション・操作性を調べたうえで、mdgrid の仕様をまず全部書き切り、そのあと実装する。値の書き換えとリストからの選択ができる。AI エージェントの機能は最初の版に入れない。Rust で作る。調査の結果は research-lab の設計ログ(2026-09-30 の節)にある。

終わりの条件: 仕様(specs/)が、表示・移動・検索と絞り込み・並べ替えとグループ・列の操作・編集・保存・取り消し・コピーと出力・起動オプションと設定・見つけやすさ(ヘルプ・パレット)・文字の幅と端末の差・安全(書き戻し)を、版1 / 次の段 / 採らない の優先度つきで持ち、照合の検証役の指摘の残りが0になる。関係する要件: scope・base-view・cell-edit・write-back・screen の既存の要件(SC-1〜SC-12 は人の決定を含む)。

## 不明点と仮定

- 問い → 答え(要約): 保存の仕方 → ためてから保存(差分を見て保存、取り消しあり)。推しで進めてよいとの返事で、読みに ⚠(違えば直す)。
- 問い → 答え(要約): 機能の分け方 → 全部を仕様に書き、版1 / 次の段 / 採らない の優先度で分ける。
- 問い → 答え(要約): キーの流儀 → vim 風と矢印の両方、Obsidian Bases の主なキーも効く、すべて割り当て直せる。
- 仮定: 行ごとに外部コマンドを動かす列は版1に入れない。外れたら: 次の段の仕様に足す。
- 仮定: 名前 mdgrid は仮のまま。外れたら: リポと crate の名前を変える(今なら安い)。→ その後 [rename-mdgrid](../_decisions/2026-09-30-rename-mdgrid.md)(2026-09-30)で mdgrid に決めた。
- 仮定: 芯は Obsidian Bases の .base の table ビューとの互換。外れたら: ビューの定義の形が変わる(止める)。

## 設計

設計の本文は docs/design.md(「全体の形(v1-full-spec の設計)」の節と、それより前からある書き戻し・表の組み立て・文字の幅・テストの節)。要点:

- 1つの cargo のパッケージに、画面に依存しない核のライブラリと、実行ファイル(画面)を分ける。モジュールは vault・frontmatter・types・base・expr・changes・writeback・keymap・ui・clipboard・config。
- 書き戻しは、第1階層のキーの値のバイトの範囲を自前で特定して置き換える(YAML の編集の部品は使わない)。対応しない形は読むだけ。
- ためる変更は (ノート, キー) → 新しい値 と取り消しの積みで持ち、保存でファイルごとの差分を見せてから書く。失敗したノートの変更は残す。
- 外での変更とためる変更がぶつかったら、ためる変更は残して「外で変更」の印を付け、保存の検査で止める。
- 依存は入れる前に配布元・保守・既知の脆弱性を確かめ、`cargo deny` を CI に置く。

選ばなかった案: YAML の編集の部品(yamlpatch・yaml-edit)を使う(best-effort で書式を保てず、依存が増える)、フロントマターを丸ごと出力し直す(Obsidian 型。書式が崩れる)、1ファイルに状態と入力と書き込みを集める(cellops の失敗)。

## 実装の気づき

- 人の判断(2026-09-30、要約): 点検の指摘の直しはそのままでよく、仕様の量に上限は設けない。
- 仕様の点検(書込なしの点検役、2026-09-30): キーのぶつかり・IME・外の変更とためた変更のぶつかり・値の見せ方・大きな保管庫・節の名前の指摘を、v1-review-fixes で仕様に入れた(102要件・9ケイパビリティ)。
- タスク 2・3(実装役、2026-09-30): ハードリンクで書かない理由は `ReadOnly` に項目が無いので、`save` は `SaveError::Io`(ErrorKind::Other)で返す。表で理由を出すタスク 4・7 で `ReadOnly::HardLink` を足すか決める。
- タスク 2・3: フローのリストの値に `NewValue` を当てると `NotEditable` で止まる(レビューの指摘で、形が変わるのを部品の側で防ぐようにした)。リストの編集は CE-13 で。
- タスク 2・3: `key:` だけの空の値は `Value::Null`・`Shape::Plain`・長さ0の span を返す。書くときはコロンの直後に空白を補う。変更の数え方(タスク 7)で長さ0の span を扱えること。
- タスク 2・3: 改行の混ざりの判定はフロントマター(開きから閉じの行まで)だけ、UTF-8 の判定はファイル全体。タグつきの値(`!!str` など)・複数行の素のスカラーや引用符つきの値・複数行のフローは、span なしの読むだけ。
- タスク 2・3: 新しい基準は、名前の変更の前に一時ファイルの fd の更新時刻・大きさと、書いたバイト列のハッシュから作る(レビューの指摘で、読み直しの間の外の書き込みを基準に取り込まないようにした)。検査から名前の変更までのわずかな間の外の書き込みは防げない(ロックは無い)。
- タスク 2・3 のレビュー(書込なしの検証役、2026-09-30): 範囲の外のバイトが変わる例・クオートの漏れ・SHA-256 の誤りは見つからず(約90の形と30万件のランダム入力、PyYAML と shasum で照合)。直した3点: タブの字下げ、フローのリスト、基準の作り方。残り(低): 区切りの後ろの空白、空のフロントマターへのキーの追加、一時ファイルの名前の長さ(ext4 の255バイト)、グループの違う fchown、xattr と ACL が消える、リンクの先がフォルダの外。
- 読み取り専用(0444)のノートも書き換えてしまう。WB-5 と同じく止めるかは仕様で決める(未決)。→ write-back の未決の問いに移した(2026-10-01、edit-view-gaps)。
- 日付の型が無いため、クオートなしの日付を書くと二重引用符つきになる。WB-7 の「元と同じクオート」との関係をタスク 7・11 の前に決める(未決)。→ write-back の未決の問いに移した(2026-10-01、edit-view-gaps。ラボをまたぐ論点で人の判断待ち。harness の cross-repo の未決の問い)。
- 仕様の点検(2026-10-01): 設計(docs/design.md の依存の候補)は、ハッシュに sha2、値の読み取りに saphyr を挙げるが、実装(タスク 2・3)は SHA-256 もフロントマターの値の読み取りも自前で、依存は無い。どちらに揃えるかを、依存を足すとき(タスク 6 の `.base` の読み取り)に決め、設計か実装を直す。
- 仕様の点検(2026-10-01): 仕様の変更で実装に効くもの: 表のモードの既定のキー(SR-16・SR-18。Ctrl+C はコピー、読み込みの中止は Ctrl+G、やり直しに `U`)はタスク 8・10、評価できない列の `?`(BV-7)はタスク 6・9、候補を読み込んだノート全部から集める(CE-3)と日付の空は null(CE-5)と飛ばす行(CE-10)はタスク 7・11、CE-8 の読むだけの形は実装済み(タスク 2)。
- 仕様の点検(2026-10-01、2回目): WB-4 の保存の基準は「最初に変更をためた時点で表が持っていた内容」で、ためたあとの読み直し(WB-16)では動かさない。保存で「外の変更の上に書く」を選んだら、選んだ時点のファイルの内容を基準にして WB-4 の検査をする(overwrite-baseline、タスク 3・7・12。今の writeback の基準の渡し方がこれに合うかはタスク 7 で確かめる)。SR-17 の `、`→`,`・`・`→`/`、SR-18 のキーの無いセルの Backspace は何もしない(タスク 8・10)。BV-7 の未対応の印は薄い `?` と下の帯の説明(タスク 6・9)。
- 依存の確認(書込なしの調べ役、2026-10-01): ratatui 0.30.2(crossterm 0.29 を再エクスポート。直接は使わず `ratatui::crossterm` を通す)・unicode-width 0.2・unicode-segmentation 1.13・similar 3.2(Apache-2.0 のみ)・toml 1.1・serde 1.0 は RustSec の該当なし。推移依存の lru に RUSTSEC-2026-0253(0.18.2 以上で修正)があるので古い lock を使わない。推移依存のライセンスに Zlib・Unicode-3.0・BSL-1.0(deny.toml で許す)。cargo-deny はこの機械に入れた。
- BV-1 と BV-2 の読み方(設計の判断、2026-10-01): ノートを読む範囲は保管庫の根(BV-2。CE-3 の候補もここから)、フォルダだけで開いた既定の表の行は渡したフォルダの下のノートに限る(BV-1 の「その中の」)。
