### A. 同じことを決める項目が2つ以上ある

| # | 重なり | 今 |

### B. 性質の違う項目が混ざっている

- 端末の性質(`color`・`ambiguous_wide`・`nerd_font`)、アプリ全体のこと(`language`・`editor`・`poll_ms`・`keys`・`workspace_detect`)、表の見え方(`theme`・`[style]`・`[colors]`・`cells`・`[display]`)、編集(`candidates`・`date_format`・`week_start`・`add_frontmatter`・`[new_note]`)が、どれも最上位に並ぶ。範囲ごとに上書きできるものとできないものの境目が見えない。
- `nerd_font`(端末の字形)が見た目のテンプレート(`look.toml`)に入っていて、テンプレートを当てると端末の設定まで変わる。

### C. 範囲ごとの上書きの仕組みがばらばら

- ビューごとの上書きは、`[display]` の7つ(ビューの設定)と `[new_note]`(mdgrid のビューだけ)にある。見た目(テーマ・組・色)とセルの部品にはどの範囲にも無い。
- ワークスペース(`workspaces.toml`・`.mdgrid/workspace.toml`)は名前と表の並びしか持たない。

### D. 名前と形がそろっていない

- 表を指す書き方が4通り: `views.toml` の `[[target]]`、`places.toml` の `[[place]]`、`workspaces.toml` の `[[workspace.table]]`、印の `[[table]]`。
- 警告の文がファイルごとに違う(`ConfigUnknownItem`・`LookUnknownKey`・`ViewsUnknownItem`・`WsBadTable`・`PlacesBadEntry`)。どのファイルのどの項目かの出し方がそろわない。
- 読み方もばらばら: config.toml は手で1項目ずつ、`views.toml` は serde、`look.toml` はまた別。新しい項目を足すたびに、読み取り・`--print-config`・文書・カタログ・設定の画面を別々に直す。

## 案

### 1. 設定の形(config-v2)

項目を「アプリ全体」と「表のプロファイル」に分ける。プロファイルはどの範囲でも同じ形で書け、範囲ごとの上書き(2.)はこの形をそのまま使う。

```toml
# ── アプリ全体(config.toml だけ。範囲で上書きしない)──
language = "auto"
editor = "nvim"
poll_ms = 1000

[terminal]                 # 端末の性質
color = true
ambiguous_wide = false
nerd_font = "auto"

[workspace]
detect = ["vault"]         # 旧 workspace_detect

[keys.table]
"ctrl+f" = "search"

# ── 表のプロファイル(全体・ワークスペース・表・ビューで上書きできる)──
[look]
theme = "auto"             # 名前か、{ light = "saas", dark = "sumi" }。旧 theme_light・theme_dark はこの中へ
preset = "sumi"
mode = "modern"            # 旧 look(modern・classic)
use = "夜"                 # テンプレートの名前(下の [templates])を土台にする

[look.style]               # 旧 [style] から preset を除いたもの。frames が旧 borders を吸う
status = "dot"             # … tags・check・select・rules・tabs・frames・band・icons・links
cells = "rich"             # 旧 cells = "rich"|"plain" の全体の切り替え

[look.columns]             # 旧 [cells.columns]
status = "plain"
owner = "chip"

[look.colors]              # 旧 [colors]
accent = "#e0a458"
[look.colors.values]       # 旧 [colors.values]
done = "green"

[display]                  # 旧 [display] に search_bar を入れ、tabs に view_tabs を吸う
row_numbers = false
zebra = false
column_lines = false
group_gap = false
chips = true
search_bar = true
tabs = "always"            # "always"・"auto"・"never"

[dates]
format = "YYYY-MM-DD"      # 旧 date_format
week_start = "sun"

[edit]
candidates = 20
add_frontmatter = true

[new_note]                 # 今のまま

# ── 名前を付けたプロファイルの断片(テンプレート)──
[templates.夜.look]
theme = "dracula"
preset = "dozy-pink"
```

- 旧 `[cells]` の部品ごとの真偽(`checkbox`・`chips`・`select`・`links`・`icons`)は `[look.style]` の各部品の `plain`(と新しい `links = "accent"|"plain"`)に寄せる。
- 画面で選んだもの(今の `look.toml`)は、config.toml と同じ形の、画面が書くファイル `ui.toml` に置く。持てるのは見た目の3つだけでなくプロファイルの全部と、テンプレート。config.toml は今どおり書き換えない。
- 旧い名前(`theme_light`・`borders`・`view_tabs`・`search_bar` ほか)は、読んで新しい場所に当て、「X は Y に移った」と警告する。`mdgrid --migrate-config` で、今の config.toml を新しい形にした文を標準出力に出す(ファイルは書かない)。
- 警告は、どのファイルでも「ファイル: 項目の道筋: 理由」の形にそろえる。
- 項目は1つの表(名前の道筋・型・既定・書ける範囲・説明)に持ち、読み取り・`--print-config`・文書・カタログ・設定の画面がそれを使う(設計)。
- `views.toml` の `[[target]]` を `[[table]]` にし、表を指す書き方を `path`・`view` にそろえる。

### 2. 範囲ごとの上書き(scope-overrides)

| 範囲 | 手で書く | 画面が書く |
|---|---|---|
| 全体 | `config.toml` | `ui.toml` |
| ワークスペース | `.mdgrid/workspace.toml` か `workspaces.toml` の `[[workspace]]` に `[look]` などのプロファイル | `workspaces.toml`(印のワークスペースは、画面からは書かない) |
| 表 | ワークスペースの表の項目(`[[workspace.table]]`・印の `[[table]]`)にプロファイル | `views.toml` の `[[table]]` |
| ビュー | — | `views.toml` のビュー(今の `[display]`・`[new_note]` を、プロファイル全部に広げる) |

- 決まりは2つ: **狭い範囲が勝つ**(全体 < ワークスペース < 表 < ビュー)。**同じ範囲では画面で選んだものが手で書いたものに勝つ**。
- 項目ごとに重ねる。ただし、組(`preset`)を書いた範囲より広い範囲の部品ごとの形は使わず、テーマを書いた範囲より広い範囲の役割の色(`[look.colors]`)は使わない(値の色は使う)。今の SR-43 の「組を変えたら config.toml の部品の形は重ねない」をどの範囲にも広げたもの。
- `use = "<テンプレート>"` は、その範囲の土台にテンプレートを置き、その範囲で書いた項目が上に重なる。
- 設定の画面の「見た目」の区画で、保存先(全体・このワークスペース・この表・このビュー)を選べ、今の値がどの範囲から来たかを項目の横に出す(例「テーマ dracula(この表)」)。範囲ごとに「この範囲の上書きを外す」を置く。
- `mdgrid [<表>] --print-config --resolved` で、その表で効く設定を、項目ごとにどこから来たかのコメント付きで出す。

## 不明点と仮定

人の決定(会話 2026-10-10。4つとも推しの案):

- Q1 旧い書き方 → 当分は読んで新しい場所に当て、「X は Y に移った」と警告し、`--migrate-config` で移してもらう。
- Q2 錠 → 今の項目の名前や `Config` の形に触れる錠のある試験(約 200)を、作り直しの決定記録で掛け直してよい。
- Q3 上書きできる範囲 → 全体・ワークスペース・表・ビューの4段。
- Q4 上書きできる項目 → プロファイル全部(見た目・セルの部品・表示・日付・編集・新しいノート)。

AI の仮定(違えば言ってもらう):

- 仮定: 印(`.mdgrid/workspace.toml`)はノートのフォルダの中なので、画面からは書かない(WS-1・SR-11 のとおり、ノートのフォルダに書かない)。印のワークスペースに保存しようとしたら、理由と「workspaces.toml に書く」を出す。
- 仮定: ビューの範囲の画面が書く上書きは、今の `[display]` の上書きと同じく、ビューの設定(NV-17。見た目の状態に覚え、mdgrid のビューは保存で定義にも入る。BV-18)に持つ。ビューの設定の残り方は変えない。
- 仮定: ワークスペースが検知(WS-5)か登録した表(CLI-18)から来たときは、ワークスペースの範囲は無い(書く場所が無い)。画面の保存先にも出さない。
- 仮定: 画面からの範囲ごとの保存は「見た目」の区画だけに置く。ほかのプロファイルの項目は、ファイルに書いて範囲ごとに変える(表示はビューごとに今どおり画面で変えられる)。
- 仮定: テンプレートは見た目の項目(`[look]` の下)を持つ。丸い札の端(`nerd_font`)は端末の性質なので `[terminal]` に移し、テンプレートには入れない。
- 仮定: `places.toml`(よく開く表のしおり)は `workspaces.toml` に混ぜない。しおりは開く入口、ワークスペースはリンクと関係マップの範囲で、役目が違う。
- 仮定: テーマの既定は今の `"default"`(端末の色のまま)のまま変えない。
- 仮定: 端末の項目(`[terminal]`)・`language`・`editor`・`poll_ms`・`keys`・`[workspace] detect` は全体だけで、範囲で上書きしない。

## 実装の気づき

- 範囲の層は、起動(`App::start` で範囲を決めたあと)とビューの切り替え(`restore_state`)と反映で重ね直す。表を切り替えると main が開き直すので、表の範囲もそこで決まる。`add_frontmatter` は表で決まるので、読み込みの前に源へ渡す(`Source::set_add_frontmatter` を trait に上げた)。
- 明暗の組のテーマの地の問い合わせは、要るとき(組が効くとき)に1回だけ。main が問い合わせの関数を App に渡す(試験では渡さない)。
- `[new_note]` は1つの項目として重ねる(狭い範囲に書けば丸ごと代わる)。CE-27 のビューの new_note の振る舞いと合わせた。
- workspaces.toml にワークスペースのプロファイルを書くときは、区画の文字を置き換えて手のコメントを残し、読み直して狙いと違えば並びから書き直す(今までの足し・外しと同じ形)。
- 旧い `[cells]` の部品ごとの真偽は、部品の形の文字のままの形(`check = "text"`・`tags = "plain"` など)に写す。札を強いる列(`chip`)と部品を切った形の組み合わせだけ、前と違う(前は列の chip が部品の真偽より強かったが、今は部品の形が `plain` なら文字のまま)。
- 錠の掛け直し: この環境には decidespec の check.py が無いので、specs/test-locks.json はまだ掛け直していない。対象の試験は specs/_decisions/2026-10-10-config-v2-locks.md に並べた。`check.py --lock --relock specs/_decisions/2026-10-10-config-v2-locks.md` で掛け直す。
