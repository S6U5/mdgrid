## 要求

依頼の要約(会話 2026-10-02): examples に、いろいろな機能を有効にした表になる版も置いておく。今の examples/vault は設定なしの素の状態を見る見本として残す。

終わりの条件: `mdgrid --config examples/showcase/config.toml examples/showcase/vault/<名前>.base` で、設定(日付の形・週の始まり・キーの割り当て直し・検索の欄)と、`.base` のビュー(絞り込み・並べ替え・グループ分け・式の列・displayName・limit)と、リストの選択・カレンダー・型ごとの入力が一通り見える。見本が仕様の変更で開けなくなったら試験で気づける。README に起動のしかたと、どのビューで何が見えるかを書く。

## 不明点と仮定

- 仮定: ビューの設定(`o`)は開いた場所ごとの見た目の状態に覚えるので配れない。同じ見せ方は `.base` のビューで用意する。
- 仮定: 親タスク(`parent`)のフロントマターは入れておくが、階層の表示はまだ無い(リレーションと階層の変更で見えるようになる)。

## 設計

置き場所: `examples/showcase/`。`config.toml`(`date_format = "YYYY/MM/DD (ddd)"`、`week_start = "mon"`、`candidates`、キーの割り当て直しの例を1つ、`search_bar = true`)、`vault/.obsidian/types.json`(due・start = date、estimate = number、done = checkbox、tags・assignees = tags/multitext)、`vault/プロジェクト/` に十数個のタスク(status・priority・due・start・estimate・done・tags・assignees・parent・説明)、`vault/メモ/` に数個、`vault/プロジェクト.base`(ビュー: 今週の作業(filters で期日が近い・未完了、sort)、担当ごと(groupBy)、優先度と見積(式の列・displayName・limit)、完了(done のもの)、全部)。README の「試す」の節に showcase の起動を足し、`examples/showcase/README.md` にビューごとの見どころを書く。試験は tests/test_examples.rs に、写してから開く形で足す(設定が警告なしで読める、`.base` の table のビューが全部 build できる、フォルダで開いて全ノートが入る)。

## 実装の気づき

- 「担当ごと」の groupBy は、リストの列(`assignees`)だと要素の組み合わせ(`佐藤, 営業` と `営業, 佐藤` が別)ごとのまとまりになり、見本として分かりにくい。1つの値のテキストの列 `owner`(表示名「主担当」)を足して、それで分けた。`owner` の無いタスクを1つ置き、`(空)` のまとまりも見えるようにした。テキストの列の候補(CE-3)を試す材料にもなる。
- 式の列で日付の差(`due - today()`)を出すと期間はミリ秒の数で見える。見本では使わず、「状況」(期限切れ / もうすぐ / これから)の if にした。
- 見た目の状態(SR-12)は開いた場所とビューごとに残るので、同じ写し先で `.base` の order に列を足して開き直すと、足した列は右の端に出る(仕様どおり)。showcase の README の「気をつけること」に書いた。
- 疑似端末で確かめた(写した showcase を `--config` で、リポの showcase を `--config` と `--readonly` で): 日付の形 `2026/10/02 (金)`、月曜始まりのカレンダー、`Ctrl+F` で検索、`\` で検索の欄、`o` のビューの設定、リストの選択(候補と件数)、テキストの候補、チェックボックスの切り替え。設定の警告は出ない。実装の不具合は見つからなかった。
