## 要求

人が、タスク・ブックマークのような台帳の「形」の定義を見せ方のテンプレートとして mdgrid に持ち、いくつかの型を組み込んでおいてそこから台帳を作れるようにしたいと言った(会話 2026-10-24。提案 `specs/_proposals/2026-10-24-starter.md`)。組み込みは tasks・bookmarks・reading・people の4つ、入口は CLI と画面の両方、自分のスターターも設定の置き場に置いて同じ仕組みで使え、見本のノートを入れるかは選べる。スターターは見せ方(印・新しいノートの本文の雛形・見本)だけで、スキーマ・lint は持たない。版1 の ST-1〜ST-6 を作る。

受け入れの条件(作った値):

- `mdgrid books --init-workspace --starter reading --with-samples` を `MDGRID_TODAY=2026-10-06` で走らせる → `books/.mdgrid/workspace.toml`・`books/.mdgrid/templates/` の雛形・`books/reading/` の見本ができ、見本の `{date-10}` は `2026-09-26`、雛形の `{date}` は文字のまま。`mdgrid books` で Reading の表が開く。
- もう一度同じコマンド → 理由1行と終了コード 2 で、ファイルは1つも変わらない(失敗時)。

関係する要件: ST-1〜ST-6(新)、WS-7(`--init-workspace`・印)・WS-9・WS-10・TR-2(印の中身)、CE-32(雛形の変数と `body`)、CLI-3(設定の置き場・警告の形)・CLI-4(引数の誤りの終了コード)・CLI-12(印の項目の文書)・CLI-19(開く前の確かめ)、SR-14(パレット)、WB-15(読むだけの起動)。

## 不明点と仮定

- 問い: 最初に組み込む型 → 答え: タスク・ブックマーク・読書と視聴の記録・人と連絡先と会議メモの4つ。
- 問い: 入口 → 答え: CLI と画面の両方。
- 問い: 自分の型も同じ仕組みで使うか → 答え: 使う(組み込みは見本の扱いで特例にしない)。
- 問い: 見本のノートを入れるか → 答え: 選べるようにする(既定は印と雛形だけ)。
- 問い: 呼び名 → 答え: 日本語「スターター」、英語 `starter`(「型紙」は日本語として耳慣れないので退けた。「テンプレート」は `[templates]` と衝突する)。
- 問い: examples/bookmarks と組み込みの bookmarks の関係 → 答え: スターターを正本にし、見本はそれから作ったものにして一致を試験で縛る。
- 問い: 中身の言語 → 答え: 英語(正本)と日本語の両方。
- 仮定: 組み込みの印に `name` は書かない(作った先のフォルダの名前が範囲の名前になる。WS-7)。外れたら: `starter.toml` の名前を差し込む。
- 仮定: 言語の変種は丸ごとの差し替え(`ledger.ja/` があれば `ledger/` を使わない)。外れたら: 重ねる規則を足す。
- 仮定: 画面で作る場所の既定は、開いたフォルダの下のスターターの名前。外れたら: 空の欄にする。
- 仮定: tasks のスターターは、別のリポの台帳の印から一般化し、台帳の固有の作法(ファイルの名前の日付・担当の計算の列・リポの列)は入れない。外れたら: その台帳の側がユーザーのスターターとして置く(ST-3 の仕組みで足せる)。
- 仮定: `starter.toml` の名前と説明は、今の言語のものが無ければ英語(正本)のものを使い、それも無ければフォルダの名前と空の説明(ST-1 の文は後者だけを書く。英語が正本という前提の延長)。外れたら: 英語に落とさず、すぐフォルダの名前にする。
- 仮定: 設計で挙げた `docs/manual-scenarios.toml` の場面は足さない(場面の鍵の打ち方がパレットの文字の入力に合わず、撮り直しの道具の側で確かめるのが先)。外れたら: 場面を足す。

選んだ案と却下した案:

- 選んだ: 組み込みをファイルの木のまま build.rs で埋め込む(文言の台帳と同じ道)。却下: Rust の定数に手で書く — 中身が印の TOML と Markdown で、ファイルのままの方が人が読め、ユーザーのスターターと同じ形になる。却下: 実行ファイルの隣に置く — 1つのバイナリで配る形(SC-2)に合わない。
- 選んだ: 名前と説明は `starter.toml` に持つ。却下: 文言の台帳(`Msg`)に持つ — ユーザーのスターターは `Msg` を足せないので、同じ仕組みで説明を持てるのはマニフェストだけ(「組み込みを特例にしない」)。
- 選んだ: 新しいモジュール `src/starter.rs`。却下: `workspace::init` を広げる — workspace.rs は印の読み書きの核で 1300 行あり、マニフェスト・一覧・写し・変数は関心が違う。
- 選んだ: people は根の `[table.base]`(Meetings)1つ + フォルダの表(People)。却下: 根の `[table.base]` を2つ — リレーションは `.base` を根の表とみなすので、2つあると見分けられない(`src/relations.rs` の表の決め方。studio の見本と同じ形にする)。
- 選んだ: 言語の変種は丸ごと差し替え。却下: 重ねる(merge) — 見本のノートの名前が英語と日本語で混ざる。

## 実装の気づき

- テスト役(実装を見ていないサブエージェント)が、採択のコミットの worktree で `src/test_starter_unit.rs` と `tests/test_starter_cli.rs` を先に書いた。CLI の試験は実装の前の版で「知らないオプション: --starters」で落ちることをテスト役が確かめた。単体の試験(`src/test_starter_unit.rs`・`src/ui/test_starter.rs`)は、実装の前の版では取り込む `mod` が無いので組み立てに含まれず、走らせても 0 件になる(要件の手前)。画面の試験(`src/ui/test_starter.rs`)と e2e・見本の同期の試験は実装と同じ文脈で書いた(独立したテスト役ではない)。レビュー役は使っていない。
- 単体の試験が「組み込みは4つ」を縛るので、タスク 1(tasks の英語)とタスク 4(残りの3つと日本語)は分けずに1つの「実装:」にまとめた。
- 雛形の置き場: CE-32 の `body` は開いたフォルダの中のファイルだけなので、どのスターターも根から開く表を `[table.base]` にし、雛形を根の `.mdgrid/templates/` に置いた(bookmarks も、examples/bookmarks のフォルダの表から `[table.base]` に変えた)。people の `People`(フォルダの表)は雛形を持たない(持つなら `People/.mdgrid/` になり、試験の「見本は `.mdgrid/` の外の `.md`」と見分けられない)。
- 見本のフォルダの名前は studio と同じ大文字始まり(`Tasks/`・`Bookmarks/`・`Reading/`・`People/`・`Meetings/`)。日本語の変種でもフォルダの名前は英語のまま(ノートの名前と列の表示名・ビューの名前だけ日本語)。
- `--starters` の読めないスターターの警告は、`ws_cli` が `mdgrid: ` を頭に標準エラーへ出す(`run` の返り値は変えない)。
- clap の `--starter` に `allow_hyphen_values` を付けない(付けると `--starter --with-samples` が値になる)。`requires = "init_workspace"` で、`--init-workspace` の `conflicts_with_all` を引き継ぐ。
- レビューの版: 408225b(「実装:」のコミット。決めた手順の版(decidespec 0.22.2)ではレビュー役は実装の中で呼ぶ決まりが無く、手順を 0.26.0 に上げたあとで、実装を見ていないレビュー役とセキュリティの役を「実装:」のコミットの後に呼んだ。指摘の直しは別の「実装:」のコミット)。重要の #1 は、別の確かめる回(読んで、リポの外の実験で再現)が「本当」と判定してから直した。
- `export_dir_of`(書き出し・取り込みの置き場)も、複数のフォルダを開いたときの改行入りの `nv.target` を見分けない。スターターでは `starter_base` で断るようにしたが、書き出し・取り込みの側は前からの振る舞いなので触っていない(別の変更の候補)。
- build.rs で `.` 始まりを飛ばすのはファイルだけにする(フォルダに `.mdgrid/` があるので、フォルダまで飛ばすと印が埋め込まれない。単体の試験で気づいた)。
