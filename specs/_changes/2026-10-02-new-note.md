## 要求

依頼の要約(会話 2026-10-02): 右上でもどこでもよいので、ファイル(ノート)を足す機能が要る。選んだもの: 作る場所は開いたフォルダで変えられる、ビューの絞り込みの値を前もって入れる、設定などで作るときに何を入力させるかのルールも選べる、操作は右上の「+ 新規」とキー。

終わりの条件: 「+ 新規」・キー・パレットから名前を打って新しいノートを作れ、絞り込みの値と設定の値が入り、設定で聞く項目を1つずつ入力でき、作った行が選ばれる。外の場所・同じ名前・読むだけでは作らない。関係する要件: CE-25・CE-26・CE-27・CE-2・WB-2・WB-15・BV-17・SR-4。

## 不明点と仮定

- 仮定: 人が選んだ「n キー」は検索の次の一致と重なるので、既定は `a` にし、割り当て直しで `n` にもできる(new-note-details)。外れたら: 既定を入れ替える。
- 仮定: 作ったノートは画面のためる変更(保存待ち)を経ず、Enter のときにすぐ作る(新しいファイルで上書きの心配が無く、作らなかったことにするには削除が要るため)。外れたら: ためる変更にして Ctrl+S で作る。
- 仮定: 本文は空(フロントマターだけ)。テンプレートの写しは後で足せる。

## 設計

- 核(新しい `src/newnote.rs`、ratatui に依存しない): 作る場所と名前の検査(開いたフォルダからの相対の `folder` と `名前`、`..`・絶対パス・空・制御文字・`.md` の補い、既にある名前は断る)、前もって入れる値の集め方(ビューの設定の条件のうち値が1つに決まるもの: Keep の値が1つ・Cmp の `==`、`.base` / mdgrid のビューの式の絞り込みのうち `列 == "値"`・`列.contains("値")` の形。設定の `[new_note.set]` より絞り込みの値が先)、中身の作り方(`writeback::apply(b"", 編集)` でフロントマターを作る。add-frontmatter と同じ書き方。本文は空)、書き方(下のフォルダを作り、`create_new` で作る。既にあれば作らない)。
- 設定(src/config.rs): `[new_note]` の `folder`・`name`(日付の差し込み date を今日に)・`ask`(列の並び)・`[new_note.set]`(列 = 値)。ITEMS と文書(docs/config.md・config.ja.md)に足す(CLI-12)。mdgrid のビュー(src/views.rs)に `new_note` の表を足し、ビューでは設定の代わりにそちらを使う。
- 画面(src/ui): ヘッダーの右の端に「+ 新規」(クリックで始める)、表のモードの `a`(Action::NewNote、`new_note`)、パレット。名前の入力の欄(雛形を入れて出す)→ Enter で `ask` の列を1つずつ、列の型に合った入力(CE-2。日付はカレンダー、リストは選択)で聞く → 最後の Enter で作る。Esc で取りやめ。作ったら読み直して、その行を選ぶ(絞り込みで見えないときは知らせる)。`--readonly` では始めず「読むだけ」。
- 作るのはためる変更を経ず、その場で作る(仮定)。WB-2 の「既にあるファイルを書き換えない」は create_new で守る。

## 実装の気づき

- タスク1: NativeView に new_note を足すと、全項目を並べて作る既存の試験(tests/test_views.rs・src/test_views_unit.rs)に `new_note: None` が要った。また NewValue が f64 を持つので Config の Eq を外し、`new_note` の既定は試験(既定の無い項目は editor・keys だけ)に合わせて `{}` にした。
- タスク1 差し戻し1: toml は serde を通すと日付の値を内部の表(保存)や文字列(読み込み)に崩すので、views の new_note は toml::Value から直に読み書きする(`NewNote::from_toml`・`to_toml`)。式の `==` は型を厳密に比べるので、式から拾う値は日付の列以外は書いてある型のまま入れる。
- タスク1(再レビューの残り、低): `a/.` は最後の `.` を飛ばして `a.md` を作る。末尾の点を残す(`x. ` → `x..md`)。folder の説明に断る文字が書いていない(作るときに断る)。views の new_note を読む口が2つ(serde と from_toml)。
- タスク2: 名前と聞く項目は既存の `Mode::Edit`・`Mode::ListPick` の入力をそのまま使い(書き先の行は空の RowId)、確定と Esc だけを new_note.rs が先に受ける。`input_box` が新しいノートの欄を返すので、カーソル・カレンダー・リストの選択の窓は手を入れずに欄に付く。表の再組み立てで入力を閉じる `guard_input` と、行の入力ボックスを描く `data_row` だけは欄のときを外す要があった。作ったノートは `Source::reload` に新しいパスを渡すと vault に入る(Source に足す口は要らなかった)。
- タスク2 差し戻し1: 聞く欄は前もって入れる値で始まるので、`build` の「空の答え」は前もって入れる値(絞り込み・set)も外す意味に変えた(タスク1の単体試験の「空なら設定の値のまま」を CE-26 に合わせて直した)。NewNote はキーとパレットのコマンドの両方に載るので、パレットの候補は1つにまとめ、読むだけではキーの表の側もヘルプとパレットに出さない。「+ 新規」は作る場所が1つのフォルダに決まるときだけ出すので、`start` を通さない試験の golden からはボタンが消えた(golden の差は sr_5 のヘルプだけになった)。
