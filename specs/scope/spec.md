# 道具の芯と最初の版の範囲(scope)

mdgrid は、フロントマター付き Markdown の集まりをターミナルの表で見て、その場で値を直す単体の道具。Obsidian を開かずに使えて、Obsidian Bases の `.base` の table ビューの一部と互換の表を扱う。ここでは、道具の芯、作り方の大枠、最初の版に入れるものと入れないもの、公開と安全を決める。表の組み立ては [base-view](../base-view/spec.md)、セルの見せ方は [cell-view](../cell-view/spec.md)、セルの編集は [cell-edit](../cell-edit/spec.md)、ファイルへの書き戻しは [write-back](../write-back/spec.md)、画面と操作は [screen](../screen/spec.md)、移動・検索・選択は [navigation](../navigation/spec.md)、コピーと書き出しは [output](../output/spec.md)、起動と設定は [cli](../cli/spec.md) にある。

強さの読み方: 「しなければならない」= 例外なし、「するべき」= 理由があれば外してよい、「してよい」= 任意。

## 要件: 版1 — 芯と作り方

| ID | 要件 | 例(確かめ方) | 決定 |
|---|---|---|---|
| SC-1 | この道具の芯は、Markdown の YAML フロントマターを表として表示し、編集できることにするべき。 | 機能を足す案が、表の表示と編集のどちらにも役立たない → 芯から外れる(読んで判定) | [2026-09-30](../_decisions/2026-09-30-import-scope.md) |
| SC-2 | 単体の OSS として作るべき。 | 他の道具(cellops・Obsidian のプラグイン等)の一部としてしか動かない作り → 違反(読んで判定) | [2026-09-30](../_decisions/2026-09-30-import-scope.md) |
| SC-3 | Obsidian を開かずに使えるようにするべき(Obsidian を開くとメモリを使うため)。 | Obsidian を起動していない環境で、`.base` とノートのフォルダを渡すと表が出る(読んで判定) | [2026-09-30](../_decisions/2026-09-30-import-scope.md) |
| SC-4 | 最初から Rust で作るべき(他で試作すると作り直しになるため)。 | Rust 以外の言語・フレームワークで試作してから移す案 → 理由が無ければ違反(読んで判定) | [2026-09-30](../_decisions/2026-09-30-import-scope.md) |
| SC-5 | 製品名に、Obsidian の名前やロゴを使ってはならない。 | 名前の候補に「obsidian」を含む → 違反。README で互換を説明するのはよい(読んで判定) | [2026-09-30](../_decisions/2026-09-30-import-scope.md) |

## 範囲外

- 次の段: Markdown と CSV・TSV(SC-15〜SC-17)以外の形式(JSON・YAML・SQLite など、ほかの表の道具が扱う形式)の読み込み口。どの読み込み口も、書き戻しの約束(write-back)を守る。CSV とノートの間のリレーションの持ち方は未定(人)。
- 次の段: AI エージェントの機能(起動・枠・実行ログ)。SC-6 で最初の版から省いてよいとされ、今後載せる。
- 次の段: タスクの画面(cellops のガント・カード等)。SC-9 の別の画面の型として足す。
- 次の段: `.base` の table 以外のビュー(cards・list・map・kanban)。最初の版は table だけ(SC-8)で、足すなら SC-9 の別の画面の型として足す(表の見た目の切り替えで作るのは採らない。base-view の範囲外)。
- 次の段: ノートの中の ```` ```base ```` の埋め込み(base-view の範囲外)。
- 採らない: 既にある `.base` ファイルの編集(ビューや絞り込みを TUI で変える。base-view の BV-3)。画面で作るビューは mdgrid のビュー(BV-17)に持ち、`.base` へは新しいファイルへの書き出し(BV-19)だけをする。

## 前提(AI の仮定)

- 仕様の量に上限は設けない(人の判断、2026-09-30。点検役が挙げた上限の案は採らない)。版1は縦切りを先に作る順で扱う。
- 作り始める時期は、cellops-creator と decidespec の実物が回ってからとしていた(設計ログの AI の判定。新しい道具が同時に増えると一人で回らない、という反証の評価役の注意による)。2026-09-30 に実装に入った(変更の記録 [v1-full-spec](../_changes/2026-09-30-v1-full-spec.md) のタスク 1〜3)。
- 公開するときは、決定記録の人の発言の原文と、非公開の設計ログへの参照(パス・コミット)を除いて書き出す(検証役の指摘。SC-12 の書き出しのときに行う)。
- cellops(自作の Rust の TUI)の仕様とコードは流用してよい(人の発言の要約: 自作なので流用してよい、2026-09-30。規範ではないので要件にしない)。ただし cellops のレイアウトは、タスクの画面を載せたときのものとして参考にとどめる。
- 名前は mdgrid(人の選択、2026-09-30。crates.io に同名なし、GitHub の同名のリポ2件)。cellops はこの TUI の上にタスクの画面(プラグイン)として載せてよい(SC-9 の画面の型)。

## 未決の問い(人の判断待ち。最大3)
