# 0002: 期限の無い未確定事項3件を決めて閉じ、テストの無い P1 は触るときに書く

- 状態: 採用
- 日付: 2026-11-18
- 決めた人: AI(依頼者が判断を任せた。2026-11-18 の依頼「あなたの思う進め方のベストを選べばいい。なのでこちらに聞き返す必要はないです」)。人の決定ではない

## 背景

0001 で期限切れの6件を閉じたあと、期限の無い未確定事項が3件残った。印の見直し(#65・#66)で、受け入れを断言していない印を外した結果、テストの無い P1 の要求が 205 件ある(P2 の作っていないものは別)。

## 決定

- `--print --with-path` の鍵の重なり(cli.with-path-name-clash): 今の実装の形にする。先頭に足した `path` は鍵 `path`、ビューの同じ見出しの列は `path (<列の id>)`、それでも重なれば ` #<列の番号>`。要求の文に書いて版を2にした。
- 問題のある行だけに絞っている間の表示(navigation.problem-jump-filter-shown): 今の実装とテストの断言のとおり、ヘッダーに「問題のある行だけ」を出し、外すと消える。要求の文に書いて版を2にし、それを断言しているテストに印を付けた。
- 行ごとに外部コマンドを動かす列(scope.command-column): 今は持たない。エージェントや外の道具は、`--print` と `--apply` で表を読み書きする形に任せる。
- テストの無い P1: 一度にまとめて書かず、その機能を直す・足すときに、その要求の落ちるテストを先に書く。数は check の要約に毎回出る。

## 理由

前の2件は、仕様の文が実装とテストに追いついていなかっただけで、今の形で困っている報告も無い。外部コマンドの列は、表のセルからコマンドを動かすので、誤操作と、ノートに書かれた値を引数にする注入の危うさを持ち込む。`--print`・`--apply` で外から同じことができるので、今は足さない。テストの無い要求を一度に書くと、期待値を今の実装から写しがちになる(要求の受け入れから取らない)ので、触るときに書く。

## 選ばなかった案

| 案 | 選ばなかった理由 |
|---|---|
| 何もしない(未確定のまま残す) | 仮の値で動いていて、決めないと誰も決めない |
| 外部コマンドの列を汎用の口で足す | 誤操作と注入の守りの設計が要り、`--print`・`--apply` で代わりが利く |
| テストの無い P1 をまとめて書く | 量が多く、期待値が実装の写しになりやすい |

## 影響

未確定事項は 0 件になる。見直す条件: 外からの操作で困る報告が出たら外部コマンドの列を考え直す。テストの無い P1 の領域で不具合が出たら、その領域から先に書く。
