# 画面の型「カンバン」を足し、状態の列の値ごとのレーンに札を並べて、札を動かして値を直す(kanban)

## きっかけ

人は会話 2026-10-31 で、ガントのあとにおすすめの図(カンバン・カレンダー・マトリクス・集計の棒グラフ)を同じ仕組みで足すよう求めた(決定 2026-10-31-gantt)。会話 2026-11-02 で、ガントの時間軸の直しのあとにそのまま先へ進めるよう言ったので、順の先頭のカンバンを足す。新しいケイパビリティ `kanban`(KB)を置き、木・ガントと同じ仕組み(印の `[[table]]` の型の名前のキー → 画面の型のメニュー → 画面のモジュール。GA-7)で足す。札を動かして状態を直すことと、レーンの順を列の決まり(CE-36)から取ることは、AI が足した細部(人の依頼はカンバンを足すことまで)。

## 差分

新しいケイパビリティ `specs/kanban/spec.md`(カンバン)。

- 追加: KB-1「ワークスペースの印の `[[table]]` に `kanban = { column = "<列>" }` を書いてよく、その列の値ごとに行を分けるべき。設定が無いときは、列の名前から推定してよい(status・state・stage・状態・ステータス・段階。大文字小文字を問わない。リストの型の列は選ばない)。推定でも決まらないときは、理由を出してカンバンを出さないべき。設定の `column` の列が表に無いか、リストの型の列のときは、CLI-3 の形で警告して出さないべき(1行が複数のレーンに属さないように)。」(確かめ方: `kanban = { column = "status" }` の表 → 画面の型のメニューに「カンバン」が出て `B` で開く。設定なしで status の列がある → 推定して開き、画面の題に推定と示す。設定なしで状態らしい列が無い → 理由1行で開かない。`column = "none"` → 警告1行で、メニューに出ない(`test_kb_1_*`))
- 追加: KB-2「`B`(か画面の型のメニューの「カンバン」)で、今のビューの行(絞り込み・並べ替えのあと。TR-1 と同じ)を、列の値ごとのレーン(縦の列)に札として並べて見せるべき。レーンの順は、その列の決まり(CE-36 の `values`)があればその順(行の無い値もレーンにする)、続いて決まりに無い値を行に現れた順、最後に値の無い行の「(なし)」のレーン(そういう行があるときだけ)にするべき。レーンの見出しには値と札の数を出し、札は行の名前(表のノートの欄と同じ見せ方)の1行で、レーンの中は表の行の順にするべき。レーンが幅に収まらないときは、選んでいるレーンが見える所まで横にずらし、隠れたレーンがあることを示すべき。色なしでも、選んでいる札とレーン、ためる変更のある札を見分けられるべき(SR-15)。」(確かめ方: 決まり `values = ["todo", "doing", "waiting", "done"]` の status で todo 2件・doing 1件・done 1件・状態なし1件 → レーンは todo(2)・doing(1)・waiting(0)・done(1)・(なし)(1) の順。決まりに無い値 blocked の行がある → done と (なし) の間に blocked のレーン。幅 40 で5つのレーン → 選んでいるレーンが見え、隠れた側に印。`--no-color` でも選んでいる札に `>`(`test_kb_2_*`))
- 追加: KB-3「カンバンの画面では、`j` `k` でレーンの中の札を選び、`h` `l` でレーンを移り、`Enter` で表に戻ってその行を選び、`Esc`・`q`・`B` で表に戻るべき。マウスは、札のクリックで選び、選んでいる札をもう一度クリックすると表のその行へ、ホイールで札、横のホイールでレーンを動かすべき。」(確かめ方: `B` → `l` → `j` → `Enter` で、表の doing の2件目の行が選ばれる。札のクリック → その札を選ぶ(`test_kb_3_*`))
- 追加: KB-4「カンバンの画面では、`H` `L` で選んでいる札を左・右のレーンへ動かし、その行の列の値を、動かした先のレーンの値に書き換えるべき。書き換えは表のセルの直しと同じためる変更(未保存)にし、動かした札は動かした先のレーンで選んだままにするべき。`u` で取り消し、`U` でやり直し、`Ctrl+s` で表に戻って保存の確かめ(差分)を開くべき。「(なし)」のレーンへは動かさず(値を消すのは表で)、読むだけのとき(`--readonly`、読むだけの列や行。CLI-2・BV-7・BV-12)は動かさずに理由を出すべき。」(確かめ方: todo の札で `L` → 札が doing のレーンへ移って選んだまま、下の帯の未保存が 1。`u` → todo に戻る。`--readonly` で `L` → 動かず理由1行。右の隣が (なし) の札で `L` → 動かず理由1行(`test_kb_4_*`))

## 却下した案

| 案 | 理由 |
|---|---|
| 何もしない | 状態ごとに全部の行を1枚で見られず、表のタブ(状態ごとのビュー)を切り替えるしかない。人はガントのあとにカンバンを足すよう求めている。 |
| 表のまとまり(groupBy)の見た目を横に並べてカンバン風にする | SC-9 が退けている(表のテーマや見た目の切り替えでなく、別の画面の型として足す)。 |
| 読むだけのカンバン(札を動かさない) | カンバンの主な使い道は状態を変えること。mdgrid は表でセルを直せるので、同じためる変更の道を通せば書き戻しの安全(保存の確かめ・外の変化)は表と同じになる。 |
| レーンの順を値の名前の順にする | 状態の名前の順は進みの順にならない(doing・done・todo)。列の決まり(CE-36 の `values`)が人の決めた順で、無い値も空のレーンとして見えるほうが、札を動かす先が分かる。 |
| 「(なし)」のレーンへ動かして値を消す | 動かすと消すを同じキーにすると、押し間違いで値が消える。値を消すのは表のセルの直しでする。 |
| `.base` の kanban のビューを開く | SC-8 は `.base` の table 以外のビューを開かないと決めている。`.base` の設定の形はカンバンの列の指し方が違い、印の `[[table]]` の `kanban` の設定(GA-7 の形)にそろえる。 |
| カンバンのキーを `K` にする | `K` は表で使っている。`B`(board)は表のモードで空いている。 |
