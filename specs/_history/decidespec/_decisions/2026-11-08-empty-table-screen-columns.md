# 行が1つも無い表では、画面の型の設定の列が表に無くても警告しない例外を GA-1・TR-2・KB-1 に書き足す(empty-table-screen-columns)

## きっかけ

変更 2026-11-02-kanban のレビュー(#9・#14・#24)で、見本なしのスターターで作った空の台帳を開くたびに「列 status が無い」と警告が出ることが分かった。表の列はノートのキーから作るので、行が1つも無い表では、設定の列があるかを決められない。そこで、行が1つも無い表では列があるかを確かめず、警告しない形に実装を変えた(行ができてから列が無ければ、前と同じく警告して出さない)。GA-1 と TR-2 は人が決めた要件で、文には例外が無いので、AI はこの形を「するべき」を理由つきで外したものとして記録に残し、人に尋ねた(軌跡の要約 2)。人は会話 2026-11-08 の選択肢の問いで「例外を書き足す」を選んだ。人の答えを AI が要件の文に起こした。

## 差分

- 変更: GA-1 旧「ワークスペースの印の `[[table]]` に `gantt = { start = "<列>", end = "<列>" }` を書いてよく、`start` と `end` の列の日付をその行の棒の始まりと終わりとみなすべき。`end` の代わりに `days = "<列>"`(始まりからの日数)でもよい。設定が無いときは、日付の列の名前から推定してよい(始まりは start・begin・from・開始、終わりは end・due・finish・until・to・期限・終了。大文字小文字を問わない)。推定でも決まらないときは、理由を出してガントを出さないべき。設定の `start`・`end`・`days` の列が表に無いときは、CLI-3 の形で警告して出さないべき。」→ 新「ワークスペースの印の `[[table]]` に `gantt = { start = "<列>", end = "<列>" }` を書いてよく、`start` と `end` の列の日付をその行の棒の始まりと終わりとみなすべき。`end` の代わりに `days = "<列>"`(始まりからの日数)でもよい。設定が無いときは、日付の列の名前から推定してよい(始まりは start・begin・from・開始、終わりは end・due・finish・until・to・期限・終了。大文字小文字を問わない)。推定でも決まらないときは、理由を出してガントを出さないべき。設定の `start`・`end`・`days` の列が表に無いときは、CLI-3 の形で警告して出さないべき。ただし、行が1つも無い表(見本なしで作った台帳など)では、列はノートのキーから作るので設定の列があるかを決めず、警告しないべき(画面の型のメニューには出し、開くときに出す行が無いと理由を出す)。」
- 変更: TR-2 旧「ワークスペースの印の `[[table]]` に `tree = { path = "<列>", separator = "<区切り>", order = "<列>" }` を書いてよく、`path` の列の値を `separator`(省略は ` > `)で切ったものを、その行の置き場の階層とみなすべき。`order` は省略してよい。`path` の列が無い表や、区切りが空の文字のときは、CLI-3 の形で警告して木を出さないべき。」→ 新「ワークスペースの印の `[[table]]` に `tree = { path = "<列>", separator = "<区切り>", order = "<列>" }` を書いてよく、`path` の列の値を `separator`(省略は ` > `)で切ったものを、その行の置き場の階層とみなすべき。`order` は省略してよい。`path` の列が無い表や、区切りが空の文字のときは、CLI-3 の形で警告して木を出さないべき。ただし、行が1つも無い表(見本なしで作った台帳など)では、列はノートのキーから作るので`path` の列があるかを決めず、警告しないべき(画面の型のメニューには出し、開くときに出す行が無いと理由を出す)。」
- 変更: KB-1 旧「ワークスペースの印の `[[table]]` に `kanban = { column = "<列>" }` を書いてよく、その列の値ごとに行を分けるべき。設定が無いときは、列の名前から推定してよい(status・state・stage・状態・ステータス・段階。大文字小文字を問わない。リストの型の列は選ばない)。推定でも決まらないときは、理由を出してカンバンを出さないべき。設定の `column` の列が表に無いか、リストの型の列のときは、CLI-3 の形で警告して出さないべき(1行が複数のレーンに属さないように)。」→ 新「ワークスペースの印の `[[table]]` に `kanban = { column = "<列>" }` を書いてよく、その列の値ごとに行を分けるべき。設定が無いときは、列の名前から推定してよい(status・state・stage・状態・ステータス・段階。大文字小文字を問わない。リストの型の列は選ばない)。推定でも決まらないときは、理由を出してカンバンを出さないべき。設定の `column` の列が表に無いか、リストの型の列のときは、CLI-3 の形で警告して出さないべき(1行が複数のレーンに属さないように)。ただし、行が1つも無い表(見本なしで作った台帳など)では、列はノートのキーから作るので設定の列があるかを決めず、警告しないべき(画面の型のメニューには出し、開くときに出す行が無いと理由を出す)。」

例の列には、それぞれ「行が1つも無い表で設定の列が無い → 警告なし。メニューに出て、開くと理由1行」を足す。試験は変えない(この振る舞いは変更 2026-11-02-kanban の試験がすでに確かめている)。KB-1 は人の決定で守られる要件になるので、KB-1 を指す試験のファイルに錠を掛ける(`check.py --lock`)。

## 却下した案

| 案 | 理由 |
|---|---|
| 前の形に戻す(行が無い表でも、設定の列が無ければ警告する) | 空の台帳を開くたびに誤った警告が出る。人が選ばなかった |
| 文を変えず、「するべき」を理由つきで外したままにする | 人が決めた要件の文と振る舞いがずれたまま残る。人が書き足すほうを選んだ |
