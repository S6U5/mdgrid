## 要求

人は会話 2026-10-31 で、ガントのあとにおすすめの図(カンバン・カレンダー・マトリクス・集計の棒グラフ)を同じ仕組みで足すよう求めた(決定 2026-10-31-gantt のきっかけ。順はカンバンが先)。会話 2026-11-01 ではカンバンとギャラリーに対応しているかを尋ね、無いと答えた。会話 2026-11-02 で、ガントの時間軸の直しの報告を受けて、そのまま先へ進めるよう言った。これを受けて、次の画面の型のカンバンを足す。

何を: 表(と木・関係マップ・ガント)に続く画面の型「カンバン」。今のビューの行を、状態の列の値ごとのレーン(縦の列)に札として並べる。札を隣のレーンへ動かすと、その行の状態の値をレーンの値に書き換える(表のセルの直しと同じ、ためる変更として)。設定は印の `[[table]]` の `kanban = { column = "<列>" }` で、無ければ列の名前から推定する(GA-7 の形)。

なぜ: タスクの台帳を状態ごとに見渡し、状態を札の移動で変えたい。今は表のタブ(状態ごとのビュー)を切り替えて見るしかなく、全部の状態を1枚で見られない。

何ができたら終わりか:
- 状態の列に決まり `[rules.status] values = ["todo", "doing", "waiting", "done"]` がある見本の台帳で `B` → 左から todo・doing・waiting・done の4つのレーンがこの順で並び、各行の札が自分の状態のレーンにある。状態の無い行があれば、最後に「(なし)」のレーンにある。
- todo の札を選んで `L` → 札が doing のレーンへ移り、下の帯の未保存が 1 になる。`--readonly` で開いたときは動かず、理由を1行出す。
- 状態の列も推定できる列も無い表 → 画面の型のメニューに「カンバン」が出ず、`B` で理由を1行出す。

関係する要件: GA-7(型ごとの設定と推定・メニュー)、SC-9(別の画面の型)、REL-8(画面の型のメニュー)、TR-1(今のビューの行だけを扱う)、CE-36(列の決まりの `values`)、SR-15(色なしでも見分けられる)、SR-22(キーの文書)、SR-49・SR-51(見せ方とできることの一覧)、CLI-2(`--readonly`)、BV-7・BV-12(読むだけの列)。

## 不明点と仮定

- 問い(人に聞く。答えを待たずに下の仮定で進める): 最初の版で、札を動かして状態の値を書き換えられるようにするか → 未回答。
- 仮定: 札は動かせる(`H` `L` で左右のレーンへ。表で列を左右に動かすキーと同じ向き)。値の書き換えは表のセルの直しと同じためる変更(未保存)にし、保存・取り消しは表と同じキー(`Ctrl+s`・`u`)がカンバンでも効く。理由: カンバンの主な使い道は状態を変えることで、mdgrid はセルを直せる道具のため。外れたら(読むだけにする): `H` `L` と保存・取り消しのキーを外し、KB の「札を動かす」の要件を消す。
- 仮定: レーンの順は、列の決まり(CE-36 の `values`)があればその順(行の無い値もレーンにする)、続いて決まりに無い値を表の行に現れた順、最後に値の無い行の「(なし)」(そういう行があるときだけ)。理由: 状態の順は名前の順では決まらず(doing・done・todo になる)、決まりの順が人の決めた順のため。外れたら: 決まりの無いときの順だけを変える。
- 仮定: 札は行の名前(ノートの欄の文字)の1行だけ。期限などの値を札に添えるのは次の段。理由: 最初の版を小さく保ち、レーンの幅を名前に使う。外れたら: `kanban = { column, card = [列, …] }` で2行目を足す。
- 仮定: 「(なし)」のレーンへは札を動かさない(値を消すのは表で)。理由: 消すのと書くのを同じ操作にすると、キーの押し間違いで値が消える。外れたら: (なし)へ動かすと値を空の文字にする。
- 仮定: リストの型の列(`[types]` が list)は、1行が複数のレーンに属してしまうので、カンバンの列にしない(設定で指せば警告、推定では選ばない)。
- 仮定: 開くキーは `B`(board)。表のモードで空いている大文字(ガントの記録の仮定と同じ)。
