## 仕様の動き

### 錨との照合の節を持つ自己採択(守られる要件に触れたもの)

- Windows でパスの区切りの違いで落ちるスターターの試験は、試験の補助だけを直して錠を掛け直した(ST-1〜ST-6 の文と例は変えない。Windows でも同じ強さで確かめるようになった)— [2026-10-25-windows-starter-tests-locks.md](../_decisions/2026-10-25-windows-starter-tests-locks.md)

### 人の発言から AI が起こして自己採択したもの

- 新しいケイパビリティ kanban(KB-1〜KB-6)を足した。状態の列(印の `kanban = { column }` か名前からの推定)の値ごとのレーンに札を並べ、`H` `L` で札を動かすと、その行の値をためる変更として書き換える。scope と gantt の「次の段」の文から、カンバンを kanban のケイパビリティへ移した(要件の文は変えない)。札を動かして値を書き換えるか(KB-4)は人に尋ねたまま答えが無く、書き換える形で進めている(kanban の spec.md の「未決の問い」)— [2026-11-02-kanban.md](../_decisions/2026-11-02-kanban.md)
- 決定の記録ではないが、カンバンの変更(specs/_changes/2026-11-02-kanban.md の #9・#14・#24)で、人の決定 gantt の GA-1 と木の TR-2 の振る舞いが、行の無い表で変わった: 前は、設定の列が表に無ければ読み終えたときに警告して画面の型を出さなかった。今は、行が1つも無い表では列があるかを決めず(見本なしのスターターの空の台帳で「列 status が無い」と誤って警告しないため)、メニューにはガント・カンバンを並べ、開くときに「出す行が無い」と理由を出す。行ができてから列が無ければ、前と同じく警告して出さない。GA-1 の「警告して出さない」は「するべき」なので、理由を記録に書いて外した。要件の文に行の無い表の例外を書き足すかは、人の判断を待つ。
