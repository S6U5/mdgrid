# ノートへの書き戻し(write-back)

mdgrid は、直した値をすぐには書かない。ためておき、保存の操作で、ファイルごとの差分を見せてからまとめて書く。書くのは直したキーの値(と、無いキーやフロントマターを足す行。WB-3)だけで、ほかは1バイトも変えない。他の人のノートや保管庫を壊さないことが、この道具の信用の芯になる。どのセルが編集できるかは [cell-edit](../cell-edit/spec.md) にある。

強さの読み方: 「しなければならない」= 例外なし、「するべき」= 理由があれば外してよい、「してよい」= 任意。

## 範囲外

- 採らない: ネストした map・ブロックスカラーの値の書き換え(読むだけ)。
- 採らない: 表からの本文の編集(エディタに渡す。screen の SR-8)。
- 次の段: 保存したあとの取り消し(ファイルを元に戻す)。

## 前提(AI の仮定)

- cellops の `edit.rs`(1キーを行単位で置換)は、ブロックリスト・ブロックスカラー・ネストした map・キーの重複を壊すことを実測で確かめた(2026-09-30)。そのため行単位ではなく、YAML の値の範囲(バイトの位置)を特定して置き換える方式にする(docs/design.md)。
- ためてから保存する形(WB-9)は人が選んだ(推しの案で進めてよいとの返事。読みに ⚠)。既存の表の TUI(VisiData・lazysql)には保存前の差分の画面が無く、これが強みになる(2026-09-30 の調査)。
